## 三、建议

### [P1] SKILL.md v0.2 衣柜示例应明确"线性即确认"

**现象**：2.2 thinking 中 ~60 秒用于 L 型衣柜多种构型探索，尽管最终选择线性。

**推测根因**：SKILL.md v0.2 示例中衣柜描述为"~3770mm 线性"，但未显式说明"v0.2 阶段不评估 L 型"。Agent 在 bedroom.md 策略中可能读到"优先 L 型"的偏好后，自然在 v0.2 阶段尝试验证。

**具体改动**：在 SKILL.md 的 v0.2 示例中（L66），在衣柜行追加括号说明：
```
衣柜 ✓ → 北墙门右段：~3770mm 线性，入口侧，隐私序列正确（L 型评估留给 v0.3）
```
或在"主家具确认原则"（L239）中追加一句：
```
v0.2 衣柜按线性确认；L 型升级在 v0.3 中根据可选家具位置评估，不在 v0.2 thinking 中展开。
```

**优先级**：P1 — 当前泄漏可控（~60s），Agent 能自纠正，但若 L 型分析更深的空间（如更复杂的角部关系），泄漏可能放大。

### [P1] 推进 zoning Skill 内容减载（第二批）

**现象**：2.2 thinking 中分区分析约 24 秒（竖切/横切/不分割），结论与预期一致（不分割），但展开过程包含对每种方案的通道宽度验算。

**推测根因**：generate-zoning/SKILL.md 内部仍保留了展开式的候选枚举和预布置验证指导，诱导 Agent 在 2.2 thinking 中做详细方案对比。这是 Codex 在讨论中指出的"权重冲突"问题。

**具体改动**：按讨论共识第二批计划，将 generate-zoning/SKILL.md 从"展开式论证器"压缩为"决策过滤器"——削减候选方案详细枚举、多功能方案长篇比较，保留判断树和过滤逻辑。

**优先级**：P1 — 第一批（结构边界）已验证成功，第二批（内容减载）可安全推进。目标：将 2.2 thinking 从 3:27 压缩至 ~2:00。

### [P2] 监控"快速落地"姿态的稳定性

**现象**：本次测试中 Stage 3 无 thinking block，坐标计算完全在输出中完成，首版一次通过。这是理想表现，但只有一次测试数据。

**推测根因**：v0.3 内容要求（完整选型结论）+ 试错示例锚定的组合效果。但不同空间复杂度、不同模块数量下，Agent 可能回退到"写入前精确验算"模式。
