     │ 根据 Schema-JSON.md，当前的建筑结构信息存储在 structure 节点：          │

     │ | function           | 功能类型      |                                  │

          9 -  ## 1. 设计理念
         10 -  
         11 -  ### 1.1 核心原则："JSON 为骨，SVG 为皮"
         12 -  
         13 -  | 层面 | 格式 | 职责 |
         14 -  |------|------|------|
         15 -  | **数据层（骨）** | JSON | 存储、传输、AI 交互、业务逻辑 
            - |
         16 -  | **视图层（皮）** | SVG | 渲染、显示、视觉反馈 |
         17 -  
         18 -  **为什么选择 JSON 作为核心数据格式？**
         19 -  
         20 -  | 对比项 | JSON | SVG |
         21 -  |--------|------|-----|
         22 -  | Token 效率 | 高（结构紧凑） | 低（大量标签冗余） |
         23 -  | AI 理解能力 | 强（键值对直观） | 弱（需解析路径数据） |
         24 -  | 空间推理 | 易（坐标直接可读） | 难（需解析 transform） |
         25 -  | 自定义属性 | 原生支持 | 需命名空间，兼容性差 |
         26 -  | 版本控制 | 易 diff | 难 diff |
         27 -  
         28 -  ### 1.2 数据流
         29 -  
         30 -  ```
         31 -  【AI 操作画布】
         32 -  AI 调用 MCP 工具 → 修改 JSON 数据 → WebSocket 推送 → 
            - 前端渲染 SVG
         33 -  
         34 -  【用户操作画布】
         35 -  用户交互 → 前端修改本地 JSON → 点击同步 → 服务端更新 → AI 
            - 感知变更
         36 -  
         37 -  【AI 视觉验证】
         38 -  JSON 数据 → 服务端渲染 → PNG 截图 → 发送给 AI（多模态）
         39 -  ```
         40 -  
         41 -  ### 1.3 坐标系统
         42 -  
         43 -  - **类型**：笛卡尔坐标系（Cartesian）
         44 -  - **原点**：视图裁剪框左下角
         45 -  - **X 轴**：向右为正
         46 -  - **Y 轴**：向上为正（与数学直觉一致）
         47 -  - **单位**：毫米 (mm)
         48 -  - **旋转**：顺时针为正，单位为度
         49 -  
         50 -  > ⚠️ **重要**：这是 CAD 标准坐标系，与 Web 屏幕坐标系（Y 
            - 向下）相反。
         51 -  > 前端渲染时必须进行显式坐标转换：`y_screen = canvasHeight
            -  - y_model * scale`
         52 -  > **禁止**使用 CSS `scaleY(-1)` 
            - 翻转，会导致文字倒置等副作用。
         53 -  
         54 -  ### 1.4 网格系统
         55 -  
         56 -  - **默认网格大小**：500mm × 500mm
         57 -  - **网格坐标计算**：
         58 -    - `col = Math.floor(x / gridSize)`  // 
            - 列号，从左往右递增
         59 -    - `row = Math.floor(y / gridSize)`  // 
            - 行号，从下往上递增（Y 向上）
         60 -  - **用途**：帮助 AI 更直观地理解空间位置

        573 -  | `backTo` | 背向 |

        575 -  | `parallel` | 平行 |
        576 -  | `perpendicular` | 垂直 |
        577 -  | `adjacentTo` | 相邻 |
        578 -  
        579 -  ```json
        580 -  {

          9 +  ## 1. 设计原则
         10 +  
         11 +  ### 1.1 核心原则：KISS (Keep It Simple, Stupid)
         12 +  
         13 +  | 决策点 | 选择 | 理由 |
         14 +  |--------|------|------|
         15 +  | **坐标系** | Y-Up (笛卡尔) | 符合 
            + CAD/BIM/数学直觉，只在前端渲染时转换 |
         16 +  | **数据分层** | Layer 1 (AI 上下文) | Token 
            + 效率，职责清晰 |
         17 +  | **墙体表示** | 封闭轮廓多边形 | AI 
            + 不需要理解墙体结构，只需知道空间边界 |
         18 +  | **门窗表示** | 简化为线段 | 厚度不影响家具布置 |
         19 +  | **门扇区域** | 预计算为矩形禁区（AABB） | AI 
            + 只需知道"这里不能放" |
         20 +  | **房间结构** | 只有 zones，无 rooms | 
            + 单一数据源原则，zones 是设计概念 |
         21 +  | **标高信息** | 全局 levelId | 一张平面图对应一个 Level |
         22 +  | **布置单元** | modules（模块） | 
            + 支持单一家具或组合（如睡眠模块=床+床头柜） |
         23 +  | **模块位置** | AABB 包围盒 | 
            + 直观显示占用空间，碰撞检测简单 |
         24 +  | **模块朝向** | 语义化方向 | AI 友好，插件端转换为角度 |
         25 +  
         26 +  ### 1.2 数据分层架构
         27 +  
         28 +  ```
         29 +  ┌─────────────────────────────────────────────────────────
            + ────────┐

         31 +  ├─────────────────────────────────────────────────────────
            + ────────┤
         32 +  │                                                         
            +         │
         33 +  │   【Layer 1: AI 上下文】- CanvasDocument.json

            +    │
         47 +  │

            + ────────┘
         49 +  ```
         50 +  
         51 +  ### 1.3 坐标系统
         52 +  
         53 +  - **类型**：笛卡尔坐标系（Cartesian）
         54 +  - **原点**：视图裁剪框左下角
         55 +  - **X 轴**：向右为正
         56 +  - **Y 轴**：向上为正（CAD 标准）
         57 +  - **单位**：毫米 (mm)
         58 +  
         59 +  > **重要**：这是 CAD 标准坐标系，与 Web 屏幕坐标系（Y 
            + 向下）相反。
         60 +  > 前端渲染时必须进行显式坐标转换：`y_screen = canvasHeight
            +  - y_model * scale`
         61 +

        381 +  ## 7. AI 布置逻辑
        382 +  
        383 +  ### 7.1 核心约束规则
        384 +  
        385 +  ```
        386 +  对于每个要放置的模块：
        387 +  1. 模块 bounds 必须完全在 zone.innerBoundary 内
        388 +  2. 模块 bounds 不能与任何 zone.exclusionAreas 重叠
        389 +  3. 模块 bounds 不能与其他已放置模块重叠
        390 +  ```
        391 +  
        392 +  ### 7.2 碰撞检测伪代码
        393 +  
        394 +  ```javascript
        395 +  function canPlaceModule(module, zone, existingModules) {
        396 +    const bounds = module.bounds; // [minX, minY, maxX, 
            + maxY]
        397 +  
        398 +    // 约束1: 必须在 innerBoundary 内
        399 +    if (!isInsidePolygon(bounds, zone.innerBoundary)) {
        400 +      return false;
        401 +    }
        402 +  
        403 +    // 约束2: 不能与禁区重叠
        404 +    for (const exclusion of zone.exclusionAreas) {
        405 +      if (aabbIntersects(bounds, exclusion.rect)) {
        406 +        return false;
        407 +      }
        408 +    }
        409 +  
        410 +    // 约束3: 不能与其他模块重叠
        411 +    for (const existing of existingModules) {
        412 +      if (aabbIntersects(bounds, existing.bounds)) {
        413 +        return false;
        414 +      }
        415 +    }
        416 +  
        417 +    return true;
        418 +  }
        419 +  
        420 +  function aabbIntersects(a, b) {
        421 +    // a, b 均为 [minX, minY, maxX, maxY]
        422 +    return !(a[2] < b[0] || a[0] > b[2] || a[3] < b[1] || 
            + a[1] > b[3]);
        423 +  }
        424 +  ```

        95 +  ### 0.3 核心设计决策
        96 +  
        97 +  | 决策点 | 选择 | 理由 |
        98 +  |--------|------|------|
        99 +  | **坐标系** | Y-Up (笛卡尔) | 符合 
           + CAD/BIM/数学直觉，只在前端渲染时转换 |
       100 +  | **数据分层** | Layer 1 (AI 上下文) + Layer 2 
           + (详细数据，Phase 1 暂缓) | Token 效率，职责清晰 |
       101 +  | **墙体表示** | 封闭轮廓多边形 | AI 
           + 不需要理解墙体结构，只需知道空间边界 |
       102 +  | **门窗表示** | 简化为线段 | 厚度不影响家具布置 |
       103 +  | **门扇区域** | 预计算为矩形禁区（AABB） | KISS - AI 
           + 只需知道"这里不能放" |
       104 +  | **房间结构** | 只有 zones，无 rooms | 
           + 单一数据源原则，zones 是设计概念 |
       105 +  | **标高信息** | 全局 levelId | 一张平面图对应一个 Level |
       106 +  | **布置单元** | modules（模块） | 
           + 支持单一家具或组合（如睡眠模块=床+床头柜） |
       107 +  | **模块位置** | AABB 包围盒 | 
           + 直观显示占用空间，碰撞检测简单 |
       108 +  | **模块朝向** | 语义化方向（north/south/...） | AI 
           + 友好，插件端转换为角度 |
       109 +  | **多方案** | Phase 1 不做 | MVP 先让 AI 
           + 直出方案，对话调整 |
