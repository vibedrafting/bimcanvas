# Design_Insights — 让 AI 胜任室内设计的有效经验

> **本文用途**：记录 BIMCanvas 在"把通用大模型调教成会做室内设计的设计师"过程中，提炼出的、对工程实践有效的设计灵感与可执行手段。每则源于一次具体的失败或观察，落点是"它如何改进了程序设计"。
>
> **怎么读**：每则灵感独立成节，彼此不强求逻辑递进，按需取用。承载这些灵感的具体机制（某个工具 / 某版工作流）一直在演进、部分已退役，但**灵感本身仍是当前信奉的设计哲学**——本文记录思想与方法，不记录已退役的接口名。
>
> **读者**：BIMCanvas 贡献者；以及任何想让 LLM 胜任某种专业判断的工程师——多数手段不限于室内设计。

---

## 1. AI 是"OBB 规划师"：决策与计算分离

> 让 AI 决策"放哪里"，让代码计算"精确几何"。

**背景**：早期让 AI 直接产出家具的精确多边形坐标，既慢又频繁出错（在 thinking 中逐角心算、易越界）。

人理解空间看的是"皮"，AI 应只看"骨"。这个隐喻精确划出了人机分工：

| 维度 | 人类（皮 / SVG） | AI（骨 / OBB） |
|------|------------------|----------------|
| 视觉几何 | 看到家具的真实形状、材质、光影 | 世界由有向包围盒（OBB）构成，只取外接矩形 |
| 坐标直觉 | 屏幕坐标（Y 向下） | CAD 坐标（Y 向上，`above` = Y 更大） |
| 关注点 | 美感与体验 | 拓扑关系（在 Zone 内、不重叠）、数值约束、语义方向 |
| 处理方式 | 直观感知 | 数据计算（多边形交集 / 包含判断） |

由此划出系统的根本边界：

- **AI 负责决策**：靠哪面墙、朝哪个方向、与谁相邻——语义判断。
- **代码负责计算**：精确多边形、碰撞检测、坐标转换——确定性运算。

**工程价值**：这条"决策 / 计算"分界线决定了整个系统的职责划分（Agent 不做几何、Server 做几何）。对任何"LLM + 精确计算"的系统都适用：不要让 LLM 做它不擅长、且有确定性算法可替代的事。

## 2. 为 AI 而画的视图：把隐性约束变成显性视觉

> 引入视觉能力时，给 AI 看的图要为它的逻辑服务，而非复用给人看的渲染图。把设计师脑中隐性的空间直觉，画成 AI 能"看见"的显性约束。

**背景**：把渲染精美的效果图给 AI 做视觉判断反而帮倒忙——美图里全是噪音（阴影、纹理、圆角），关键约束却是隐形的（门扇扫过区、完成面厚度），AI 会把家具摆进门的开启范围。

解法是为 AI 单独构建一套**语义增强的工程视图**，分四个图层递进：

### 2.1 约束层：显性化"不可见"的逻辑

| 隐性约束 | 显性画法 |
|----------|----------|
| 门扇开启区等禁区 | 半透明红 / 斜线阴影 |
| 可设计区边界 | 淡绿背景（"这是你的安全工作区"） |
| 墙面完成面厚度 | 彩色描边标出不可占用层 |
| 家具本体 | 简化为纯矩形 OBB + 朝向箭头，去掉一切装饰 |
| 家具身份 | 盒子中心标 ID（AI 报告"3 号挡住 5 号"时可精确定位） |

核心是抽象：人看的家具细节（圆角、抱枕）对"是否碰撞 / 朝向哪里"是噪音；AI 视图追求高对比、扁平、工程制图风。

### 2.2 意图层："设计场线"——把设计直觉画成可遵循的线

人类设计师的隐性习惯（"沙发要正对电视""电视要居中"），转成 AI 能视觉遵循的显性约束：

| 场线 | 解决的问题 | 画法与 AI 直觉 |
|------|-----------|----------------|
| 对齐轴线 | 正对 | 垂直于主背景墙画中轴线，主要家具中心吸附其上 |
| 锚点与中轴 | 居中 | 重点墙面几何中心画"十字锚点"，家具核心对准 |
| 动线通道 | 挡路 | 连接关键出入口画半透明带（如 900mm 宽）——"虚拟河流"，家具只能在岸边 |
| 视线锥 | 遮挡 | 从沙发向电视墙画扇形，区域内不得有高大障碍 |
| 对称参考线 | 平衡 | 床头墙中轴画镜像标记，左放床头柜则右镜像位也放 |

### 2.3 索引层：语义网格——把度量空间降维成符号空间

把连续坐标离散成符号网格（列 A/B/C… × 行 1/2/3…，600mm 或 1000mm 一格，原点对齐 Zone 左下）：

- **为什么 `C3` 比 `x:1200,y:3400` 好**：`C3` 是语义符号，AI 天然知道"A3 在 B3 左边""A1 到 C3 是对角线"，无需坐标减法；坐标数字则要消耗算力去"算"。
- **由粗到精（coarse-to-fine）**：先在网格级粗规划（"沙发放 C2–E2 区"，快、逻辑清晰），再在格内细调坐标（"C2 内中心微调至 x=2400"，降幻觉）。

四层叠起来构成完整的 AI 视觉系统：L0 物理（墙门窗）→ L1 约束（OBB / 禁区 / ID，几何计算）→ L2 意图（设计场线，视觉遵循）→ L3 索引（语义网格，符号推理）。

**工程价值**：多模态 LLM 的输入应按"它要判断什么"来构造，而非复用给人看的产物。把领域专家的隐性直觉显性化为视觉/符号约束，是让 LLM 应用专业判断的通用手段。

## 3. 设计即熵减：把决策外化为可见文本

> 逼 AI 把每个决定写成可见、逐步精化的文本，而非在 thinking 中反复权衡。

**背景**：一次布置任务 AI 耗时 27 分钟、八成时间在思考——同一空间分析三遍、方案间反复横跳不收敛、推理塞进单次超长输出被截断丢失。它能力没问题（最终结果正确），是思考方式错了。

设计的本质是熵减：从无穷种摆法不断做决定、收窄可能性，直到唯一解。人类设计师的熵减是**外化**的——说出"床放东墙"，可能性当场坍缩，再在此约束下继续。AI 的问题是熵减发生在 thinking 块内：不可见、不可锚定、溢出即全失。

解法：**决定一件、写一件，从粗到细逐步精化**（空间骨架 → 主要家具墙面归属 → 可选家具与细节）。它消除四类浪费：

| 问题 | 外化如何解决 |
|------|-------------|
| 中间决策在 thinking 中，截断即丢失 | 写入可见输出，可见即存活 |
| 反复重新分析相同信息 | 已写决策可直接引用，不必重推 |
| 决策不承诺、反复 second-guessing | 写入即承诺，白纸黑字不再摇摆 |
| 一次性巨大输出撑爆上限 | 每次只增量几行，物理上不会溢出 |

### 3.1 精度边界：规划期只做粗估

规划阶段全程只做"空间预演级"的粗估，精确坐标推迟到落地时才算：

| 允许（粗估） | 不允许（精确计算） |
|-------------|-------------------|
| "北墙 4070mm 放衣柜，深 600mm，通道约 950mm，够用" | 计算 bounds 四角坐标 |
| "东墙放床+两柜约 2700mm，剩余 2150mm" | 逐件家具定精确 X/Y |

WHY：粗估是空间预演的必要工具（"放得下吗？通道够吗？"），但精确坐标心算是 thinking 膨胀的主因；把它推迟到落地、配合确定性校验，既更快又更可靠。

### 3.2 方案即"设计图纸"，享有权威

曾发生：AI 在规划阶段按用户参考图把床定在东墙，落地阶段却被一条"最长实墙放床"的设计偏好诱导改到西墙，背叛了用户意图。根因是它把"已定方案"和"通用偏好"当成平级信息。

规矩：**方案是设计图纸，其他规则是施工规范**——规范决定"在这面墙上怎么放"，但不能改"放在哪面墙"；要改图纸，须用户许可。这条权威性靠在多个阶段重复强化（LLM 注意力会衰减，重复出现的约束获得更高权重）。

**工程价值**：让 LLM 的中间状态可见且可锚定，是对抗"长链思考发散 / 上下文溢出"的结构性手段——不依赖模型"更自律"。

## 4. 结构性解法优于文字规则

> 当某信息已在上下文中产生干扰，加一条"请忽略"无效；有效的解法是让它在关键时刻物理上不在场。

**背景**：为防设计偏好污染对参考图的解读，先加文字规则"请忽略墙面偏好、以图为准"——无效，AI 仍被悄悄带偏。另一例：提示词里的示例参数恰与测试房间相同，AI 直接抄示例结论、跳过独立推理，哪怕示例标注了"不提供可复用结论"。

两个问题同源（上下文里已有信息隐性引导判断），解法都是结构性的：

| 污染源 | 无效的文字解法 | 有效的结构解法 |
|--------|---------------|---------------|
| 设计偏好诱导对参考图的解读 | "请忽略偏好" | **延迟加载**：解读参考图全程不加载偏好文件，让它物理上不在上下文 |
| 示例参数与真实任务重合，结论被照抄 | "示例不提供可复用结论" | **示例去参数化**：示例改用与任何真实场景都不同的虚构参数，保留方法示范、消除结论照抄 |

辅助一条：基准记录必须精确——若空间骨架用模糊描述（"居中偏南"而非"东墙"），后续一致性检查会失效（任何结论都能"一致"于模糊基准）。

**工程价值**：本文最具普适性的一条。**控制 LLM 行为时，"移除/重构上下文"远比"增加约束文字"可靠**——模型读得到上下文里的一切，"请别理它"反而强化了它的存在。有效解法始终是：让该消失的信息在关键决策时刻真的不在场。

## 5. 分区是结论，而非前提

> 分区线从家具预布置与动线中浮现，不是先验地切割空间。

**背景**：曾把"分区"当预处理步骤——先切块、再在块内摆家具。但真实设计师的思维是反过来的。

### 5.1 一体三面：分区、过道、家具预布置同时发生

设计师的真实思维："门在这边，床放那面墙，从门到床走这条线，衣柜靠这面的话过道够不够，不够床往窗边挪……那这块自然就是更衣区了。"三件事互相验证、同时浮现：

| 面向 | 回答的问题 | 性质 |
|------|-----------|------|
| 家具预布置 | 这里需要多大空间？ | 空间需求 |
| 过道设计 | 人怎么在家具间移动？ | 空间连接 |
| 分区 | 前两者叠加后浮现的结构 | 空间组织 |

家具是岛屿、过道是河流、分区是看着岛屿河流后画出的地图——不能先画地图再造岛屿。一条没有物理依据（没验证过"放得下、走得通"）的分区线，只是随意的几何切割，不是设计决策。

### 5.2 分区的三层价值（递进）

| 层 | 价值 | 说明 |
|----|------|------|
| 工程价值 | 约束解耦 | 把高维耦合问题（床+衣柜+书桌+通道同时权衡）拆成单功能子问题 |
| 质量价值 | 创造设计语言 | **分区赋予空间以意图**——命名"更衣区"即激活该类空间的全部常识，无需逐条规则。"有设计感"与"只是塞满"之别，就在空间有无意图 |
| 过程价值 | 可交付的成果 | 分区图是设计最早的对齐点——客户几秒就能判断方向对错，比家具布置图沟通效率高、改动成本低 |

### 5.3 双向锁定

分区从预布置浮现，一旦确立又反过来约束后续精确布置：`预布置（发散探索）→ 浮现分区 → 分区锁定（收敛执行）`。它是设计过程的"锁定点"——之前是开放搜索，之后是有界执行。

**工程价值**：理顺约束方向——物理空间 → 家具位置 → 过滤分区（单向、无循环）。先确定受物理约束的部分，让高层结构从中浮现，避免在抽象层反复试探。

## 6. 工程合规 ≠ 设计品质：评价维度即设计目标

> "不出错"和"做得好"是两件事；评价标准应前置为设计目标，而非事后检查清单。

**背景**：一次卫生间布置几何完全合法（不越界、不重叠、通道达标），却很别扭——进门需折返才能用洁具。审查没拦住，因为整套审查只问"有没有违反约束"，而它没违反任何约束。系统性盲区：定义了"什么不能做"（工程约束），从没定义"什么是做得好"（设计品质）。

### 6.1 分层评价体系（层层递进、不可跳跃）

```
Layer 1 工程合规   "有没有错？"     以不出错为底线
Layer 2 设计品质   "好不好？"       以好设计为目标
Layer 3 设计倾向   "合不合业主喜好？"（未来：偏好作 Layer 2 权重调节器）
Layer 4 经济指标   "花多少钱？"（未来：成本 / 性价比）
```

每层是上一层的前提——有错的布局谈不上品质，品质差谈不上偏好。当前聚焦 Layer 1 + Layer 2。

### 6.2 Layer 1 工程合规：三块

| 块 | 指标 | 判据 |
|----|------|------|
| 几何合法 | 不越界 / 不穿墙 / 不占柱 / 不侵禁区 / 不重合 | 由确定性几何校验自动检查（最成熟一层） |
| 通行可达 | 主通道 ≥900mm / 次通道 ≥600mm / 全可达无死端 | 从"通道宽度达标"提升为"所有功能点可达" |
| 功能完整 | zone 每个功能标签至少一个对应模块 / 必选家具不遗漏 | 比对 tags 与已放模块（曾是缺口：遗漏家具无人发现） |

### 6.3 Layer 2 设计品质：五个维度（每维含正反例）

这是本则信息量最大处——五个可分析的品质维度，每维既是审查标准、也是设计目标：

| 维度 | 核心问题 | 好 | 差 |
|------|---------|----|----|
| **动线设计** | 从入口到功能点的路径是否直觉、无折返？ | 进门右转直达台盆 | 需绕过门扇 / 洗手后折返才到马桶 |
| **空间意图** | 每个区域有明确存在理由吗？ | L 形延伸做化妆间、凹角做书桌 | 延伸区空置、<600mm 缝隙无用途 |
| **功能叙事** | 同区家具讲连贯故事吗？墙面主题统一吗？ | 一整面墙做衣柜 / 台盆+镜柜+毛巾架成洗漱区 | 衣柜-空隙-床头柜-书桌混杂一墙 |
| **空间节奏** | 入口到深处有意识递进吗？留白是选择还是遗漏？ | 入口缓冲→功能区，私密度递进（台盆→马桶→淋浴） | 一进门正对家具、马桶紧贴门口 |
| **采光通风** | 窗户资源是否被合理利用？ | 高柜沿非窗墙、梳妆台靠窗 | 高衣柜正对窗使深处变暗 |

关键区分：动线设计 vs Layer 1 通行可达——后者问"能不能走到"（900mm 底线），前者问"走到的过程是否自然"（一条需折返的 900mm 通道，工程合规但动线不合格）。

### 6.4 品质标准即设计目标（贯穿四阶段）

核心领悟：**好设计不是先随便做、再检查碰巧对没对**——设计师落笔前脑中已装着目标。出错真因是 AI 只有"选较远长墙"的公式、不知其所以然，公式在复杂空间变模糊时无更高目标可回退。五个维度应在全流程换不同角色：

- **理解阶段**：作为读空间的透镜（这空间支撑什么动线？能讲什么叙事？光从哪来？）
- **策略阶段**：作为显式声明的设计目标（不是"台盆放东墙" what，而是"进门直达、东墙统一洗漱区" why）
- **执行阶段**：作为每个决策的判据（选墙时想动线、分组时想叙事、留白时想节奏）
- **审查阶段**：作为目标达成的验证（检查声明的目标是否实现，而非拿陌生清单空对）

**工程价值**：从"规则驱动"转向"目标驱动"。规则告诉 AI 不要做什么（护栏），目标告诉它要追求什么（驱动力）——两者缺一不可，但目标决定方向。对任何"质量难以用约束穷举"的 LLM 任务都适用。

## 7. 强外壳 + 弱内核：知识的双层切分

> 同一份领域知识，切成"机器校验的契约层"和"AI 理解的意图层"。

**背景**：给 AI 喂家具知识时撞上矛盾——Server 要严谨（尺寸、碰撞，差一点都不行），AI 要理解力（为什么这样放）。塞进同一结构，要么 Server 没法校验，要么 AI 被框得不会思考。

### 7.1 两层四支柱

| 层 | 服务对象 | 内容 | 特征 |
|----|---------|------|------|
| **契约层（强外壳）** | Server 校验 / Web 渲染 / Revit 导出 | `tags`（严格对齐 ZoneTag 枚举）、`size`、资源路径 | 强结构、强校验、无模糊语义 |
| **意图层（弱内核）** | Agent 决策 | `morphology` 形态学 / `topology_rules` 拓扑 / `relation_rules` 关系 | 自然语言与逻辑共存，Server 不解析 |

- **拓扑规则**（物体↔空间）：自然语言数组，如"靠墙""居中""避让动线""深处角落"。
- **关系规则**（物体↔物体）：如"面向电视""与坐便器相邻""优先成对对称"。

### 7.2 形态学：让家具声明自己的可变性

这让 AI 做的是"设计"（寻优）而非"摆图块"：

| 策略 | 含义 | 典型 | Server 行为 |
|------|------|------|------------|
| `fixed` | 刚体，尺寸不可变 | 成品床、马桶 | 忽略 limits，强制用 size |
| `horizontal_fill` | 横向填充两墙之间（1D） | 定制衣柜、窗帘 | 校验 width 在 limits 内 |
| `parametric` | 二维自由寻最佳长宽比（2D） | L 形沙发、转角淋浴房 | 校验 width/depth 均在 limits 内 |
| `pad_to_fit` | 本体不变、加填充条适配 | 嵌入式电器 | 核心尺寸不变，算 padding |

### 7.3 架构价值

- **解耦**：Server 不必懂"对称"语义也能跑（规则是自然语言、由 AI 解析），新增设计规则无需改 Server 代码。
- **鲁棒**：靠强类型 `limits` 物理拦截 AI 幻觉尺寸（如"5 米的马桶"）。
- **可维护**：分类即定位——柜子总拉太长→改形态学 limits；马桶总摆路中间→改拓扑规则。

**工程价值**：当一份数据同时服务"确定性系统"和"LLM"时，按消费者切层——强类型部分给机器校验兜底（拦幻觉），自然语言部分给 LLM 留理解空间。

## 8. 提示词是激活，而非注入

> 提示词唤醒 AI 已有的知识，无法注入它没有的知识。它构建的是"认知环境"，不是"命令清单"。

**背景**：写"作为资深室内设计师"，AI 不是在演，是在激活训练数据中相关的知识区。能唤醒已有的，无法注入没有的（它从没见过的模式，再详细的规则也只能机械模仿）。

### 8.1 五个底层机制

| 机制 | 要点与推论 |
|------|-----------|
| 注意力零和 | 每个 token 都在抢注意力，规则越多每条权重越低。一条精准规则 > 十条模糊规则；加规则前问"去掉它会变差吗"。 |
| 激活而非注入 | 提示词唤醒已有知识区，无法灌输没有的模式。 |
| WHY = 泛化 | 附理由的规则给出推理框架，边界场景能从原理推导；没理由的只能机械执行。 |
| 示例 = 锚定 | LLM 从示例提取模式比从文字解析规则更自然。能用示例就用示例锚定基准，无法穷举时用 WHY 覆盖边界。 |
| 位置效应 | 头尾关注度高于中间（lost in the middle），最关键规则放头/尾，中间放说明。 |

### 8.2 三层论 + 三级约束

提示词设计分三层：**信息架构**（怎么处理信息——结构化分层 + 保持信噪比，做错严重扣分）→ **认知校准**（以什么标准——示例锚定 / 禁止项 / WHY / 渐进信任）→ **留白**（在哪里发挥判断力）。

留白靠三级约束实现：

| 层级 | 性质 | AI 行为 | 语气 |
|------|------|---------|------|
| 硬约束 | 功能 / 安全 | 必须满足、无例外 | "必须" / "禁止" |
| 软指导 | 质量规范 | 默认遵守，说明理由后可偏离 | "应" / "建议" + WHY |
| 自由区域 | 风格 / 偏好 | AI 自主 | **有意识地不写规则** |

> 自由区域不是"还没来得及写规则的地方"，而是"想清楚后决定不写规则的地方"。没有校准的留白是失控，没有留白的校准是僵化。

### 8.3 常见反模式

| 反模式 | 正确做法 |
|--------|---------|
| 规则叠加（修 A 加 X，X 致 B 又加 Y） | 找根因，一条精准规则解决 |
| 职责越界（流程文件写领域标准） | 拆到知识库，流程文件只引用 |
| 面面俱到（覆盖每种场景） | 给原理让 AI 自行推导 |
| 留白恐惧（每个决策点都写规则） | 自由区域有意识地不写 |
| 示例缺失（大量文字描述输出） | 1–2 个精选示例替代 |

**工程价值**：提示词设计的本质是"构建认知环境"而非"下达命令"。信噪比、WHY、示例、留白、约束分级，是任何 LLM 系统提示词都通用的杠杆。

## 9. 两道独立防线：能解析 ≠ 能安全使用

> 面向"无容错能力的下游"，要有一道不依赖上游的独立闸门。

**背景**：一次 AI 写出字段格式错误、缺关键几何字段的数据，JSON 解析未报错（未知字段被忽略、缺失字段静默填空），系统以为就绪、推给前端，前端渲染撞上空值崩溃。且崩溃发生在 AI 主动校验**之前**——渲染路径根本不经过校验工具。

### 9.1 先分清"坏数据"的三层

| 层级 | 定义 | 例子 |
|------|------|------|
| 数据损坏 | JSON 无法解析 / 转换器无法处理 | 语法错误、`bounds: "hello"` |
| 数据缺失 | JSON 合法但必需字段缺 / 为 null | `bounds: null`、`facing: null` |
| 数据不正确 | 结构完整但语义错 | 越界、零向量朝向、moduleId 不在库 |

### 9.2 两道职责不可互替的防线

| | 第一道：面向 AI 的校验 | 第二道：面向渲染的加载闸门 |
|---|----------------------|--------------------------|
| 触发 | AI 主动调用 | 每次加载自动运行 |
| 服务对象 | AI（有推理能力） | 渲染引擎（无容错） |
| 目标 | 从源头预防坏数据 | 阻止坏数据到达下游 |
| 覆盖 | 全部三层 | 仅影响渲染安全的两层（损坏 + 渲染必需字段缺失） |
| 修正 | 自动修 + 诊断（混合） | 不修，只隔离并报告 |
| 独立性 | 依赖 AI 主动调 | **完全独立，不假设第一道已运行** |

### 9.3 第一道的混合修正策略

划分标准：程序能否在不猜测 AI 意图的情况下确定正确结果。

- **自动修正（意图明确）**：`semantic:"south"` → 转 `value:[0,-1]`；非单位向量 `[3,0]` → 归一化 `[1,0]`；semantic 与 value 冲突 → semantic 优先。
- **返回诊断让 AI 重做（意图不明）**：`"NE"` 非标准词（缩写？笔误？）；`[0,0]` 零向量无方向；value 与 semantic 都缺失；越界 / 重叠 / moduleId 不在库。

### 9.4 归属判定准则

```
Q1 会导致渲染崩溃或 Server 抛异常吗？ → YES：第二道（加载闸门，隔离）
Q2 属于 AI 决策失误、需理解后修正吗？ → YES：第一道（诊断）
Q3 程序能不猜意图直接修正吗？        → YES：第一道自动修 / NO：第一道诊断
```

**工程价值**：系统里凡"下游无容错能力"之处（渲染、外部接口、跨进程边界），都值得为其单设一道不依赖上游的闸门。第二道防线的全部意义，是即使第一道完全失守（压根没被调用）也能守住底线——因为渲染路径不经过第一道。

---

## 贯穿性原则

上述灵感反复指向三条更底层的倾向，可作为设计 LLM 系统时的默认偏好：

1. **结构 > 文字**：用结构让 AI 自然走对（移除污染上下文、外化决策、按消费者切分知识、为 AI 单建视图），优先于用文字规则去命令它。
2. **目标 > 规则**：让 AI 带着显式目标工作（评价维度即设计目标），优先于堆砌"不许做什么"。规则是护栏，目标是驱动力。
3. **激活 > 注入**：唤醒模型已有的能力（提示词激活知识、分区激活意图、角色激活专业常识），优先于试图灌输它没有的。

这些经验提炼自室内设计这一个领域，但"让通用大模型胜任某种专业判断"的工程问题，多数可迁移。本文不求体系完整，按需增补。
