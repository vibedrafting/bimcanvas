# 模块库数据指南 (Module Library Data Guide)

> **文件**: `module_library.json`
> **定位**: 模拟后端数据库，包含家具的基础信息与 AI 设计规则。

本文档帮助开发者与 AI 理解该 JSON 文件的结构逻辑。

---

## 1. 核心架构：强外壳 + 弱内核

数据被设计为两层：

1.  **契约层 (Contract Layer)**: 位于根节点。是 **Server 校验** 和 **Web 渲染** 的硬性依据，必须保持结构稳定。
2.  **意图层 (Intent Layer)**: 位于 `agent_config`。是 **AI 设计师** 的决策依据，包含软性规则。

## 2. 字段速查

### 2.1 基础契约 (Contract)

*   `id`: 唯一标识符（如 `mod_bed_002`）。
*   `tags`: **功能分类**。仅包含 `ZoneTag` 定义的合法标签（如 `sleep`, `study`），用于筛选家具。
*   `size`: **默认参考尺寸**。Web 前端渲染时的默认大小。
*   `svgPath`: 对应的矢量图块路径。

### 2.2 AI 意图 (`agent_config`)

这是告诉 AI "如何像设计师一样思考" 的核心配置。

#### A. 形态学 (`morphology`)
> *"这个物体是死板的，还是可塑的？"*

*   `strategy`:
    *   `fixed`: **刚体**。尺寸不可变（例：马桶、成品床头柜）。
    *   `horizontal_fill`: **横向填充**。宽度可变，通常用于填满两墙之间（例：定制衣柜、窗帘）。
    *   `parametric`: **参数化**。长宽均可在 `limits` 范围内自由调整，寻找最优解（例：转角淋浴房、L型沙发）。
    *   `pad_to_fit`: **适配填充**。物体本身不变，但周围加填充物（例：嵌入式电器）。

#### B. 拓扑规则 (`topology_rules`)
> *"这个物体应该放在空间的什么位置？"*

*   描述物体与 **环境 (墙/地/角落)** 的关系。
*   *示例*: "靠墙放置", "布置于卫生间深处角落", "严格避让门开启区域"。

#### C. 关系规则 (`relation_rules`)
> *"这个物体和其他物体怎么配合？"*

*   描述物体与 **其他家具** 的互动。
*   *示例*: "面向电视墙", "通常与坐便器相邻", "优先成对布置(对称)"。

---

## 3. 示例解读

```json
"agent_config": {
  // 形态：这是一个"横向填充"的物体，宽度在 800-2400mm 之间自由伸缩
  "morphology": {
    "strategy": "horizontal_fill",
    "limits": { "width": [800, 2400] }
  },
  // 拓扑：把它放在墙边
  "topology_rules": ["靠墙放置"],
  // 关系：靠近入户门放（暗示是鞋柜）
  "relation_rules": ["接近入户门"]
}
```
