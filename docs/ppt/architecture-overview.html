03 / 08

三大设计理念

📁
File-Driven
文件是唯一真理源。Server 是"文件播放器"，不是数据库。所有状态以 JSON 文件持久化，天然支持 Git 版本控制。
📐
AI = OBB 规划师
AI 只操作矩形包围盒（bounds + facing），不计算精确几何。几何验证、禁区计算均由 Server 负责。
🧠
Agent 只做决策
Agent 负责"放什么、放哪里"的决策。几何计算、状态管理、数据验证全部交给 Server。

五大子系统

🦴
BIMCanvas.Core
.NET Standard 2.0  |  骨骼
  • 几何基元：Point2D, Polygon2D, AABB, Facing
  • 空间算法：碰撞检测、布置验证、方向转换
  • 数据转换：Revit 数据 ↔ JSON ↔ NTS
  • 跨框架兼容：同时支持 .NET FW 和 .NET 8
💪
BIMCanvas.Revit
.NET FW 4.7.2  |  手臂
  • 6 阶段导出流程：墙体 → 门窗 → 房间
  • 坐标转换：Revit feet ↔ 标准 mm
  • 房间类型推断与边界提取
  • Phase 2 回写 Revit（待开发）
❤
BIMCanvas.Server
.NET 8.0  |  心脏 + 神经系统
  • 状态管理：项目上下文、文件监听（500ms 防抖）
  • 通信中枢：REST API + SignalR + SSE + MCP
  • 几何计算：Zone 生成、禁区计算、碰撞检测
  • Git Worktree：多方案并行隔离
🧠
BIMCanvas.Agent
Python 3.10+  |  大脑
  • 基于 Anthropic Agent SDK 构建
  • MainAgent + SubAgent 分层架构
  • 三种工作流：query / edit / generate
  • Skills 驱动，插件式旁路加载
👁
BIMCanvas.Web
Vue 3 + TypeScript  |  皮肤 + 眼睛
  • JSON → SVG 动态渲染画布
  • 元素拖拽、旋转、缩放交互
  • SignalR 实时状态同步
  • 撤销/重做 + AI 指挥中心
06 / 08

Server vs Agent 职责边界

维度 Server 指挥中心 Agent 设计师
状态管理 ✅ 管理项目文件夹、内存状态 ❌ 无状态，只发指令
几何计算 ✅ Zone 生成 / 禁区 / innerBoundary ❌ 不做几何计算
智能决策 ❌ 不决定"放哪里" ✅ 规划布置方案、理解意图
约束验证 ✅ 边界 / 碰撞 / 禁区检查 ❌ 依赖 Server 验证结果
Git 操作 ✅ Worktree 创建 / 合并 ✅ 在 Worktree 中读写文件
通信 ✅ REST / WebSocket / SSE / MCP ❌ 只通过 MCP / SSE 交互
07 / 08

三条核心数据流

✏
用户编辑流
Web → Server → File
用户在 Web 画布上拖动/修改模块，通过 REST API 发送到 Server，Server 写入 JSON 文件并广播更新。
🔄
文件同步流
File → Server → Web
Agent 或外部编辑器修改了 JSON 文件后，FileWatcher 感知变化，通过 SignalR 实时推送到 Web 前端重新渲染。
📂
项目加载流
File → Server → Web
用户上传 .bcp 项目文件或切换项目时，Server 解析文件结构，计算派生数据，一次性推送完整状态到 Web。

六个工作阶段

1
数据准备
BIMCanvas.Revit
从 Revit 提取墙体、门窗、房间，生成精简版项目结构
2
数据处理
BIMCanvas.Server
计算房间区域 (Zones)、门扇禁区 (Exclusions) 等派生数据
3
区域确认
用户 + AI
确认各区域功能标签 (tags)、墙面完成面材质
4
方案生成
BIMCanvas.Agent
AI 理解需求，规划家具布置，输出 modules[]
5
交互修改
用户 + AI
用户在 Web 画布上调整，AI 可感知变化并协助
6
回写 Revit
Revit-MCP
将最终方案同步回 Revit，创建实际家具实例
