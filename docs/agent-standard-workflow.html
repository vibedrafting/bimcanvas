03 / 06

三种核心作业模式

🔍
Query (只读检索)
特征：数据查询、盘点、检查。

工具权限限制：仅开启 Read、Glob、Grep 等只读工具。
禁止行为：绝对禁止修改或幻想任何数据内容。
✏️
Edit (单一修改)
特征：指点式局部修改（如布置单一模块、调整特定家具）。

工具权限限制：具备读写权限。
工作流：执行单一或少数原子步骤，修改后快速验证。
🚀
Generate (完整布局)
特征：全房生成、A/B 分支策略并行设计。

工作流：长链路工作流，结合 Worktree 进行环境隔离，并在最后提供完整方案包供用户合并或决断。
04 / 06

Git Worktree 独立并行机制

🎯
策略层 (Strategy)
设计理念的顶层定义，例如“极致收纳”、“动线优先”。它们是长期的配置分支，指导全屋规划的数据倾向。
⎇️
变体层 (Variant)
在具体策略下派生的不同尝试分支（如：策略A-方案1，策略A-方案2），便于用户在UI中并行预览设计差异。
📂
隔离层 (Worktree)
Agent 在接管 Generate 任务时，Server 自动切出物理隔离的 Git Worktree 供 AI 进行安全读写。完成方案后即可发起 Commit，即使验证失败也不会污染主干状态。
05 / 06

标准工作流实例剖析：rule-review

BIMCanvas 中 Agent 的能力被高度插件化，封装为一个个独立的 Skill 工作流。
以下是 `rule-review` 工作流的标准目录结构与实现范式：

.claude/skills/rule-review/
├─ SKILL.md // 核心入口。包含 YAML 元数据定义（名/描述）和具体 Markdown 工作流指令步骤
└─ references/ // 知识库文件夹。存放执行该工作流所必需的上下文或校验工具
├─ prompt-file-map.md // 索引地图：Agent在审查时参考的代码与文档映照表
└─ review-checklist.md // 检查清单：具体执行评判时依赖的标准化标准列表

机制解说： 主控 Agent 获取到任务后，会加载对应的 SKILL.md，并根据其引导自主去 references/ 内使用 view_file 阅读清单，从而在 零代码污染 前提下完成极其复杂的规范审查。

06 / 06

单一任务的生命周期

1
理解感知 (Perception)
主控节点解析指令 ➔ 匹配具体子 Agent/Skill ➔ 读取指定的项目配置与知识库（如 SKILL.md 中的 references）。
2
规划执行 (Execution)
基于获取的 Checklist 与规范 ➔ Server 切出 Worktree ➔ Agent 在内部沙盒进行高频分析、文件读写、冲突处理。
3
闭环验证 (Validation)
数据落盘后触发验证流 ➔ 如遇门窗包围盒碰撞 / 间距非法则发起修订 ➔ 状态无误后，Commit 封版。
4
决策反馈 (Review & Merge)
提交生成的多线方案 ➔ 前端画板以三联屏呈现设计图 ➔ 用户可基于局部（Zone）或者全局进行 Cherry-pick 合并到 Main 分支。
