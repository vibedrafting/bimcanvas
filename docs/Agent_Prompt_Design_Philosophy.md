## §1 提示词的本质

提示词不是"命令"，而是**认知环境的构建**。

很多人把提示词当编程指令——写 if-then-else 式的规则，期待 AI 精确遵循。但 AI 的工作方式根本不是这样的。AI 在生成每一个 token 时，做的是**在给定上下文中选择最可能的延续**。提示词构成了这个"给定上下文"——它决定的不是"AI 做什么"，而是"AI 站在什么认知环境中做决策"。

### 五个底层机制

**机制 1：注意力是零和的**

提示词中的每个 token 都在竞争 AI 的注意力。你写了 10 条规则，每条分到 10% 注意力；写了 100 条，每条只剩 1%。这不是比喻——这是 transformer 注意力机制的直接后果。

**细化**：实际的注意力分配不是严格均分，而是**内容相关的**——与当前推理步骤高度相关的规则会获得更多注意力权重。但这不改变核心结论：规则越多，模型**定位并聚焦正确规则的难度越大**。这本质上是一个信息检索问题——噪音越多，信号越难找到。

这也解释了为什么结构化分层（§2 第一层）如此重要：清晰的章节标题和层级结构不仅是排版美观，它们实质上**缓解了注意力稀释**——帮助模型快速定位与当前任务相关的规则区域，而不必在一大段平铺的文本中逐条扫描。

**推论**：一条精准的规则 > 十条模糊的规则。每加一条规则，所有已有规则的权重都在被稀释。提示词越多不代表越好——每条规则都有认知成本。

**机制 2：提示词激活知识区域，而非注入知识**

当你写"作为资深室内设计师"，AI 不是在"扮演"——它是在激活训练数据中与室内设计相关的知识区域。这意味着：

- 提示词**能唤醒** AI 已有的知识（"考虑 L 形转角衣柜方案"→ 激活相关设计模式）
- 提示词**无法注入** AI 没有的知识（如果 AI 从未见过某种布局，再详细的规则也只能让它机械模仿）

**推论**：概念引入（如"L 形转角衣柜"）之所以有效，是因为 AI 的训练数据中已有这个设计模式，提示词只是激活了它。规则修复的是参数，概念引入激活的是整个知识区域——这是完全不同量级的影响。

**机制 3："为什么"改变的是泛化能力**

这是最关键的底层机制之一。

告诉 AI "衣柜填满有效段"——AI 得到一条规则，只能在完全匹配的场景中执行。

告诉 AI "衣柜填满有效段，因为连续柜面视觉更整洁且最大化收纳"——AI 得到一个**推理框架**。当遇到有效段只有 1.2m（放不下标准柜）时：
- 只有规则的 AI：硬塞一个柜子，或者困惑地放弃
- 有推理框架的 AI：理解目标是"视觉整洁 + 收纳"，可能推导出用书架或储物柜替代

**推论**：WHY 不是"锦上添花"，它从根本上改变了规则的适用范围。没有理由的规则只能被机械执行；有理由的规则能被灵活应用。

**机制 4：示例是最强的模式锚定**

这是与机制 3 同等重要、却最容易被低估的机制。

AI 从示例中提取模式（pattern matching）比从文字指令中解析规则（instruction following）更自然、更高效。这不是偶然——transformer 的训练过程本身就是大规模的模式提取，示例直接对接了这个底层能力。

```
# 10 条文字规则描述布置输出格式：
#   "bounds 用 [x, y, width, height] 表示..."
#   "facing 用 'north/south/east/west' 表示..."
#   "每个模块必须包含 moduleId 字段..."
#   ...（继续 7 条）

# 1 个示例达到同等甚至更好的效果：
# 输入：次卧，3600×3200，南墙窗户，北墙门
# 输出：
# {
#   "moduleId": "bed_1500",
#   "bounds": [1050, 200, 1500, 2000],
#   "facing": "south",
#   "reason": "床头靠北墙居中，朝向南窗采光"
# }
```

一个好示例传递的信息密度远超十条文字规则——它同时锚定了**数据格式、数值范围、命名风格、决策逻辑**，而且 AI 不需要"理解"指令就能复现模式。

**与其他机制的关系**：

- **与机制 2（激活知识区域）天然配合**：文字规则只激活"规则遵循"的认知模式；示例同时激活格式模式和领域知识——AI 看到一个布置示例时，不仅学会了输出格式，还激活了"室内设计布置"这整个知识区域。示例是最高效的"知识区域激活器"。
- **与机制 3（WHY）互补而非替代**：WHY 提供推理框架让 AI **泛化**（在新场景中推导），示例提供具体锚点让 AI **精准**（在已知模式中复现）。WHY 管"方向"，示例管"精度"——最强的提示词两者兼有。

**推论**：当你能提供一个好示例时，优先用示例——它的信息传递效率最高。当场景太多变无法穷举示例时，用 WHY 提供推理框架。两者不是替代关系，而是协作关系：**示例锚定基准，WHY 覆盖边界**。

**机制 5：位置效应——头尾优先**

AI 对提示词**开头和结尾**的内容关注度高于中间部分。这被称为"lost in the middle"现象——当提示词较长时，中间段落的信息更容易被"遗忘"或降低权重。

**推论**：最关键的规则（硬约束、核心原则）应放在各文件的**头部或尾部**，而非埋在中间。这对 BIMCanvas 的三文件架构有直接影响——每个文件的开头应是最重要的规则或原则总结，结尾应是关键的检查清单或禁止项。中间放详细的说明性内容。

### 正面作用与反面作用

| 正面 | 反面 |
|------|------|
| 减少歧义——明确约束让 AI 不用猜测意图 | 过度约束——规则太多互相矛盾，AI 被迫妥协 |
| 提升一致性——规范和模板让输出风格统一 | 注意力稀释——提示词太长，关键信息被噪音淹没 |
| 激发深度——WHY 和原理让 AI 探索更深层解法 | 虚假确定性——指令过于具体，AI 不敢偏离低效路径 |
| 防止遗漏——禁止项精准修剪不需要的行为 | 留白缺失——所有决策点都被规则覆盖，AI 没有空间施展判断力 |
| 模式锚定——示例高效传递格式+逻辑+风格 | 示例偏见——不恰当的示例会让 AI 过度拟合特定模式，丧失灵活性 |

## §2 提示词设计三层论

好的提示词设计有三个层次。大多数设计者只做前两层，结果是 AI 合规但机械。第三层——留白——决定了 AI 能否从"不犯错"升级到"有品味"。

### 第一层：信息架构 — 决定 AI "怎么处理"信息

信息架构是基础设施——做对了不加分，做错了严重扣分。

**结构化分层，而非平铺直叙**

```
# 错误：一大段文字混合目标、约束、步骤
# 正确：分层组织
  第一层：角色和目标（你是谁，要做什么）
  第二层：约束和规范（不能做什么，标准是什么）
  第三层：具体指令（步骤、模板、示例）
```

AI 处理结构化信息的效率远高于连续文本。章节标题、表格、层级列表都能帮助 AI 快速定位相关规则——它们不是为了"好看"，而是帮 AI 建立信息索引。

**保持信噪比**

每条规则都应该问：**去掉这条，AI 的行为会变差吗？** 如果不会，就删掉。冗余规则不是无害的——它们占用 AI 的注意力配额（机制 1），稀释真正重要的规则的权重。

### 第二层：认知校准 — 决定 AI "以什么标准"工作

认知校准不是告诉 AI 每一步做什么，而是校准它的判断力：

**用示例锚定输出模式（机制 4 的实践）**

```
# 弱：请用简洁专业的语言描述布置方案
# 强：参考示例——"床头靠北墙居中，两侧各留 500mm 放置床头柜，衣柜沿东墙填满 2400mm 有效段"
```

AI 从一个具体示例中提取到的模式，远比十句抽象描述更精确。

示例能校准的远不止输出风格——它还能校准**推理深度**（示例中展示了多少步推理，AI 就倾向于做多少步推理）、**决策逻辑**（示例中如何权衡取舍，AI 就学会同样的权衡方式）、**边界处理**（示例中遇到异常怎么处理，AI 就知道边界场景的应对策略）。

**成本意识**：示例虽强，但也占用 token（机制 1）。1-2 个精选的代表性示例 > 5 个冗余的重复示例。选择示例时，优先覆盖**最典型的场景**和**最容易出错的边界场景**——前者锚定基准，后者防止偏差。

**用禁止项校准行为边界**

AI 的默认行为是"尽可能多做"——加功能、加容错、加优化。明确的禁止项能精准修剪不需要的行为。"不要做什么"比"要做什么"更重要——修剪比添加更精准。

在 BIMCanvas 中的体现：`BIMCANVAS.md` 的禁止事项（禁止编造家具、禁止凭猜测修改）比正面指令更有效地防止了 Agent 的过度行为。

**用 WHY 校准推理方向**

```
# 弱："衣柜应填满有效段全长"
# 强："衣柜应填满有效段全长——连续柜面比碎片化布置视觉更整洁，且最大化收纳效率"
```

WHY 改变的不只是行为，是泛化能力（机制 3）。当 AI 理解规则背后的原因，它就能在**规则未覆盖的边界场景**中做出合理推断。

**用渐进信任校准自主权**

分阶段给 AI 放权——先做方案让人审核，再逐步扩大自主权。BIMCanvas 的"阶段 A → 验证 → 阶段 B"就是这种模式的实践：不是让 AI 一次布完所有家具，而是分阶段布置、分阶段验证。

### 第三层：留白 — 决定 AI "在哪里发挥"判断力

这是最反直觉的一层——**好的提示词不追求全覆盖**。

过度规则化的提示词会产生一个隐蔽的问题：AI 把所有注意力用于"检查是否违反规则"，而非"思考怎么做得好"。

> 三层关系：信息架构是地基，认知校准是框架，留白是灵魂。
> 人类设计师的"好品味"恰恰体现在没有硬性规则的地方。
> 第三层决定了 AI 能否从"不犯错"升级到"有品味"。

留白的完整论述见下一章。

## §3 留白的设计哲学

### 3.1 为什么留白是最重要的

一个被交通法规塞满脑子的司机，每个路口都在想"这里能不能右转、限速多少、有没有单行线"——他是合规的，但他的驾驶是机械的。一个好司机内化了法规（不需要占用注意力），剩余的认知资源用于判断路况、预判行人、选择最舒适的车速。

**提示词的留白，就是有意识地把认知资源还给 AI，让它用于判断和创造。**

**比喻的边界**：人类司机能"内化法规"是因为有数千小时的驾驶经验，而 AI 对你的规则体系没有"内化"过程——每次对话都是从头读取全部提示词。减少规则数量不等于 AI"已经内化了这些规则"，而是等于 AI 根本没有这些规则。因此，留白**只能在 AI 训练数据中已有充分常识的领域使用**——比如"间距分配比例"（AI 的训练数据中有大量室内设计知识），而不能在领域特异性强的地方留白（比如 BIMCanvas 特有的 Zone 坐标系统）。

**务实预期**：对于 BIMCanvas 这种约束密集的工程场景，留白的价值更多体现在**防止僵化**——让 AI 在边界场景中不死板套用规则，而非期待它产出令人惊艳的创意设计。留白让 AI 从"遇到规则未覆盖的场景就卡住"升级到"能做出合理的折中判断"——这已经是很大的进步。

### 3.2 控制的悖论

```
规则越多 → AI 越多注意力用于合规检查 → 越少注意力用于思考 → 输出越机械
规则越少 → AI 越多注意力用于思考 → 但可能偏离意图 → 需要精准校准替代规则数量
```

真正的控制不来自穷举规则，而来自**共识**——当 AI 理解了目标和原理（§2 第二层的 WHY），它能在没有规则的地方做出与你一致的判断。

这就是为什么第二层（认知校准）和第三层（留白）必须配合使用：没有校准的留白是失控，没有留白的校准是僵化。

### 3.3 三级约束模型

| 层级 | 性质 | 示例 | AI 行为 | 设计态度 |
|------|------|------|---------|---------|
| **硬约束** | 功能 / 安全 | 门开启不被阻挡、主通道 ≥ 900mm | 必须满足，无例外 | 明确写出，语气强硬（"必须"/"禁止"） |
| **软指导** | 设计规范 | 床头靠实墙、衣柜填满有效段 | 默认遵守，可在说明理由后偏离 | 写出规则 + WHY，用"应"/"建议" |
| **自由区域** | 审美 / 偏好 | 间距分配比例、辅助家具位置 | AI 自主决策 | **有意识地不写规则** |

**关键认知：自由区域不是"还没来得及写规则的地方"，而是"经过深思熟虑后决定不写规则的地方"。** 留白是一种设计选择，不是遗漏。

### 3.4 如何在提示词中设计留白

**区分"必须正确"和"可以有品味"**

- 门不被阻挡 → 硬约束（必须写规则）
- 床头柜是否成对 → 软指导（写规则但允许偏离）
- 间距如何分配才好看 → 自由区域（不写规则）

**提供评估维度，而非具体答案**

```
# 过度规则化："窗侧间距 200mm，使用侧间距 600mm"
# 留白设计："间距分配应兼顾采光（靠窗侧）和使用便利（使用侧），
#           具体比例由 Agent 根据房间实际情况判断"
```

前者给了一个死答案，AI 只能机械执行或违反。后者给了评估维度（采光 vs 使用便利），AI 可以在不同房间中做出不同但合理的判断。

**用原理替代规则覆盖边界场景**

不可能为每种户型写规则。但可以提供"空间流动感"和"视觉均衡"这样的设计原理，让 AI 在新场景中自行推导。

人类设计师的工作方式不是查规则表——他们内化了设计原理，在具体场景中**推导**出合理方案。一个优秀设计师面对 L 形房间时，不会去翻"L 形房间规则"，而是基于"空间流动感"和"视觉均衡"这些原理，创造性地利用异形空间。AI 也可以做到这一点——前提是提示词给它提供了原理层面的认知，而不仅仅是规则层面的指令。

**显式标注"这里你做主"**

在提示词中显式标注自由区域，而非让 AI 猜测哪里可以发挥。

例：在 placement_guide 中对辅助家具说"位置由 Agent 根据剩余空间自主决定，优先考虑动线流畅和视觉均衡"——这不是偷懒不写规则，而是明确告诉 AI 这是它的决策空间。

## §4 BIMCanvas Agent 提示词体系

### 三文件架构

```
BIMCANVAS.md (系统身份 + 执行规范)
       │
       ↓ 自动加载
generate-workflow/SKILL.md (执行流程 + 检查清单)
       │
       ├─ 参考 → placement_guide.md (设计知识库)
       │           提供：通道标准、房间布局规范、朝向逻辑、设计原则
       │
       └─ 查询 → module_library.json (模块行为规则)
                   提供：家具尺寸、topology_rules、relation_rules
```

### 各文件职责边界

#### SKILL.md — 流程卡（管"做事的顺序"）

| 应该有 | 不应该有 |
|--------|----------|
| 步骤序列（截图 → 读数据 → 分析 → 放置 → 验证） | 具体设计规范数值（如"窗侧 200mm"） |
| 入口/出口条件（"阶段 A 前必须完成…"） | 详细的评估方法论（如"怎么计算有效段"） |
| 检查清单（H/S 项：逐项确认） | 房间类型的设计经验 |
| 常见误判提醒（已知陷阱） | |

**类比**：施工流程卡——"第 3 步：检查墙面平整度"，但不写"平整度标准是多少"。

#### placement_guide.md — 规范手册（管"做事的标准"）

| 应该有 | 不应该有 |
|--------|----------|
| 通用设计原则（靠墙、顶角、异形利用） | 具体模块的尺寸约束 |
| 房间类型布局规范（主卧/次卧/客厅各怎么布） | 工作流执行步骤 |
| 间距/通道标准值及适用场景 | |
| 整体布局方法论（衣柜选墙、床定位） | |

**类比**：室内设计规范手册——"主卧衣柜应选有效段最长的墙面"。

#### module_library.json — 产品说明书（管"每个零件的规格"）

| 应该有 | 不应该有 |
|--------|----------|
| 模块尺寸 / 参数化约束（size, morphology.limits） | 房间整体布局策略 |
| 放置规则（topology_rules: 靠墙、避门） | 工作流步骤 |
| 模块间关系（relation_rules: 衣柜选墙、组合关系） | |

**类比**：产品安装说明书——"1500 柜体：靠墙放置，选非床头墙最长有效段"。

### 三级约束在各文件中的分布

| 文件 | 硬约束 | 软指导 | 自由区域 |
|------|--------|--------|---------|
| SKILL.md | 步骤序列、入口条件 | 检查清单 S 项 | — |
| placement_guide | 通道/安全标准（"必须"/"禁止"） | 布局规范（"应"/"建议"） | 辅助家具位置、间距分配比例 |
| module_library | topology_rules | relation_rules | — |

### 数据流：规则如何流入 Agent 决策

```
用户请求 "布置次卧"
  │
  ▼
MainAgent 加载 generate-workflow SKILL.md
  │  ← 定义执行步骤、预检规则、检查清单
  ▼
步骤 2: 读取 placement_guide.md
  │  ← 通道标准、房间布置要点、朝向逻辑
  ▼
步骤 4: 读取 module_library.json
  │  ← 家具尺寸 + topology_rules + relation_rules
  ▼
步骤 6A: 综合三者做出布置决策
  │  → placement_guide 提供标准值和设计原则
  │  → relation_rules 提供模块特定约束
  │  → SKILL.md 提供预检规则和误判提示
  ▼
写入 → validate_layout → 截图审查(检查清单)
```

## §5 核心矛盾与演进方向

### 核心矛盾：规则合规性 vs 设计创造力

BIMCanvas Agent 的提示词体系具有 **重规则、强流程、弱原理** 的特征：

- **规则丰富**：placement_guide 覆盖了主卧、次卧、客厅等各类房间的布置细节
- **流程严格**：SKILL.md 定义了线性阻塞的工作流，每步都有入口条件
- **原理稀薄**：规则大多是结论式的（"应该这样做"），较少解释设计逻辑（"因为这样做能达到什么效果"）

这种特征的结果是：**AI 能可靠地生成"不犯错"的布置方案，但难以生成"有设计感"的方案。**

用 §3 的语言说：当前体系的硬约束和软指导很完善，但自由区域几乎不存在——所有决策点都被规则覆盖了，AI 没有空间施展判断力。

### 四个演进方向

**方向一：原理层 — 让 AI 理解"为什么"**

**主战场**：`placement_guide.md`

```
当前：靠墙放置（原则） → 衣柜选最长有效段（规则）
目标：靠墙放置（原则） → 连续柜面视觉整洁 + 最大化收纳（原理） → 衣柜选最长有效段（规则）
```

为关键规则补充设计原理，形成"原理 → 规则"的推导链。不是写论文——1-2 句话点明即可。

**价值**：当 AI 遇到规则未覆盖的场景时，能从原理出发推导合理决策，而不是僵硬套用最接近的规则。

**方向二：留白释放 — 让 AI 知道"哪里可以发挥"**

运用 §3 三级约束模型，在提示词中显式区分硬约束、软指导、自由区域。

当前问题：所有规则的语气都差不多强硬，AI 不敢偏离任何一条。标注约束层级后，AI 知道在哪里必须严格遵守，在哪里可以展现设计直觉。

**方向三：目标评估 — 让 AI 判断"做得好不好"**

当前状态：检查清单只验证合规性（"有没有阻挡门开启"），缺少设计品质评估。

新增评估维度（示意）：

| 维度 | 评估内容 |
|------|---------|
| 空间流动感 | 动线是否自然？有没有需要侧身的路径？ |
| 视觉均衡 | 家具视觉重量是否平衡？有没有一侧拥挤另一侧空旷？ |
| 功能舒适度 | 日常动作（起床、开柜、坐下）是否都有充足空间？ |

**价值**：让 AI 能区分"合格的布置"和"优秀的设计"，从被动合规走向主动追求品质。

**方向四：示例驱动 — 让 AI 看到"好的长什么样"**

**主战场**：`placement_guide.md` + `SKILL.md`

当前状态：整个提示词体系几乎没有完整的输入→输出示例。所有设计知识都以文字规则形式传递。

目标：为关键场景提供 1-2 个精选的端到端示例：

```
示例维度 1（典型场景）：
  输入：标准主卧 3600×4200，南窗北门，需放置床+衣柜+床头柜
  输出：完整布置 JSON + 每个模块的决策理由
  → 锚定 AI 对"标准布置"的理解基准

示例维度 2（边界场景）：
  输入：异形次卧，L 形空间，有效段不足
  输出：折中方案 + 偏离规则的理由说明
  → 示范 AI 在规则冲突时如何权衡取舍
```

**与前三个方向的关系**：示例是原理层（方向一）和留白（方向二）的"落地加速器"——光讲原理，AI 可能理解但不知道怎么用；给一个示例，AI 立刻知道原理在实践中长什么样。示例也是目标评估（方向三）的天然载体——好的示例本身就定义了"什么是好的布置"。

**价值**：用最小的 token 成本（1-2 个示例）获得最大的行为校准效果。优先于继续堆砌文字规则。

### 四个方向的关系

```
示例驱动 → AI 看到"好的长什么样"→ 锚定基准 + 加速理解
         ↓
原理层 → AI 能理解"为什么"→ 面对新场景能推导
         ↓
留白释放 → AI 知道"哪里可以发挥"→ 在自由区域展现创造力
         ↓
目标评估 → AI 能判断"好不好"→ 自主迭代提升品质
```

## §6 实操指南：调优提示词时的检查清单

### 新增一条规则前，问自己

1. **这条规则解决的是已发生的问题，还是假想的问题？** 只为实际出现的 Agent 错误行为增加规则。
2. **这条规则放在哪个文件？** 按职责边界放置——流程规则 → SKILL.md，设计标准 → placement_guide，模块行为 → module_library。
3. **去掉这条规则，AI 会犯错吗？** 如果不会，不要加。每条规则都有认知成本。
4. **这条规则和现有规则有冲突吗？** 检查是否与其他规则矛盾。矛盾的规则比没有规则更糟——AI 会在矛盾中随机选择。
5. **这条规则需要解释原因吗？** 如果规则的逻辑不自明，加一句"因为……"。
6. **这条规则应该是哪个约束层级？** 硬约束用"必须"/"禁止"，软指导用"应"/"建议"，自由区域则有意识地不写规则。

### 修改规则时的注意事项

- **改规则前先理解 Agent 的决策链**：读日志，追踪 Agent 实际读取了哪些规则、做了什么推理。问题可能不在规则本身，而在 Agent 对规则的理解。
- **优先修改 placement_guide**：它是 Agent 的"设计知识库"，影响面最广。module_library 的修改只影响单个模块。
- **避免在 SKILL.md 中硬编码设计知识**：如果发现自己在 SKILL.md 中写具体数值（如"窗侧 200mm"），说明这条规则应该放在 placement_guide 里。
- **一次只改一个变量**：修改一条规则后测试效果，确认有效再改下一条。同时改多条规则无法判断是哪条起了作用。

### 常见反模式

| 反模式 | 表现 | 正确做法 |
|--------|------|---------|
| **规则叠加** | 为了修复 A 问题加了规则 X，X 导致 B 问题又加规则 Y | 找到根因，用一条精准规则解决 |
| **职责越界** | SKILL.md 中写了具体设计标准 | 拆到 placement_guide 中，SKILL.md 只引用 |
| **面面俱到** | 试图用规则覆盖每一种可能场景 | 提供原理让 AI 自行推导边界场景 |
| **语气一致** | 所有规则都用"必须""禁止"语气 | 区分约束层级，建议性规则用"建议""优先" |
| **重复表述** | 同一条规则在多个文件中重复出现 | 一处定义，其他处引用 |
| **留白恐惧** | 对每个决策点都写规则，不敢给 AI 自主权 | 区分三级约束，自由区域有意识地不写规则 |
| **示例缺失** | 用大量文字规则描述期望的输出格式和决策逻辑 | 提供 1-2 个精选的输入→输出示例，用模式锚定替代规则堆砌 |
