# 提示词设计原则

> AI Agent 提示词设计的核心原则与实操指南。
> 面向读者：进行提示词设计与优化的开发者或 AI assistant。

### 核心速览

| 机制 | 一句话 |
|------|--------|
| 注意力零和 | 规则越多，每条规则的权重越低 |
| 激活而非注入 | 提示词唤醒 AI 已有知识，无法注入新知识 |
| WHY = 泛化 | 有理由的规则能灵活应用，没理由的只能机械执行 |
| 示例 = 锚定 | 一个好示例的信息密度远超十条文字规则 |
| 位置效应 | 头尾内容获得更多注意力，中间容易被遗忘 |

**三层论**：信息架构（怎么组织）→ 认知校准（以什么标准）→ 留白（哪里发挥）

**三级约束**：硬约束（必须/禁止）→ 软指导（应/建议）→ 自由区域（AI 自主）

## §1 五个底层机制

提示词不是"命令"，而是**认知环境的构建**。它决定的不是"AI 做什么"，而是"AI 站在什么认知环境中做决策"。

**机制 1：注意力是零和的**

提示词中的每个 token 都在竞争 AI 的注意力。规则越多，模型定位并聚焦正确规则的难度越大。

**推论**：一条精准的规则 > 十条模糊的规则。每条规则都有认知成本。

**机制 2：提示词激活知识区域，而非注入知识**

当你写"作为资深室内设计师"，AI 不是在"扮演"——它是在激活训练数据中与室内设计相关的知识区域。

- 提示词**能唤醒** AI 已有的知识（"考虑 L 形转角方案"→ 激活相关设计模式）
- 提示词**无法注入** AI 没有的知识（从未见过的模式，再详细的规则也只能让它机械模仿）

**机制 3："为什么"改变的是泛化能力**

告诉 AI "衣柜填满有效段"——只能在完全匹配的场景中执行。告诉 AI "衣柜填满有效段，因为连续柜面视觉更整洁且最大化收纳"——AI 得到一个**推理框架**，遇到边界场景时能从原理出发推导替代方案。

**推论**：没有理由的规则只能被机械执行；有理由的规则能被灵活应用。

**机制 4：示例是最强的模式锚定**

AI 从示例中提取模式比从文字指令中解析规则更自然——transformer 的训练过程本身就是大规模的模式提取。

```
# 10 条文字规则描述 API 响应格式：
#   "status 字段必须是 'success' 或 'error'..."
#   "data 字段包含实际返回内容..."
#   ...（继续 7 条）

# 1 个示例达到同等效果：
# { "status": "success", "data": { "orderId": "12345", "total": 299.00 }, "message": null }
```

**推论**：能用示例时优先用示例；场景多变无法穷举时用 WHY。**示例锚定基准，WHY 覆盖边界**。

**机制 5：位置效应——头尾优先**

AI 对提示词开头和结尾的内容关注度高于中间部分（"lost in the middle"）。最关键的规则放头部或尾部，中间放说明性内容。

## §2 提示词设计三层论

### 第一层：信息架构 — 决定 AI "怎么处理"信息

做对了不加分，做错了严重扣分。

- **结构化分层**：角色目标 → 约束规范 → 具体指令。章节标题和层级列表帮 AI 建立信息索引，缓解注意力稀释。
- **保持信噪比**：每条规则都问——去掉这条，AI 的行为会变差吗？如果不会，删掉。

### 第二层：认知校准 — 决定 AI "以什么标准"工作

校准判断力，而非规定每一步：

- **示例锚定**：一个具体示例校准的不止输出风格，还有推理深度、决策逻辑、边界处理。1-2 个精选示例 > 5 个冗余示例。
- **禁止项**：AI 默认"尽可能多做"。"不要做什么"比"要做什么"更精准。
- **WHY**：为关键规则附 1-2 句理由，让 AI 在规则未覆盖的场景中合理推断。
- **渐进信任**：分阶段放权——执行 → 验证 → 扩展自主权。

### 第三层：留白 — 决定 AI "在哪里发挥"判断力

**好的提示词不追求全覆盖。** 过度规则化让 AI 把注意力用于合规检查，而非思考怎么做好。没有校准的留白是失控，没有留白的校准是僵化。

**三级约束模型**：

| 层级 | 性质 | AI 行为 | 设计态度 |
|------|------|---------|---------|
| **硬约束** | 功能/安全 | 必须满足，无例外 | 语气强硬："必须"/"禁止" |
| **软指导** | 质量规范 | 默认遵守，可说明理由后偏离 | 规则 + WHY，用"应"/"建议" |
| **自由区域** | 风格/偏好 | AI 自主决策 | **有意识地不写规则** |

> 自由区域不是"还没来得及写规则的地方"，而是"经过深思熟虑后决定不写规则的地方"。

**留白实操**：
- 区分"必须正确"和"可以有品味"——只对前者写规则
- 提供评估维度而非具体答案——让 AI 在不同场景中做不同判断
- 显式标注"这里你做主"——而非让 AI 猜测哪里可以发挥

## §3 实操指南

### 新增规则前的检查清单

1. **已发生 vs 假想？** 只为实际出现的错误行为增加规则。
2. **放哪个文件？** 流程规则 → 流程文件，领域知识 → 知识库，模块行为 → 模块规则。
3. **去掉会犯错吗？** 不会则不加。
4. **与现有规则冲突？** 矛盾的规则比没有规则更糟。
5. **能用示例替代？** 能则优先用示例。

### 修改规则的注意事项

- 改规则前先理解 Agent 的决策链——问题可能不在规则本身
- 优先修改知识库文件——影响面最广
- 避免在流程文件中硬编码领域知识
- 一次只改一个变量

### 常见反模式

| 反模式 | 表现 | 正确做法 |
|--------|------|---------|
| **规则叠加** | 修 A 加规则 X，X 导致 B 又加 Y | 找根因，一条精准规则解决 |
| **职责越界** | 流程文件写了领域标准 | 拆到知识库，流程文件只引用 |
| **面面俱到** | 规则覆盖每种可能场景 | 提供原理让 AI 自行推导 |
| **语气一致** | 所有规则都"必须""禁止" | 区分约束层级 |
| **重复表述** | 同一规则多文件出现 | 一处定义，其他引用 |
| **留白恐惧** | 每个决策点都写规则 | 自由区域有意识地不写 |
| **示例缺失** | 大量文字描述期望输出 | 1-2 个精选示例替代 |
