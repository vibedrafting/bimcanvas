# 布局设计评价体系

> 定义"什么是一个设计"和"什么是一个好的设计"——从一个卫生间选墙错误中发现的系统性缺失。

---

## 一、问题的发现

### 表面问题

主卫 rz_4 的台盆和马桶放在了西墙（门偏向的一侧），而理想方案是东墙。门偏向西墙，入门后开阔侧在东——洁具放东墙，进门右转直达；放西墙，进门后要折返。SubAgent 选错了墙面，MainAgent 审查未发现。

### 第一层追问：为什么 SubAgent 选错了？

bathroom.md 的模式A墙面选择规则写的是"距 door 段中心较远的长墙"。这条规则的结论其实指向东墙（门偏西 → 东墙更远），但 SubAgent 仍然选了西墙。规则的措辞太抽象——它告诉 Agent 一个几何计算方法，但没有解释 WHY。Agent 不理解"为什么要选较远的墙"，在 L 形空间的复杂几何下就容易误判。

### 第二层追问：为什么 MainAgent 没发现？

MainAgent 的审查检查了三件事：validate_layout 通过（几何合法）、通道宽度达标（能走过去）、截图确认家具就位。这三项西墙方案都满足——通道宽度 950mm ≥ 900mm 标准。MainAgent 没有能力发现"虽然能走过去，但走的路线不自然"这类设计品质问题。

### 第三层追问：为什么审查体系发现不了？

因为整个审查框架是**工程合规检查**——"是否违反了约束"，而不是**设计品质评估**——"这个设计好不好"。这不是某一条规则的缺失，而是评估维度的系统性缺失。

当前的审查维度"空间合规 / 策略一致 / 设计品质 / 规则遵从"中，"设计品质"只有一句"空间效率合理、功能联动、填充舒适度"——模糊到 Agent 永远能声称满足。

**根本问题：我们定义了"什么不能做"（工程约束），但没有定义"什么是做得好"（设计品质）。**

---

## 二、层层递进的评价体系

好的室内布局需要满足多个层次的要求，每层回答不同的问题：

```
Layer 1  工程合规    "这个布局有没有错？"          以不出错为底线
Layer 2  设计品质    "这个布局好不好？"            以好设计为目标
Layer 3  设计倾向    "这个布局符不符合业主喜好？"    以满足偏好为目标
Layer 4  经济指标    "这个布局花多少钱？"           以成本控制为目标
```

每层是上一层的前提——一个有错误的布局谈不上品质，一个品质差的布局谈不上偏好适配。层次之间不可跳跃。

现阶段聚焦 **Layer 1 + Layer 2**：先建立"不出错"和"做得好"的完整定义。

---

## 三、Layer 1：工程合规

工程合规回答："这个布局是否物理可行、功能完整？"

### 3.1 几何合法性

| 指标 | 含义 | 检查方式 |
|------|------|---------|
| 不越界 | 家具 bounds 完全在 zone 内部 | validate_layout E001 |
| 不穿墙 | 家具不与墙体重叠 | validate_layout E002 |
| 不占柱 | 家具不与柱子等障碍物重叠 | validate_layout E003 |
| 不侵禁区 | 家具不在门扇开启区等禁区内 | validate_layout E004 |
| 不重合 | 家具之间不互相重叠 | validate_layout E005 |

这五项由 Server 的 validate_layout 自动检查，是最成熟的一层。

### 3.2 通行可达性

| 指标 | 含义 | 标准 |
|------|------|------|
| 主通道 | 入口到核心功能区的路径 | ≥ 900mm |
| 次通道 | 家具间穿行路径 | ≥ 600mm |
| 全可达 | 每件家具的使用面和每扇窗户可从入口走到 | 无死端 |

这部分在当前 Review 的"可达性验证"中已覆盖，但需要从"通道宽度达标"提升为"所有功能点可达"。

### 3.3 功能完整性（当前缺失）

| 指标 | 含义 | 检查方式 |
|------|------|---------|
| 功能不丢失 | zone.tags 中每个功能标签至少有一个对应模块 | 比对 tags 与已放置模块 |
| 必选不遗漏 | 房间策略定义的"必须"家具全部存在 | 比对房间策略清单 |

示例：卧室 zone 有 tags=[sleep, wardrobeStorage]，如果 modules.json 中没有任何 wardrobeStorage 模块 → 功能丢失 → Layer 1 不通过。

**这是当前体系的一个缺口**——validate_layout 不检查功能完整性，SubAgent 遗漏家具时无人发现。

## 四、Layer 2：设计品质

### 4.1 从 generate-zoning 获得的启发

设计品质的定义不是凭空构造的。generate-zoning 的设计哲学中有三段话，精确地划出了"设计"与"非设计"的分界线：

> **"分区赋予空间以意图"**——有意图的空间才能产出有设计感的布置。

> **"家具属于各自区域的功能叙事"**——每件家具在它所在区域讲述功能故事，家具间的关系有了上下文。

> **"区域间的留白是有意识的空间节奏"**——不是"剩余空间"，而是有意识地创造的呼吸感。

这三个概念——**空间意图、功能叙事、空间节奏**——是在分区层面（宏观空间组织）提出的。但它们同样适用于家具布置层面（微观空间品质）。一个好的布局，在每面墙、每个功能区、每件家具上都应该体现意图、叙事和节奏。

### 4.2 五个品质维度

结合 generate-zoning 的三个核心概念和空间阅读三要素（动线方向、纵深层次、采光轴），Layer 2 由五个品质维度构成：

#### 维度一：动线设计

> 核心问题：从入口到每个功能点的路径是否直觉、无折返？功能序列是否沿动线递进？

动线是用户每天体验空间的方式——每一次进入房间，都在走一条路线。好的动线让人无意识地到达目的地，差的动线让人感觉"每次都要绕一下"。

**评估要点**：

- **入门流线**：门到首个使用点的路径是否直觉？是否需要绕过障碍（如门扇区域）？
  - rz_4 案例：西墙方案需绕过门扇，东墙方案进门直达——动线维度直接区分优劣
- **功能序列**：功能排布是否匹配使用逻辑？
  - 卫生间：洗手 → 如厕 → 淋浴，沿入口→深处递进
  - 卧室：入口 → 衣柜/更衣 → 床，从公共到私密
- **无折返**：日常使用流程中是否需要反方向行走？
  - 如果洗完手后要往回走才能到马桶，说明功能序列与动线方向不一致
- **通行舒适度**：不只是"能走过去"（那是 Layer 1），而是"走起来自然、身体不用侧身或刻意避让"

**与 Layer 1 的区别**：Layer 1 的通行可达性问"能不能走到"，动线设计问"走到的过程是否自然"。900mm 通道宽度是 Layer 1 底线，但一条 900mm 的通道如果需要先折返再前进，动线设计仍然不合格。

#### 维度二：空间意图

> 核心问题：每个区域是否有明确的存在理由？是否存在"无意识的剩余空间"？

来源于 generate-zoning 的核心命题："分区赋予空间以意图"。在家具布置层面，这意味着每一块被家具围合或界定出的区域，都应该有一个可命名的功能身份——而不是"家具放完之后恰好剩下的空白"。

**评估要点**：

- **区域可命名**：每个子区域/墙面有明确的功能主题
  - 好："这面墙是衣帽区"、"这个角落是梳妆区"、"这段是淋浴间"
  - 差："这里是家具放完之后剩下的空间"
- **异形区功能化**：L 形延伸、凹角等非标区域被赋予了具体功能
  - 好：L 形延伸做化妆间、凹角放书桌
  - 差：延伸区空置、凹角留白无用途
- **无无功能死角**：< 600mm 的缝隙既不是通道也不是收纳，就是无意图的残留
  - 此处与 design_principles 的"顶角"规则呼应——贴靠墙角是为了消灭无意图的窄缝

**"意图"不等于"填满"**：空旷区域也可以有意图——"这是主通道的呼吸空间"是意图，"家具放不下所以空着"不是。区别在于：有意图的空白是从功能需求推导出来的，无意图的空白是家具排列的副产品。

#### 维度三：功能叙事

> 核心问题：同一区域的家具是否讲述连贯的故事？墙面是否有统一主题？

来源于 generate-zoning 的"家具属于各自区域的功能叙事"。一面墙上的家具如果形成连贯的功能主题，整体感和设计品质就高；如果东一件西一件无逻辑关联，就是碎片化堆砌。

**评估要点**：

- **墙面主题统一**：
  - 好：一整面墙做衣柜（存储墙）、台盆+镜柜+毛巾架组成洗漱区
  - 差：衣柜-空隙-床头柜-空隙-书桌混杂在同一面墙上
- **功能群组协调**：相关家具形成有逻辑的组合
  - 好：床+床头柜（睡眠叙事）、沙发+茶几+电视柜（休闲叙事）
  - 差：床头柜远离床、茶几和沙发不对位
- **家具关系有逻辑**：相关家具相邻或对位，无关家具不混杂
  - 好：梳妆台靠近衣柜区（更衣+化妆叙事连贯）
  - 差：梳妆台插在床和衣柜之间，打断两个功能区

**叙事的层次**：
- 单件家具有自己的朝向和使用面（微观）
- 一组家具讲述一个功能故事（中观）——这就是功能叙事
- 整个房间的所有组形成完整的空间体验（宏观）——这由分区设计保证

#### 维度四：空间节奏

> 核心问题：从入口到深处是否有意识的递进？留白是设计选择还是无意的遗漏？

来源于 generate-zoning 的"区域间的留白是有意识的空间节奏"和空间阅读的"纵深层次"。空间节奏是感受层面的品质——人走进房间后，从入口到深处是否感受到空间在"讲故事"。

**评估要点**：

- **隐私梯度**：入口侧是公共/过渡功能，深处是私密/静态功能
  - 卫生间：台盆（公开）→ 马桶（半私密）→ 淋浴（最私密）
  - 卧室：衣柜/更衣（过渡）→ 床（核心）
  - 违反隐私梯度：马桶紧挨着门口，进门一览无余
- **密度渐变**：空间感从开放过渡到包裹，或从紧凑过渡到宽敞（取决于房间类型）
  - 不是所有家具挤在入口端，也不是所有家具堆在深处
  - 每个功能区有自己合适的密度
- **有意识的留白**：通道的空旷不是浪费，入口的缓冲不是闲置——它们是节奏的一部分
  - 好：入口有一段"缓冲"再过渡到功能区（从公共空间到私人空间的心理准备）
  - 差：一进门就正对家具，毫无过渡

**节奏不是规则，是感受**：无法用一个数字标准判断节奏好坏。它需要 Agent 理解"人走进这个空间后的体验序列"，而不是只看家具坐标。

#### 维度五：采光通风

> 核心问题：窗户资源是否被合理利用？光路是否通畅？

来源于空间阅读的"采光轴"。窗户是室内空间最珍贵的资源——它带来自然光、新鲜空气和空间感。家具布置不应该浪费这个资源。

**评估要点**：

- **光路保持**：高大家具不切断窗 → 深处的光线通路
  - 好：高柜沿非窗墙布置，窗墙附近保持低矮
  - 差：高衣柜正对窗户，深处空间变暗
- **功能-光匹配**：需要自然光的功能靠窗
  - 好：梳妆台靠窗（化妆需要自然光）、书桌靠窗（阅读需要光线）
  - 差：梳妆台在无窗暗角，窗前放了不需要光的衣柜
- **通风流线**：门窗之间的空气流通路径不被大面积家具完全阻断
  - 卫生间尤其重要：淋浴区临窗有利于排湿通风

**例外**：design_principles 中已注明"卫生间淋浴区可临窗"——淋浴需要通风和采光，是这条维度的正面示例。

## 五、核心原理：品质标准就是设计目标

### 5.1 好的设计不是碰巧的

rz_4 的问题揭示了一个更深的认知偏差：**我们把品质标准当成了"事后审查清单"，但好的设计不是先随便做、再检查有没有碰巧做对——好的设计从一开始就知道自己要往哪走。**

一个人类设计师在画卫生间平面时，不会先随便选一面墙放台盆，画完再检查"动线自然不自然"。他在拿起笔之前就已经想好了："门在这边，人进来往那边走，所以台盆应该在那边。"动线自然性不是事后检验标准，而是从第一笔就在引导他的设计目标。

这正是 rz_4 出错的真正原因。SubAgent 有一条规则说"选距门中心较远的长墙"，但它不知道这条规则是为了什么。它在执行一个公式，不是在追求一个设计目标。当公式在 L 形空间中变得模糊时，Agent 没有更高层的目标可以回退——因为它从来没有把"入门动线自然"设为自己的设计目标。

**如果 Agent 在策略阶段就声明了"进门后直达台盆"这个设计目标，它在选墙时会自然选择入门开阔侧——不需要任何公式。**

### 5.2 品质标准贯穿工作流的始终

设计品质的五个维度（动线、空间意图、功能叙事、空间节奏、采光通风）不只在审查阶段使用。它们应该在工作流的每个阶段扮演不同角色：

**理解阶段——作为空间阅读的透镜**：

Agent 用这五个维度去理解空间的特征和潜力。不只是"这个空间长什么样"（几何描述），而是"这个空间支撑什么样的动线？能讲述什么功能叙事？光从哪里来？"

**策略阶段——作为显式声明的设计目标**：

Agent 在确定布局方案时，必须用品质维度的语言表达设计意图。不是"台盆放东墙"（what），而是"入门右转直达台盆（动线目标）/ 东墙统一布置洗漱区（功能叙事目标）/ L 形转折天然分隔干湿（空间意图目标）"（why）。

这一步是关键——**当设计目标被显式声明，后续的每个执行决策都有了判断依据**。Agent 不再需要靠公式机械地选墙，因为设计目标本身已经指明了方向。

**执行阶段——作为每个决策的判据**：

放置每件家具时，Agent 可以追问自己："这个位置是否有助于实现我声明的设计目标？"选墙时想动线，分组时想叙事，留白时想节奏，靠窗时想采光。品质目标把散落的规则串成了一条设计逻辑链。

**审查阶段——作为目标达成的验证**：

最后才是审查。但此时的审查不再是"拿一份不知道从哪来的清单挨个对照"，而是"检查我在策略阶段声明的设计目标是否在最终布局中实现了"。审查有了锚点，评估有了标准，因为标准就是自己设定的目标。

### 5.3 与 rz_4 问题的对照

如果这个理念在 rz_4 案例中生效：

- **策略阶段**：Agent 声明"入门后开阔侧布置洁具，进门直达——这是动线设计目标"
- **执行阶段**：门偏向西墙，开阔侧在东——根据目标选择东墙，无需纠结公式
- **审查阶段**：验证"进门后首个使用点是否在直觉路径上"→ ✓

如果没有这个理念（即现状）：

- **策略阶段**：Agent 没有设定动线目标，只有一条"选距门中心较远的长墙"的公式
- **执行阶段**：L 形空间中公式含糊，Agent 随机选了西墙
- **审查阶段**：检查通道宽度 950mm ≥ 900mm → ✓（工程合规通过，但动线不自然无人发现）

**差异不在于审查阶段多了什么检查项，而在于整个设计过程有没有被品质目标引导。**

### 5.4 本质：从"规则驱动"到"目标驱动"

当前的工作流本质上是**规则驱动**的：Agent 读一堆规则，按规则放家具，按规则检查。规则覆盖到的地方就做对了，规则没覆盖到的地方就看运气。

品质标准贯穿全流程之后，工作流变成**目标驱动**的：Agent 理解空间后设定品质目标，围绕目标做决策，最后验证目标达成。规则仍然存在（作为约束和指引），但不再是决策的唯一依据——设计目标是更高层的依据。

规则告诉 Agent"不要做什么"（不挡门、不越界、不留死角），目标告诉 Agent"要追求什么"（自然的动线、清晰的意图、连贯的叙事）。两者缺一不可，但目标是驱动力，规则是护栏。

## 六、与现有体系的关系

### 6.1 与 generate-zoning 的关系

generate-zoning 在**宏观层面**（空间如何组织）定义了设计品质的三个核心概念。本评价体系在**微观层面**（家具如何放置）延伸了同样的概念，并补充了动线和采光两个维度。

```
generate-zoning（宏观）          设计评价体系（微观）
"空间以意图"          →          空间意图（每面墙/每个区域有功能主题）
"功能叙事"            →          功能叙事（家具群组讲述连贯故事）
"空间节奏"            →          空间节奏（隐私/密度从入口到深处递进）
空间阅读三要素·动线    →          动线设计（入门流线、功能序列、无折返）
空间阅读三要素·采光    →          采光通风（光路保持、功能-光匹配）
```

两者共享同一套设计语言，只是作用粒度不同。

### 6.2 与 generate-workflow 的关系

设计评价体系重构了 generate-workflow 的审查阶段，将原来的"4 维度平铺"改为"分层递进"：

**原结构**（平铺，层次不清）：
```
空间合规 / 策略一致 / 设计品质(模糊) / 规则遵从
```

**新结构**（分层递进）：
```
Layer 1 工程合规：几何合法 + 通行可达 + 功能完整
  ↓ 全部通过
Layer 2 设计品质：动线 + 空间意图 + 功能叙事 + 空间节奏 + 采光
  ↓ 核心维度通过
策略一致 + 规则遵从（贯穿两层的交叉验证）
  ↓ 全部通过
汇报
```

Layer 1 不通过时不进入 Layer 2——几何错误或功能丢失是底线问题，谈不上设计品质。

### 6.3 与 MainAgent 收尾审查的关系

MainAgent 的收尾审查是 SubAgent 自审之上的**独立防线**。评价体系为 MainAgent 提供了具体的抽检维度：

- **Layer 1 独立验证**：全局 validate_layout + 功能完整性（zone.tags 覆盖率）
- **Layer 2 重点抽检**：动线设计是最高 ROI 的抽检项——检查门位置与家具墙面选择是否匹配入门流线

### 6.4 与各房间策略的关系

五个品质维度是**通用框架**。各房间策略（bathroom.md、bedroom.md 等）可以定义**房间特有的品质标准**：

- bathroom.md："动线设计"在卫生间意味着"洗手→如厕→淋浴沿入口→深处递进"
- bedroom.md："功能叙事"在卧室意味着"衣柜区是连续的存储墙，不被其他功能打断"
- livingroom.md："空间节奏"在客厅意味着"入口→过渡→沙发区→窗景的渐进体验"

通用维度 + 房间特化 = 完整的品质评估能力。

## 七、Layer 3 和 Layer 4（未来展望）

### Layer 3：设计倾向

当 Layer 1 和 Layer 2 稳定后，引入个性化维度：

- 业主偏好储纳空间 → 衣柜容量权重提升
- 业主想要自然光梳妆台 → 梳妆台靠窗成为硬约束
- 业主需要双人办公区 → 书桌区扩大

这些偏好存储在项目级 README.md 或专属偏好文件中，作为 Layer 2 维度的权重调节器。

### Layer 4：经济指标

更远期的维度：

- 方案总成本估算
- 性价比分析（同品质下更经济的替代方案）
- 预算约束下的最优组合

## 八、核心认识总结

1. **"不出错"和"做得好"是两回事**。validate_layout 通过只代表工程合规，不代表设计品质。

2. **设计品质有明确的维度可以被定义和评估**。它不是"感觉好不好"的主观判断，而是动线、意图、叙事、节奏、采光五个可分析的维度。

3. **评估维度应该同时是设计目标**。Agent 在策略阶段显式声明品质目标，在审查阶段验证目标达成——而不是在审查阶段才想起来有这些维度。

4. **好的设计品质体系和创建工作流共享同一套语言**。generate-zoning 的"空间意图/功能叙事/空间节奏"既是创建空间时的指导思想，也是评估空间时的衡量标准。

5. **层层递进不可跳跃**。先保证工程合规（Layer 1），再追求设计品质（Layer 2），再适配个性偏好（Layer 3），最后考虑经济性（Layer 4）。
