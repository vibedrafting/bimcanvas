## 1. 产品概述

### 1.1 一句话定位

**基于 AI CLI 的室内装修平面方案设计助手，用 SVG 作为 Revit 与 AI 之间的数据桥梁，实现人机协作设计。**

### 1.2 核心要素

| 要素 | 角色 | 说明 |
|------|------|------|
| **AI CLI 工具** | 整个项目的运行依赖 | 使用 AI CLI 作为 AI 交互入口 |
| **SVG 中间格式** | Revit ↔ AI 的数据桥梁 | 结构化、AI 可读写的图形格式 |
| **Web 画布** | 人机协作界面 | AI 呈现方案，用户实时编辑/批注 |
| **模块库（族库）** | AI 设计的素材来源 | 提供真实家具数据和对应的 Revit 模型 |
| **Revit-MCP 工具** | AI 在 Revit 中的"眼和手" | 让 AI 能够感知和操作 Revit |

### 1.3 解决的核心问题

| 问题 | 现状 | BIMCanvas 解决方案 |
|------|------|---------------------|
| AI 理解门槛高 | Revit 原生格式复杂，AI 难以直接读写 | SVG 是结构清晰的文本格式，AI 可直接理解 |
| AI 设计是"空想" | AI 输出的家具名称无法对应真实产品 | 模块库提供真实家具 + 对应 Revit 模型 |
| 设计迭代效率低 | 每次修改都需要打开 Revit 操作 | Web 画布实现实时协作编辑 |
| 设计与建模耦合 | 创意构思和专业建模混在一起 | 先在画布设计，确认后再同步到 Revit |

## 2. 目标用户

### 2.1 主要用户画像

**室内设计师**
- 具备专业设计能力
- 使用 Revit 进行建模
- 需要快速出方案与客户沟通
- 希望 AI 辅助完成重复性布局工作

### 2.2 用户痛点

1. Revit 操作复杂，学习曲线陡峭
2. 设计迭代周期长，修改成本高
3. AI 工具无法直接理解和操作 BIM 模型
4. 创意构思阶段被软件操作困住

### 3.2 MVP 执行流程

> **MVP 简化原则**：砍掉"候选清单"、"多方案对比"、"设计知识库"，AI 直出方案，对话调整。

#### Phase 1: 数据提取

```
1. 用户在 Revit 中激活目标平面视图
2. 点击"开始设计"按钮
3. 插件端提取并计算：
   - outline.walls: 墙体轮廓多边形
   - outline.openings: 门窗线段
   - zones[].innerBoundary: 可用空间（已扣除完成面）
   - zones[].exclusionAreas: 门扇禁区（简化矩形）
4. 生成 CanvasDocument JSON
5. Web 端显示户型底图
```

**启动方式**：
- **方式一：快速布置**（一键启动）- 自动提取 → 配置窗口 → 启动 AI CLI
- **方式二：开启对话**（手动引导）- 直接启动 AI CLI，通过对话逐步引导

---

#### Phase 2: 区域确认

```
6. AI 根据 Revit 房间名称初步填写 zones[].function
7. Web 端显示功能标签
8. 用户确认/修改各区域功能
```

---

#### Phase 3: 方案生成

```
9. AI 直接生成布置方案（不做候选清单）
   - 遵循约束：innerBoundary 内、避开 exclusionAreas
10. Web 端显示完整平面布置图
```

**AI 布置约束**：
- 模块 bounds 必须完全在 zone.innerBoundary 内
- 不能与任何 zone.exclusionAreas 重叠
- 不能与其他已放置模块重叠

---

#### Phase 4: 交互修改

```
11. 用户可以：
    a) 在 Web 端拖拽调整家具位置
    b) 通过对话指导 AI 修改（如"把床转90度"）
12. 循环迭代直到满意
```

---

#### Phase 5: 回写 Revit

```
13. 用户确认最终方案
14. 调用 Revit-MCP：
    - load_family_from_library 加载族
    - create_element 创建家具（基于 levelId + position）
15. Revit 中显示布置结果
```

## 6. SVG Schema 设计

### 6.1 文件结构

```xml
<?xml version="1.0" encoding="UTF-8"?>
<svg xmlns="http://www.w3.org/2000/svg"
     xmlns:bc="http://bimcanvas.io/schema/1.0"
     width="8000" height="6000"
     bc:version="1.0"
     bc:canvas-id="canvas_001">

  <!-- 建筑结构层（锁定） -->
  <g id="layer-structure" bc:type="layer" bc:locked="true">
    <g bc:type="wall" bc:element-id="wall_001">...</g>
    <g bc:type="door" bc:element-id="door_001">...</g>
    <g bc:type="window" bc:element-id="window_001">...</g>
  </g>

  <!-- 家具层 -->
  <g id="layer-furniture" bc:type="layer">
    <g bc:type="furniture"
       bc:element-id="furniture_001"
       bc:family-id="sofa_001"
       bc:revit-type-id="337201"
       transform="translate(3000,2000) rotate(90)">
      <!-- SVG图形 -->
    </g>
  </g>

  <!-- 批注层 -->
  <g id="layer-annotation" bc:type="layer">
    <g bc:type="annotation" bc:element-id="anno_001">
      <text x="5000" y="3000">建议换成L型沙发</text>
    </g>
  </g>

</svg>
```

### 6.2 自定义属性

| 属性 | 说明 |
|------|------|
| `bc:type` | 元素类型：wall/door/window/furniture/annotation |
| `bc:element-id` | 画布内唯一ID |
| `bc:family-id` | 族库中的ID |
| `bc:revit-type-id` | 对应的 Revit TypeId |
| `bc:locked` | 是否锁定编辑 |

## 9. 不做的事情（Out of Scope）

| 不做 | 原因 |
|------|------|
| 3D 渲染效果图 | 超出核心价值，可用其他工具 |
| 施工图深化 | 需要专业 CAD 工具 |
| 材料报价系统 | 业务复杂度高 |
| 多用户同时编辑 | Phase 1 不做，后续考虑 |
