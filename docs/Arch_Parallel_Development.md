## 一、设计目标

**核心问题**：如何让用户在 Web 端同时探索多个设计方案，同时保证 AI Agent 的编辑操作不干扰用户的实时操作？

**解决方案**：基于 Git 分支 + Worktree 的物理隔离架构，结合多窗口对话系统。

## 三、Git 分支模型

### 3.1 分支类型定义

| 分支类型 | 命名规范 | 用途 | 生命周期 |
|----------|----------|------|----------|
| **主分支** | `main` | 当前激活的设计方案 | 永久 |
| **策略分支** | `strategy/{name}` | 不同设计理念的方案 | 长期 |
| **变体分支** | `variant/{strategy}/{name}` | 策略内的阶段性存档 | 中期 |
| **Agent 工作分支** | `agent/{window-id}/{job-id}` | Agent 编辑任务的临时分支 | 短期（用完即删） |

### 3.2 分支关系示意

```
main
 │
 ├── strategy/storage-first ──────────────────► 策略：收纳优先
 │        │
 │        ├── variant/storage-first/v1 ───────► 变体：方案1存档
 │        └── variant/storage-first/v2 ───────► 变体：方案2存档
 │
 ├── strategy/flow-first ─────────────────────► 策略：动线优先
 │
 └── agent/window-1/job-001 ──────────────────► Agent 临时工作分支（短期）
```

### 3.3 策略 vs 变体

| 维度 | 策略分支 | 变体分支 |
|------|----------|----------|
| **本质** | Git 分支 | Git 分支 |
| **来源** | 设计理念不同（初始阶段） | 阶段性决策（开发过程中） |
| **类比** | 树的主干分叉 | 主干上的小枝 |
| **提升** | 可独立为新项目 | 可提升为策略 |
| **UI 显示** | Task 三联屏展示 | 不在三联屏展示 |

## 四、多窗口架构

### 4.1 窗口类型

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Web 端多窗口架构                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐ │
│  │                         真窗口 (Primary Window)                        │ │
│  ├───────────────────────────────────────────────────────────────────────┤ │
│  │  • 首个打开的对话窗口                                                  │ │
│  │  • 直接操作主项目目录                                                  │ │
│  │  • 不可关闭                                                           │ │
│  │  • 可自由切换分支（排除已被其他窗口占用的分支）                         │ │
│  │  • Agent 编辑时创建 Worktree 隔离                                     │ │
│  └───────────────────────────────────────────────────────────────────────┘ │
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐ │
│  │                        虚拟窗口 (Virtual Window)                       │ │
│  ├───────────────────────────────────────────────────────────────────────┤ │
│  │  • 新建的对话窗口                                                      │ │
│  │  • 通过 Git Worktree 操作项目                                         │ │
│  │  • 可关闭（关闭时提示合并/丢弃）                                       │ │
│  │  • 不可切换分支（绑定创建时的分支）                                    │ │
│  │  • Agent 编辑时再创建一个平级 Worktree                                │ │
│  └───────────────────────────────────────────────────────────────────────┘ │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 窗口生命周期

#### 真窗口

```
┌─────────┐     ┌─────────┐     ┌─────────┐
│ 打开项目 │ ──► │ 自动创建 │ ──► │ 持续存在 │ ──► 项目关闭时销毁
└─────────┘     │ 真窗口   │     │         │
                └─────────┘     └─────────┘
```

#### 虚拟窗口

```
┌─────────┐     ┌─────────────┐     ┌─────────┐     ┌─────────────┐     ┌─────────┐
│ 用户新建 │ ──► │ 创建 Worktree│ ──► │ 工作中   │ ──► │ 用户关闭窗口 │ ──► │ 合并/丢弃 │
│ 对话窗口 │     │ 启动 Agent  │     │         │     │             │     │ 清理 WT  │
└─────────┘     └─────────────┘     └─────────┘     └─────────────┘     └─────────┘
```

### 4.3 窗口激活机制

- **同一时间只能激活一个窗口**
- 切换窗口 → Canvas 渲染对应分支的数据
- **一个 Git 分支只能被一个窗口占用**（互斥锁）

### 4.4 Chat 页 vs Task 页

| 页面 | 多开支持 | 用途 |
|------|----------|------|
| **Chat 页** | 支持多开 | 每个窗口对应一个分支的对话交互 |
| **Task 页** | 不支持多开 | 全局任务监控 + 策略对比 |

#### Task 页面板设计

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                            Task 页布局                                       │
├────────────────────────────────┬────────────────────────────────────────────┤
│                                │                                            │
│      任务监控面板               │              三联屏面板                     │
│      ══════════                │              ════════                      │
│                                │                                            │
│  ┌──────────────────────────┐  │  ┌────────┐ ┌────────┐ ┌────────┐         │
│  │ 窗口 1 (main)            │  │  │策略 A  │ │策略 B  │ │策略 C  │         │
│  │  ├─ Agent: 运行中        │  │  │收纳优先│ │动线优先│ │极简风格│         │
│  │  └─ SubAgent-1: 完成     │  │  │        │ │        │ │        │         │
│  ├──────────────────────────┤  │  │        │ │        │ │        │         │
│  │ 窗口 2 (strategy/flow)   │  │  │        │ │        │ │        │         │
│  │  ├─ Agent: 空闲          │  │  │        │ │        │ │        │         │
```

## 五、Worktree 架构

### 5.1 核心原理

**Git Worktree 允许同一个仓库同时检出多个分支到不同目录**，实现物理隔离的并行工作。

```
主项目/.git/                    ← 共享的 Git 历史（唯一）
│
├── 主项目/                     ← 真窗口直接操作
│   ├── baseline/
│   ├── schemes/
│   └── ...
│
├── .worktrees/
│   │
│   ├── window-2/               ← 虚拟窗口 2 的 Worktree
│   │   ├── baseline/
│   │   ├── schemes/
│   │   └── ...
│   │
│   ├── agent-main-job1/        ← 真窗口 Agent 任务的 Worktree
│   │   └── ...
│   │
│   └── agent-wt2-job1/         ← 虚拟窗口2 Agent 任务的 Worktree
│       └── ...
```

### 5.2 Git 核心限制与合并机制

#### Git 核心限制

> **Git 不允许两个 Worktree 检出同一个分支**

这意味着：
- 如果 Worktree-A 检出了 `branch-A`
- 则 Agent 的 Worktree **不能**再检出 `branch-A`
- 必须创建新分支（如 `branch-A-agent-job-1`）

#### 关键技术发现

**合并操作是在分支上进行的，不是在 Worktree 之间进行的。**

可以直接在用户 Worktree 中执行合并：
```bash
cd /path/to/worktree-A
git merge branch-A-agent-job-1
# ✅ Worktree-A 的文件自动更新为合并结果
# ✅ 冲突标记直接出现在 Worktree-A 的文件中
```

**这意味着 Canvas 可以始终渲染用户 Worktree，无需临时切换渲染目标！**

### 5.3 Worktree 平级关系

不能在 Worktree 里"嵌套"创建 Worktree，但可以从同一个 `.git` 创建多个平级 Worktree：

```
❌ 错误理解：Worktree 嵌套
   主项目 → Worktree-A → Worktree-A-1（不可能）

✅ 正确理解：平级 Worktree
   主项目/.git/
     ├─ 主项目/
     ├─ Worktree-A/        （检出 branch-A）
     └─ Worktree-A-job1/   （检出 branch-A-agent-job-1，平级）
```

### 5.4 虚拟窗口 Agent 编辑完整流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    虚拟窗口 Agent 编辑流程                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【前提】                                                                    │
│  • 虚拟窗口 A → Worktree-A (检出 branch-A)                                  │
│  • Canvas 渲染 Worktree-A                                                   │
│                                                                             │
│  【Step 1: 保存用户当前改动】                                                │
│  cd Worktree-A                                                              │
│  git add . && git commit -m "WIP: 用户改动"                                 │
│                                                                             │
│  【Step 2: 创建 Agent 工作环境】                                             │
│  # 基于当前 branch-A 创建新分支                                              │
│  git branch branch-A-agent-job-1                                            │
│  # 创建新的 Worktree（平级，不是嵌套）                                       │
│  git worktree add .worktrees/agent-wt-A-job1 branch-A-agent-job-1          │
│                                                                             │
│  【Step 3: Agent 工作】                                                      │
│  Agent 在 agent-wt-A-job1 中编辑                                            │
│  cd .worktrees/agent-wt-A-job1                                              │
│  # ... 编辑 schemes/rz_*/modules.json ...                                   │
│  git add . && git commit -m "feat: AI 布置方案"                             │
│                                                                             │
│  【Step 4: 在 Worktree-A 中合并】← 关键！                                    │
│  cd Worktree-A                                                              │
│  git merge branch-A-agent-job-1                                             │
│  # ✅ Worktree-A 的文件自动更新为合并结果                                    │
│  # ✅ 如有冲突，冲突标记出现在 Worktree-A 文件中                             │
│                                                                             │
│  【Step 5: 可视化解决冲突】                                                  │
│  # Canvas 继续渲染 Worktree-A（无需切换！）                                  │
│  # 用户通过 UI 选择保留哪些改动                                              │
│  git add . && git commit -m "merge: 合并 AI 方案"                           │
│                                                                             │
│  【Step 6: 清理】                                                            │
│  git worktree remove .worktrees/agent-wt-A-job1                             │
│  git branch -d branch-A-agent-job-1                                         │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 5.5 Worktree 职责明确

| Worktree | 职责 |
|----------|------|
| **用户 Worktree** | 用户交互编辑 + 合并执行 + 冲突解决 + Canvas 渲染源 |
| **Agent Worktree** | 临时工作空间（用完即删） |

### 5.6 Worktree 生命周期

| Worktree 类型 | 创建时机 | 销毁时机 |
|---------------|----------|----------|
| **虚拟窗口 Worktree** | 新建对话窗口 | 关闭窗口（合并后） |
| **Agent 任务 Worktree** | Agent 开始编辑 | 用户确认合并/丢弃 |

**设计原则**：**用完即销毁**

```
创建 ──► Agent 工作 ──► 提交 ──► 可视化 Diff ──► 合并/丢弃 ──► 销毁
```

### 5.4 Worktree 命名规范

| 类型 | 命名格式 | 示例 |
|------|----------|------|
| 虚拟窗口 | `window-{windowId}` | `.worktrees/window-2` |
| Agent 任务（真窗口） | `agent-main-{jobId}` | `.worktrees/agent-main-job1` |
| Agent 任务（虚拟窗口） | `agent-wt{windowId}-{jobId}` | `.worktrees/agent-wt2-job1` |

### 6.2 schemes/ 分区设计

#### 设计原因

1. **支持 SubAgent 并行**：每个 SubAgent 操作独立的 `modules.json`
2. **减少 Git 冲突**：按区域隔离，合并时只比较变化的分区
3. **支持懒加载**：前端按需加载分区数据

#### 分区规则

| 规则 | 说明 |
|------|------|
| **嵌套深度** | 不限制（支持任意深度） |
| **ID 命名** | `rz_*` = 房间分区（自动生成），`dz_*` = 用户自定义分区 |
| **读取方式** | 保持分离，前端按需加载 |

#### MVP 阶段简化

- 不考虑"分区设计"功能
- 直接使用 `computed/room_zones.json` 的初始分区
- 自动生成对应的 `rz_*/modules.json` 空文件

### 7.2 数据流向

#### 用户编辑流

```
用户操作 (Web)
    │
    ▼
Canvas 状态更新
    │
    ▼
REST API → Server
    │
    ▼
写入 schemes/rz_*/modules.json
    │
    ▼
FileWatcher 检测变化
    │
    ▼
WebSocket 广播（同步其他客户端）
```

#### Agent 编辑流

```
用户指令 (Web)
    │
    ▼
Server 创建 Worktree
    │
    ├─► git worktree add .worktrees/agent-xxx feat/ai-xxx
    │
    ▼
启动 Agent，传入 Worktree 路径
    │
    ▼
Agent 在 Worktree 中编辑
    │
    ├─► 写入 schemes/rz_*/modules.json
    ├─► git add . && git commit
    │
    ▼
Agent 完成，通知 Server
    │
    ▼
Server 通知 Web 进入"评审模式"
    │
    ▼
用户查看可视化 Diff
    │
    ├─► 采纳：Server 执行 git merge
    └─► 丢弃：Server 执行 git worktree remove
```

### 7.3 一窗口一分支一线程

**核心约束**：

| 约束 | 说明 |
|------|------|
| **一窗口一分支** | 每个对话窗口绑定一个 Git 分支 |
| **一窗口一 Agent** | 每个对话窗口有独立的后台 Agent 线程 |
| **分支互斥** | 一个分支同时只能被一个窗口占用 |
| **Agent 隔离** | Agent 编辑时必须在 Worktree 中进行 |

## 八、可视化 Merge UI

### 8.1 设计目标

让用户作为"总设计师"，按区域选择性合并 AI 方案与自己的方案。

### 8.2 交互流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         可视化 Merge UI 流程                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【1. Agent 完成】                                                          │
│  Agent 在 Worktree 中完成布置 ──► git commit ──► 通知 Server                │
│                                                                             │
│  【2. 进入评审模式】                                                         │
│  Server 同时读取：                                                          │
│    • 主目录 schemes/（用户方案）                                             │
│    • Worktree schemes/（AI 方案）                                           │
│                                                                             │
│  【3. 渲染对比视图】                                                         │
│  ┌────────────────────────────┬────────────────────────────┐               │
│  │       我的方案              │        AI 方案             │               │
│  │   (main 分支 schemes/)     │   (Worktree schemes/)      │               │
│  ├────────────────────────────┼────────────────────────────┤               │
│  │  [✓] rz_1 次卧一           │  [ ] rz_1 次卧一            │               │
│  │  [ ] rz_3 主卧             │  [✓] rz_3 主卧（AI 优化）   │               │
│  │  [✓] rz_6_1 客厅           │  [ ] rz_6_1 客厅            │               │
│  └────────────────────────────┴────────────────────────────┘               │
│                                                                             │
│  【4. 用户选择】                                                             │
│  用户按分区勾选：哪些保留自己的，哪些采纳 AI 的                              │
│                                                                             │
│  【5. 执行合并】                                                             │
│  Server 执行精确的 JSON Cherry-pick：                                       │
│    • 被选中的 AI 分区 → 覆盖到主目录                                        │
│    • 未选中的 → 保持用户原样                                                │
│                                                                             │
│  【6. 清理】                                                                 │
│  git worktree remove .worktrees/agent-xxx                                  │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 8.3 合并粒度

**按分区 (Zone) 进行差异对比和合并**，而非整个 `modules.json`。

## 九、设计决策汇总

| 决策点 | 决策 | 理由 |
|--------|------|------|
| **modules.json 存储** | 按分区子目录 | 支持 SubAgent 并行，减少 Git 冲突 |
| **分区读取方式** | 保持分离，按需加载 | 支持懒加载，适合大型项目 |
| **分区嵌套深度** | 不限制 | 灵活支持复杂空间划分 |
| **分区 ID 命名** | `rz_*`（房间）/ `dz_*`（自定义） | 区分来源，便于识别 |
| **Worktree 生命周期** | 用完即销毁 | 减少磁盘占用，保持仓库整洁 |
| **窗口与分支关系** | 一对一绑定 | 避免并发写入冲突 |
| **Agent 编辑隔离** | 强制 Worktree | 用户操作不受 AI 干扰 |

## 十、术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| 策略 | Strategy | 基于不同设计理念的方案分支（主干） |
| 变体 | Variant | 策略内的阶段性存档分支（小枝） |
| 真窗口 | Primary Window | 首个对话窗口，直接操作主目录 |
| 虚拟窗口 | Virtual Window | 新建的对话窗口，通过 Worktree 操作 |
| 工作树 | Worktree | Git 的多目录检出机制 |
| 分区 | Zone | schemes/ 下的子目录，对应一个空间区域 |
| 评审模式 | Review Mode | Agent 完成后的可视化对比合并界面 |
