## 一、设计目标

**核心问题**：如何让用户在 Web 端同时探索多个设计方案，同时保证 AI Agent 的编辑操作不干扰用户的实时操作？

**解决方案**：基于 Git 分支 + Worktree 的物理隔离架构，结合多窗口对话系统。

## 三、Git 分支模型

### 3.1 分支类型定义

| 分支类型 | 命名规范 | 用途 | 生命周期 |
|----------|----------|------|----------|
| **主分支** | `main` | 当前激活的设计方案 | 永久 |
| **策略分支** | `strategy/{name}` | 不同设计理念的方案 | 长期 |
| **变体分支** | `variant/{strategy}/{name}` | 策略内的阶段性存档 | 中期 |
| **Agent 工作分支** | `agent/{window-id}/{job-id}` | Agent 编辑任务的临时分支 | 短期（用完即删） |

### 3.2 分支关系示意

```
main
 │
 ├── strategy/storage-first ──────────────────► 策略：收纳优先
 │        │
 │        ├── variant/storage-first/v1 ───────► 变体：方案1存档
 │        └── variant/storage-first/v2 ───────► 变体：方案2存档
 │
 ├── strategy/flow-first ─────────────────────► 策略：动线优先
 │
 └── agent/window-1/job-001 ──────────────────► Agent 临时工作分支（短期）
```

### 3.3 策略 vs 变体

| 维度 | 策略分支 | 变体分支 |
|------|----------|----------|
| **本质** | Git 分支 | Git 分支 |
| **来源** | 设计理念不同（初始阶段） | 阶段性决策（开发过程中） |
| **类比** | 树的主干分叉 | 主干上的小枝 |
| **提升** | 可独立为新项目 | 可提升为策略 |
| **UI 显示** | Task 三联屏展示 | 不在三联屏展示 |

## 四、多窗口架构

### 4.1 窗口类型

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        Web 端多窗口架构                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐ │
│  │                         真窗口 (Primary Window)                        │ │
│  ├───────────────────────────────────────────────────────────────────────┤ │
│  │  • 首个打开的对话窗口                                                  │ │
│  │  • 直接操作主项目目录                                                  │ │
│  │  • 不可关闭                                                           │ │
│  │  • 可自由切换分支（排除已被其他窗口占用的分支）                         │ │
│  │  • Agent 编辑时创建 Worktree 隔离                                     │ │
│  └───────────────────────────────────────────────────────────────────────┘ │
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐ │
│  │                        虚拟窗口 (Virtual Window)                       │ │
│  ├───────────────────────────────────────────────────────────────────────┤ │
│  │  • 新建的对话窗口                                                      │ │
│  │  • 通过 Git Worktree 操作项目                                         │ │
│  │  • 可关闭（关闭时提示合并/丢弃）                                       │ │
│  │  • 不可切换分支（绑定创建时的分支）                                    │ │
│  │  • Agent 编辑时再创建一个平级 Worktree                                │ │
│  └───────────────────────────────────────────────────────────────────────┘ │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 窗口生命周期

#### 真窗口

```
┌─────────┐     ┌─────────┐     ┌─────────┐
│ 打开项目 │ ──► │ 自动创建 │ ──► │ 持续存在 │ ──► 项目关闭时销毁
└─────────┘     │ 真窗口   │     │         │
                └─────────┘     └─────────┘
```

#### 虚拟窗口

```
┌─────────┐     ┌─────────────┐     ┌─────────┐     ┌─────────────┐     ┌─────────┐
│ 用户新建 │ ──► │ 创建 Worktree│ ──► │ 工作中   │ ──► │ 用户关闭窗口 │ ──► │ 合并/丢弃 │
│ 对话窗口 │     │ 启动 Agent  │     │         │     │             │     │ 清理 WT  │
└─────────┘     └─────────────┘     └─────────┘     └─────────────┘     └─────────┘
```

### 4.3 窗口激活机制

- **同一时间只能激活一个窗口**
- 切换窗口 → Canvas 渲染对应分支的数据
- **一个 Git 分支只能被一个窗口占用**（互斥锁）

### 4.4 Chat 页 vs Task 页

| 页面 | 多开支持 | 用途 |
|------|----------|------|
| **Chat 页** | 支持多开 | 每个窗口对应一个分支的对话交互 |
| **Task 页** | 不支持多开 | 全局任务监控 + 策略对比 |

## 五、Worktree 架构

### 5.1 Git Worktree 工作原理

#### 什么是 Worktree

**Git Worktree 允许同一个仓库同时检出多个分支到不同目录**，实现物理隔离的并行工作。

```
主项目/.git/                    ← 共享的 Git 历史（唯一）
│
├── 主项目/                     ← 主 Worktree（根目录本身）
│   └── checkout: master
│
└── .worktrees/                 ← 附加 Worktree 目录
    ├── window-2/               ← 检出 scheme/极致收纳
    └── agent-job-1/            ← 检出 feat/ai-layout-xxx
```

#### Git 核心限制

> **同一个分支不能被两个 Worktree 同时检出**

```
场景：主目录已 checkout master

✅ 可以：git worktree add .worktrees/win2 scheme/极致收纳
   → 不同分支，允许

❌ 不可以：git worktree add .worktrees/win2 master
   → 同一分支，Git 拒绝
```

#### 平级关系（非嵌套）

Worktree 之间是平级关系，不能嵌套创建：

```
❌ 错误理解：嵌套
   主项目 → .worktrees/win2 → .worktrees/agent（不可能）

✅ 正确理解：平级
   主项目/.git/
     ├─ 主项目/           （检出 master）
     ├─ .worktrees/win2/  （检出 scheme/极致收纳）
     └─ .worktrees/agent/ （检出 feat/ai-xxx，与 win2 平级）
```

### 5.2 两种使用场景

BIMCanvas 中 Worktree 有两种不同的使用场景，**必须区分处理**：

#### 场景 A：并行开发（多窗口）

**目的**：用户同时探索多个设计方案

| 属性 | 说明 |
|------|------|
| **触发** | 用户新建 AI 对话窗口 |
| **分支来源** | 检出**已有分支**（用户选择） |
| **生命周期** | 随窗口关闭而删除 Worktree |
| **分支处理** | **保留分支**（用户可能还要用） |

```
用户新建窗口，选择 scheme/极致收纳 分支
    │
    ▼
git worktree add .worktrees/window-2 scheme/极致收纳
    │
    ▼
虚拟窗口 2 操作这个 Worktree
    │
    ▼
用户关闭窗口
    │
    ▼
git worktree remove .worktrees/window-2
❌ 不删除分支（scheme/极致收纳 保留）
```

#### 场景 B：隔离环境（Agent 任务）

**目的**：SubAgent 执行编辑/生成任务时，不干扰用户当前操作

| 属性 | 说明 |
|------|------|
| **触发** | SubAgent 需要执行写操作 |
| **分支来源** | 基于当前分支**创建临时分支** |
| **生命周期** | 合并后立即删除 |
| **分支处理** | **删除临时分支**（用完即弃） |

```
虚拟窗口 A 在 scheme/极致收纳 分支
用户请求："重新布置客厅"
    │
    ▼
基于 scheme/极致收纳 创建临时分支 feat/ai-layout-xxx
git worktree add .worktrees/agent-job-1 -b feat/ai-layout-xxx
    │
    ▼
SubAgent 在临时 Worktree 中工作 → commit
    │
    ▼
合并回 scheme/极致收纳（详见 §5.4）
    │
    ▼
清理：
git worktree remove .worktrees/agent-job-1
git branch -d feat/ai-layout-xxx  ← 删除临时分支
```

#### 两种场景对比

| 维度 | 并行开发（场景 A） | 隔离环境（场景 B） |
|------|-------------------|-------------------|
| **Worktree 类型** | 虚拟窗口 Worktree | Agent 任务 Worktree |
| **分支来源** | 已有分支 | 新建临时分支 |
| **分支前缀** | `scheme/*`, `main` 等 | `feat/ai-*` |
| **删除时** | 保留分支 | 删除分支 |
| **命名** | `window-{id}` | `agent-{job-id}` |

#### 自动存档机制

**创建 Worktree 前，Server 会自动存档未提交的更改**：

```
创建 Worktree 请求
    │
    ▼
Server 检测工作区状态
    │
    ├── 有未提交更改 → 自动执行 git add . && git commit -m "自动存档_{timestamp}"
    │                  （静默执行，不打扰用户）
    │
    └── 工作区干净 → 直接创建 Worktree
```

| 特性 | 说明 |
|------|------|
| **触发条件** | Server API 层检测到 `HasUncommittedChanges()` |
| **存档格式** | `自动存档_{yyyyMMdd_HHmmss}` |
| **用户感知** | 无（静默执行） |
| **适用场景** | 场景 A 和场景 B 均触发 |

> 💡 **设计意图**：避免"工作区不干净导致 Git 操作失败"的问题，确保 Worktree 创建总是成功。

### 5.4 Agent 任务合并流程（关键）

#### 合并原理

**合并操作是在分支上进行的，在用户 Worktree 中执行 merge 命令。**

```bash
# 在用户 Worktree（虚拟窗口 A）中执行
cd .worktrees/window-2               # scheme/极致收纳 分支
git merge feat/ai-layout-xxx         # 合并 Agent 的临时分支
# ✅ 文件自动更新为合并结果
# ✅ 冲突标记直接出现在此目录
```

#### 完整流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Agent 任务合并流程                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  【前提】                                                                    │
│  • 虚拟窗口 A → .worktrees/window-2 (检出 scheme/极致收纳)                  │
│  • Canvas 渲染 window-2 目录                                                │
│                                                                             │
│  【Step 1: 保存用户当前改动】                                                │
│  cd .worktrees/window-2                                                     │
│  git add . && git commit -m "WIP: 用户改动"                                 │
│                                                                             │
│  【Step 2: 创建 Agent 工作环境】                                             │
│  # 基于 scheme/极致收纳 创建临时分支                                         │
│  git worktree add .worktrees/agent-job-1 -b feat/ai-layout-xxx             │
│                                                                             │
│  【Step 3: SubAgent 工作】                                                   │
│  cd .worktrees/agent-job-1                                                  │
│  # ... 编辑 schemes/rz_*/modules.json ...                                   │
│  git add . && git commit -m "feat: AI 布置方案"                             │
│                                                                             │
│  【Step 4: 在用户 Worktree 中合并】← 关键！                                  │
│  cd .worktrees/window-2                                                     │
│  git merge feat/ai-layout-xxx                                               │
│  # ✅ window-2 的文件自动更新为合并结果                                      │
│                                                                             │
│  【Step 5: Canvas 强制刷新】← 重要！                                         │
│  # 合并后 scheme/极致收纳 分支的内容已变化                                   │
│  # Canvas 必须重新读取 window-2 目录并刷新显示                               │
│  # 用户看到合并后的最新结果                                                  │
│                                                                             │
│  【Step 6: 可视化解决冲突（如有）】                                          │
│  # 用户通过 UI 选择保留哪些改动                                              │
│  git add . && git commit -m "merge: 合并 AI 方案"                           │
│                                                                             │
│  【Step 7: 清理】                                                            │
│  git worktree remove .worktrees/agent-job-1                                 │
│  git branch -d feat/ai-layout-xxx   ← 删除临时分支                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 合并注意事项

| 注意点 | 说明 |
|--------|------|
| **合并目标** | 必须合并回临时分支所基于的原分支 |
| **执行位置** | 在用户 Worktree（非 Agent Worktree）中执行 merge |
| **Canvas 刷新** | 合并后必须强制刷新 Canvas，显示最新状态 |
| **窗口状态** | 虚拟窗口不能手动切换分支，但合并会更新内容 |
| **清理顺序** | 先删 Worktree，再删临时分支 |

### 5.5 Worktree 命名规范

| 类型 | 命名格式 | 分支 | 删除时 |
|------|----------|------|--------|
| 虚拟窗口 | `window-{windowId}` | 已有分支 | 保留分支 |
| Agent 任务（真窗口） | `agent-main-{jobId}` | 临时分支 `feat/ai-*` | 删除分支 |
| Agent 任务（虚拟窗口） | `agent-wt{windowId}-{jobId}` | 临时分支 `feat/ai-*` | 删除分支 |

### 5.6 生命周期总结

| Worktree 类型 | 创建时机 | 销毁时机 | 分支处理 |
|---------------|----------|----------|----------|
| **虚拟窗口 Worktree** | 新建对话窗口 | 关闭窗口 | 保留分支 |
| **Agent 任务 Worktree** | SubAgent 开始编辑 | 合并/丢弃后 | 删除临时分支 |

```
│   └── placement_guide.md
│
├── modules/                        # 【素材层】模块库
│   ├── module_library.json
│   └── assets/
│
└── .worktrees/                     # 【临时】Git Worktree 目录
    ├── window-2/                   # 虚拟窗口 2
    └── agent-main-job1/            # Agent 任务
```

### 6.2 schemes/ 分区设计

#### 设计原因

1. **支持 SubAgent 并行**：每个 SubAgent 操作独立的 `modules.json`
2. **减少 Git 冲突**：按区域隔离，合并时只比较变化的分区
3. **支持懒加载**：前端按需加载分区数据

#### 分区规则

| 规则 | 说明 |
|------|------|
| **嵌套深度** | 不限制（支持任意深度） |
| **ID 命名** | `rz_*` = 房间分区（自动生成），`dz_*` = 用户自定义分区 |
| **读取方式** | 保持分离，前端按需加载 |

#### MVP 阶段简化

- 不考虑"分区设计"功能
- 直接使用 `computed/room_zones.json` 的初始分区
- 自动生成对应的 `rz_*/modules.json` 空文件

```
    │
```

### 7.3 一窗口一分支一线程

**核心约束**：

| 约束 | 说明 |
|------|------|
| **一窗口一分支** | 每个对话窗口绑定一个 Git 分支 |
| **一窗口一 Agent** | 每个对话窗口有独立的后台 Agent 线程 |
| **分支互斥** | 一个分支同时只能被一个窗口占用 |
| **Agent 隔离** | Agent 编辑时必须在 Worktree 中进行 |

## 九、Git 工具安全设计

### 9.1 设计原则

**Agent 不能直接执行 Git 命令，必须通过预定义的工具接口**。

| 方案 | 安全性 | 可控性 | 审计 | 错误处理 |
|------|--------|--------|------|----------|
| 直接 Bash 执行 `git` | ❌ 可能误操作 | ❌ 命令不可预测 | ❌ 难追踪 | ❌ 不一致 |
| 预定义工具 | ✅ 限制操作范围 | ✅ 固定脚本 | ✅ 统一日志 | ✅ 统一处理 |

### 9.2 架构位置

**Git 工具直接集成到 Agent 进程内**，不需要独立的 MCP Server：

```
Agent (Python)
    │
    ├─► Git 工具（进程内工具）
    │   ├─► 参数校验
    │   ├─► 调用 Git CLI（subprocess）
    │   └─► 统一错误处理
    │
    ├─► Canvas 工具（进程内工具）
    │   └─► 文件读写操作
    │
    └─► 其他工具...
```

### 9.3 暴露的 Git 工具

```
git/
├── worktree/
│   ├── create      创建 Worktree（基于指定分支创建新分支 + Worktree）
│   ├── remove      删除 Worktree（清理分支）
│   └── list        列出所有 Worktree
├── branch/
│   ├── create      创建分支
│   ├── list        列出分支
│   └── merge       合并分支（在指定 Worktree 中执行）
├── commit/
│   ├── stage       暂存改动
│   └── commit      提交（自动暂存 + 提交）
└── status/
    └── get         获取仓库状态
```

### 9.4 安全限制

| 操作 | 是否允许 | 说明 |
|------|----------|------|
| `worktree create` | ✅ | 仅在 `.worktrees/` 下创建 |
| `branch merge` | ✅ | 禁止 `--force` |
| `diff` | ❌ | Diff 仅在 Web 端可视化，Agent 不需要 |
| `push` | ❌ | 不暴露此工具 |
| `reset --hard` | ❌ | 不暴露此工具 |

## 十、设计决策汇总

| 决策点 | 决策 | 理由 |
|--------|------|------|
| **modules.json 存储** | 按分区子目录 | 支持 SubAgent 并行，减少 Git 冲突 |
| **分区读取方式** | 保持分离，按需加载 | 支持懒加载，适合大型项目 |
| **分区嵌套深度** | 不限制 | 灵活支持复杂空间划分 |
| **分区 ID 命名** | `rz_*`（房间）/ `dz_*`（自定义） | 区分来源，便于识别 |
| **Worktree 生命周期** | 用完即销毁 | 减少磁盘占用，保持仓库整洁 |
| **窗口与分支关系** | 一对一绑定 | 避免并发写入冲突 |
| **Agent 编辑隔离** | 强制 Worktree | 用户操作不受 AI 干扰 |
| **Git 操作方式** | 预定义工具，非 Bash | 安全、可控、可审计 |
