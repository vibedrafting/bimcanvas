# AI 空间理解能力增强指南

> **版本**：v1.0 | **更新日期**：2025-12-22
> **目的**：本文档汇总了关于如何全方位增强 AI 对建筑空间理解能力的深度讨论与共识。核心目标是通过多维度的手段（数据抽象、视觉增强、规则显性化），消除人类视觉与 AI 逻辑之间的鸿沟，使 AI 能够像专业设计师一样进行空间规划。

---

## 1. 核心哲学：AI 是 "OBB 规划师"

在 BIMCanvas 的架构中，我们定义了一个核心隐喻：**AI 是 "OBB 规划师" (Oriented Bounding Box Planner)**。

### 1.1 理解空间的差异

| 维度 | 人类理解空间 (Web/SVG) | AI 理解空间 (JSON/Core) |
| :--- | :--- | :--- |
| **视觉/几何** | **"皮" (SVG)**<br>看到具体的家具形状（L型沙发、圆形茶几）、材质、光影、墙体厚度等视觉细节。 | **"骨" (JSON + OBB)**<br>世界由无数个 **OBB (矩形盒子)** 组成。无论家具是 L 型还是圆形，AI 只操作其外接矩形。 |
| **坐标直觉** | **屏幕坐标 (Y-Down)**<br>符合网页浏览习惯，原点在左上角，Y 轴向下。 | **CAD 坐标 (Y-Up)**<br>符合数学和建筑直觉，原点在左下角，Y 轴向上（`above` = Y 值更大）。 |
| **关注点** | **美感与体验**<br>关注视觉效果、动线流畅度、空间氛围。 | **逻辑与约束**<br>关注**拓扑关系**（在 Zone 内、不重叠）、**数值约束**（距离、尺寸）和**语义方向**（North/South）。 |
| **处理方式** | **直观感知**<br>通过视觉图像直接判断。 | **数据计算**<br>通过 `CollisionDetector` 计算多边形交集和包含关系。 |

### 1.2 核心逻辑

**AI 不计算几何，只决策位置。** AI 的职责被限定为定向包围盒 (OBB) 规划，它不需要理解复杂的墙体构造或精细的家具模型，只需知道"哪里是边界"和"哪里不能放"。

> 详细的 OBB 规划师设计约束见 [PRD.md](./PRD.md) §4.3

## 2. 视觉增强策略：消除"视觉-逻辑"鸿沟

当引入视觉能力（Multimodal AI）作为辅助验证或规划时，直接把给人类看的"精美渲染图"丢给 AI 往往是**低效甚至产生误导**的。我们需要为它提供一张**"经过语义增强的工程视图" (Semantic Debug View)**。

### 2.1 显式化"不可见"的逻辑约束

在人类视图中，很多约束是隐形的（例如门扇的开启半径、墙面完成面的厚度）。AI 如果只看图，可能会把家具摆在门扇开启范围内。

- **禁区 (Exclusion Areas)**：将 JSON 中的 `exclusionAreas`（如门开合区）渲染为**半透明红色**或**斜线阴影**。
- **设计区 (Zones)**：将 `innerBoundary` 渲染为**淡绿色背景**，明确告诉 AI "这是你的安全工作区"。
- **墙体完成面**：用不同颜色描边墙体，标示出不可占用的厚度层。

### 2.2 几何抽象化 (OBB + Facing)

人类视图中的家具细节（圆角、抱枕）对 AI 判断"是否碰撞"或"朝向哪里"是**噪音**。

- **替换为 OBB**：将所有家具渲染为简单的**矩形包围盒**（实线边框）。
- **强化朝向**：在矩形中心画一个**明显的箭头**指示 `Facing`，或者将矩形的一边加粗表示"正面"。
- **去除装饰**：去掉阴影、渐变、纹理，使用高对比度的纯色。

### 2.3 建立"视觉-数据"索引 (ID Tagging)

AI 看到图上的"沙发"时，它无法直接知道这对应 JSON 里的哪个 `id`。

- **ID 覆盖**：在每个模块的包围盒中心，用高对比度文字直接渲染出 `Module ID`（如 `#m_12`）。
- **作用**：当 AI 在视觉上发现问题（比如"#m_12 挡住了 #m_13"）时，可以直接在工具调用中使用准确的 ID 进行修正。

### 2.4 Human View vs. AI View 对比

| 元素 | 人类视图 (Human View) | AI 视图 (AI Semantic View) |
| :--- | :--- | :--- |
| **目的** | 审美、空间感、真实感 | **拓扑验证、约束检查、ID 索引** |
| **家具** | 精美 SVG 符号、圆角、细节 | **纯矩形 OBB + 朝向箭头 + ID 标签** |
| **门窗** | 门扇图标、开启弧线 | **门洞线段 + 红色禁区块 (Exclusion)** |
| **地面** | 地板纹理、地毯 | **淡绿色 Zone 区域 + 网格线** |
| **风格** | 柔和光影、低对比度 | **高对比度、扁平化、工程制图风** |

## 3. 进阶手段：设计场线 (Design Field Lines)

为了符合人类设计师的布置习惯，我们将**隐性的设计规则（Implicit Design Rules）** 转化为 **显性的视觉约束（Explicit Visual Constraints）**。这被称为 **"设计场线"**。

### 3.1 对齐轴线 (Alignment Axes) —— 解决"正对"问题

> *用户案例：客厅的沙发应该正对客厅电视*

- **绘制方式**：识别房间的**主背景墙**（通常是电视墙），绘制一条垂直于墙面的**中轴线**（青色虚线）。
- **AI 直觉**：AI 会倾向于将主要家具（电视柜、主沙发、茶几）的中心点都"吸附"在这条线上。

### 3.2 锚点与中轴 (Anchors & Centering) —— 解决"居中"问题

> *用户案例：电视最好布置在电视背景墙的正中间*

- **绘制方式**：在重点墙面（电视墙、床头墙）的几何中心画一个明显的 **"十字锚点" (Anchor Point)**。
- **AI 直觉**：将家具的核心（如床头板中心、电视中心）对准这个十字。

### 3.3 动线通道 (Circulation Paths) —— 解决"挡路"问题

> *用户案例：客餐厅一体的情况下预留笔直过道*

- **绘制方式**：连接关键出入口（如：入户门 → 阳台门，走廊口 → 餐厅），绘制一条**半透明的灰色带状区域**（宽度如 900mm）。
- **AI 直觉**：这是一条"虚拟河流"，家具不能摆在河里，只能摆在河岸两边。

### 3.4 视线锥 (View Frustums) —— 解决"遮挡"问题

- **绘制方式**：从沙发位置向电视墙方向绘制一个**扇形区域**。
- **AI 直觉**：这个扇形区域内不能有高大的障碍物（如高盆栽、柱子），确保视线通透。

### 3.5 对称参考线 (Symmetry Guides) —— 解决"平衡"问题

- **绘制方式**：以主卧床头墙中轴为界，绘制左右对称的**镜像标记**。
- **AI 直觉**：如果在左边放了床头柜，右边镜像位置也应该放一个。

## 4. 降维打击：语义网格 (Semantic Grid)

将 **连续的度量空间 (Metric Space)** 离散化为 **符号化的拓扑空间 (Topological Space)**，是对 AI 的巨大降维打击。

### 4.1 为什么 "A3, B2" 比 "x:1200, y:3400" 更好？

- **Token 友好**：`C3` 是一个明确的语义符号，而坐标数字需要消耗算力去"计算"。
- **内置常识**：AI 天然知道 "A3 在 B3 的左边"、"A1 到 C3 是对角线关系"。这种空间关系推理是直接通过语义完成的，不需要进行坐标减法运算。

### 4.2 落地策略

- **规格**：设定为 **600mm x 600mm**（标准柜体深度）或 **1000mm x 1000mm**。
- **坐标系**：列 (A, B, C...) + 行 (1, 2, 3...)，原点与 Zone 左下角对齐。
- **视觉呈现**：在截图最上层覆盖淡灰色网格线，边缘标注坐标代码。

### 4.3 交互范式：Coarse-to-Fine (由粗到精)

1. **粗粒度规划 (Grid Level)**：
   - AI: *"我建议把沙发放在 **C2-E2** 区域..."* —— 极快，逻辑清晰。
2. **细粒度调整 (Coordinate Level)**：
   - AI: *"在 C2 网格内，沙发中心微调至 x=2400..."* —— 降低幻觉概率。

## 5. 总结：AI 视觉系统的最终形态

通过上述手段，我们构建了一个完整的 **"AI 增强视觉系统"**，分为四个层级：

| 图层 | 元素 | 作用 | AI 认知模式 |
| :--- | :--- | :--- | :--- |
| **L3: 索引层** | **语义网格 (A1, B2)** | **快速定位、相对关系** | **符号推理 (Symbolic Reasoning)** |
| **L2: 意图层** | **设计场线 (中轴、动线)** | **对齐、避让、居中** | **视觉遵循 (Visual Instruction Following)** |
| **L1: 约束层** | **OBB、禁区、ID** | **碰撞检测、物理边界** | **几何计算 (Geometric Calculation)** |
| **L0: 物理层** | 墙体、门窗轮廓 | 基础环境 | 场景理解 |
