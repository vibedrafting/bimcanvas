## 1. 议题概述

- **主题**：赋予 AI Agent 全局视角与主动反思能力 -- 工作流级提示词重构
- **发起时间**：2026-03-05
- **参与者**：用户（项目负责人）、Claude（提示词架构师）、待邀请其他专家角色
- **背景信息**：

  在"金凤143"主卧布置测试中，AI 按照现有规则在西侧异形区做了 L 形衣柜（符合 placement_guide 7.4 "优先 L 形"规则），效果合规但平庸。用户随口提到"南墙 w_33 有点浪费"，AI 第一反应是建议在南墙加小家具（椅子、斗柜等局部补充）。但用户追问"衣柜放这面墙才合理吧？"后，AI 突然意识到：

  - 南墙(w_33)是主卧最长的实墙（约 3.5m），做连续衣柜整体性极好
  - 释放出的西侧异形区可以做"女主人独立化妆间"（梳妆台 + 储物柜）
  - 一个简单的衣柜位置调整，让平庸方案变成了有设计感的方案（"南侧超级衣柜矩阵" + "独立尊享化妆间"）

  这次经历暴露了当前工作流的核心缺陷：**AI 有能力做出更好的设计，但工作流中缺少主动反思的时机**。

  当前 generate-workflow 的流程是线性执行：
  ```
  前置准备 -> 步骤6:布局骨架 -> 阶段A:主要家具 -> 验证 -> 阶段B:辅助家具 -> 验证 -> 报告
  ```

  其中：
  - 步骤 6.3 骨架自检只检查硬约束冲突（通道宽度、有效段长度），不质疑骨架方案本身是否最优
  - 8A.2 / 8B.2 的设计检查清单有 Q1/Q2 品质自检项，但标注为"参考性，不阻塞流程"
  - AskUserQuestion 工具被 config.json 的 deny list 禁用，AI 无法在关键决策点征求用户意见
  - 整个流程没有"退一步想想有没有更好的路"的环节

  用户的核心诉求：
  1. 从本次成功经验中提取对提示词有用的工作模式
  2. 加强 AI 与用户的沟通能力（启用 AskUserQuestion）
  3. 赋予 AI 全局视角和主动反思能力（工作流级调整，非局部优化）
  4. 本次只修改提示词文件 + 提出功能代码改进需求，AskUserQuestion 的 Web 端实现在新窗口专项完成

- **核心观点**：通过在工作流中嵌入两个反思微步骤（骨架反思 + 全局审视）+ 启用 AskUserQuestion + 补充设计评估维度，赋予 AI "设计师"角色意识，从"规则执行者"升级为"方案评审者"。

- **详细分析**：

  **一、问题诊断**

  在"金凤143"主卧布置测试中，AI 按照规则在西侧异形区做了 L 形衣柜（符合"优先 L 形"规则），效果平庸。用户提到南墙有点浪费后，AI 才意识到：将衣柜移到南墙(w_33) 3.5m 长的连续实墙上，不仅衣柜整体性更好，还释放了西侧异形区做"女主人独立化妆间"，让平庸方案变成了有设计感的方案。

  1. 在骨架阶段（步骤6）嵌入"替代方案审视"，让 AI 在战略决策点主动质疑自己的选择
  2. 在最终报告前嵌入"全局设计审视"，让 AI 以设计总监视角评估整体品质
  3. 通过 AskUserQuestion 在关键决策点与用户沟通
  4. 在 placement_guide 中补充"设计评估维度"，给 AI 判断"好不好"的认知框架

  **1. SKILL.md -- 新增反思步骤 + AskUserQuestion 规范**

  ```
  前置准备：截图 -> 读取数据（步骤 2-4 可并行）
    -> 步骤 5：空间类型判断
    -> 步骤 6：布局规划（动线 + 分区 + 骨架 + 骨架自检 + 骨架反思）

  ```

  **1.2 步骤 6.3 后新增「步骤 6.4 骨架反思」**

  6.4 骨架反思：替代方案审视

  > **设计意图**：骨架是方案的战略决策——锚定哪面墙、动线怎么走、功能区怎么分。
  > 一旦骨架确定，后续只是战术微调。战略方向平庸，战术再精细也无法挽救。
  > 暂停"执行者"角色，切换为"评审者"视角。

  **必须回答的三个问题**（每个问题控制在 1-2 句话）：

  1. **空间潜力**：房间中最有价值的空间资源是什么（最长实墙、独特异形区、最佳采光面）？
     当前骨架是否将最大家具分配给了最有价值的墙面？

  2. **替代骨架**：如果将核心储物家具（衣柜）的锚定墙换到另一面墙，释放出的原始空间
     能否创造新的功能区？这种"联动效应"是否让整体方案品质跃升？

  3. **决策信心**：
     - 当前骨架明显更优 -> 继续执行
     - 替代方案明显更优 -> 修改骨架后继续
     - 各有千秋，涉及用户生活方式偏好 -> 调用 AskUserQuestion 征求用户意见

  > **注意力预算**：这是快速审视，不是完整方案对比。目标是"发现明显的更优解"。
  > 如果当前骨架是顺理成章的最优选择，一句"无明显更优替代"即可通过。

  **1.3 阶段 B 验证后、报告结果前新增「步骤 9 设计反思」**

  步骤 9：设计反思 -- 全局审视

  > **设计意图**：验证回答的是"方案有没有错"。
  > 这个步骤回答的是"方案好不好"——以设计师视角评估整体品质。

  **切换视角**：假设你是第一次看到这个方案的设计总监。
  看着最后一次截图，回答：

  1. **空间叙事**：从入口走进来，视线和动线带来的空间体验是什么？

  2. **遗憾清单**：有没有让你感到"可惜"的地方？
     - 某面长墙被浪费？某个区域可以更好利用？家具组合缺少设计联动感？

  3. **决策**：
     - 无遗憾 -> 进入「报告结果」
     - 有遗憾但属于硬约束限制 -> 在报告中注明限制，进入「报告结果」
     - 有遗憾且明确可改善 -> 调用 AskUserQuestion 描述遗憾和改善方案，询问用户是否优化
       -> 用户同意 -> 回到步骤 6 执行改善（全局调整配额另计）
       -> 用户拒绝 -> 进入「报告结果」

  > **效率保护**：只有"方案会从'合格'变成'有设计感'"时才触发 AskUserQuestion。
  > "可能好一点"不够。

  **1.4 新增「AskUserQuestion 使用规范」小节（放在"报告结果"之后、"常见错误"之前）**

  AskUserQuestion 使用规范

  **仅在以下条件同时满足时触发**：
  1. 存在明确的替代方案（不是模糊的"可能更好"）
  2. 替代方案与当前方案的差异是战略级的（换墙面、换布局模式、功能区重组）
  3. 无法仅凭设计规范判断优劣（两者各有明显优劣，或涉及用户生活方式偏好）

  **提问格式**：
  ```
  当前方案：[一句话核心特征]
  替代方案：[一句话核心特征]
  核心取舍：[选A得到什么/失去什么；选B得到什么/失去什么]
  ```

  - "您觉得这样好吗？"（太笼统，用户无法给出有用反馈）
  - 列出超过 2 个选项（增加选择负担）
  - 战术级问题（"床头柜放左边还是右边"——由规范决定）

  1.3 设计评估维度

  > **WHY**：以下维度不是检查清单，而是评估视角——帮助在多个合规方案间判断哪个"更好"。

  **空间效率**：
  - 最长实墙是"战略资源"——适合放最大家具（衣柜、书柜）。将大家具放短墙、小家具占长墙，通常意味着空间效率倒置
  - 异形区（L形拐角、延伸区）是"特色资源"——可以创造独立功能区（化妆间、阅读角），而非仅仅塞入常规家具

  - 移动一件核心家具会产生"蝴蝶效应"：释放或占据空间，影响其他家具的可能性

  - 入口侧适度留空（过渡缓冲）-> 功能区适度密集 -> 窗前适度留空（采光呼吸）
  - "满铺"和"稀疏"都不是好设计——需要密与疏的有意识交替

### 专家：Antigravity（深层架构与流程分析专家）

**1. 深度日志分析：AI 究竟被什么限制了？**

在金凤143主卧案例中，AI 最初的方案表现平庸，但在用户提示后给出了令人惊艳的“功能置换”方案。为什么它没能自主想到？

**根因诊断：规则执行的“单向满足” vs 设计的“全局最优”**
- 限制点：AI 严格遵循了 `placement_guide.md` §7.4 的**软指导（建议）**——“优先评估 L 形模式”。西侧的异形区域完美符合 L 形衣柜条件，于是 AI 认为找到了“合规解”，就停止了对其他可能性的探索。
- 缺失的本质：AI 的注意力完全被“合规性检查”占用（哲学机制1：注意力零和），满足于**局部正确**，缺乏**全局空间质量的评估维度**（哲学演进方向三：目标评估）。
- 成功尝试的本质：当用户指出“这面墙有点浪费”时，相当于提供了一个新的“注意力锚点”。AI 顺着这个锚点，激活了“功能置换”的知识网络（衣柜移走 → 原区域解放 → 置换为高价值梳妆区），从而实现了设计跃升。

**2. 提示词重构策略：从“机械执行”到“原理与评估”**

我们不能通过“增加一条规则：如果有又长又空的墙，就考虑把衣柜放过去”来解决问题，这是标准的“反模式：面面俱到”，会污染整个规则库。

根据《提示词设计哲学》的“三层论”和“三级约束模型”，我们需要做的是**注入原理、释放留白、增加评估维度**。

**改造一：升级《设计指南》的评估维度（认知校准）**
**修改目标：`placement_guide.md`**
我们需要在通用规则部分，引入**“空间释放与功能置换（Space Liberation & Function Replacement）”**的**设计原理（WHY）**，以及对应的**设计品质评估维度**。
- **引入概念：** 明确告诉 AI，有时候打破“优先推荐”的局部规则（如放弃完美的 L 型盲角），集中收纳于具有大片连续面积的墙面，能够彻底“释放”这片异形区，使其升级为更高阶的独立功能区（如专属梳妆间/书房）。
- **新增评估指标：** 在现有的几何合规性检查之上，增加“空间潜力挖掘度”和“高阶功能满足度”等品质评判标准，让 AI 知道什么是“好”。

**改造二：重构 Generate 工作流的核心节点（信息架构）**
**修改目标：`generate-workflow/SKILL.md` 的步骤 6（布局骨架规划）**
真正的设计创意发生在“落子”之前。如果骨架平庸，后续再怎么反思也无济于事。
- **改单线为多重假设：** 在步骤 6（生成骨架）时，要求 AI 不要只输出一个“合规骨架”。对于空间宽裕、潜力大的房间，必须生成 **[防守型合规骨架]**（严格按规则优先级的常规方案）和 **[进攻型突破骨架]**（基于“空间释放”原理的大胆置换方案）。
- **在骨架阶段进行质检：** 在这两个骨架之间，使用新增的品质评估维度进行心智对比（Trade-off Analysis）。

**改造三：精准引入 AskUserQuestion（留白与交互）**
**使用场景：决策权交接**
如《提示词设计哲学》所言，留白是为了让 AI 和用户共同发挥判断力。`AskUserQuestion` 的引入绝不应该是在“放错家具”后，而应该在“定骨架”的十字路口。
- **触发条件：** 当 AI 在步骤 6 对比发现，[进攻型突破骨架] 的空间品质得分远胜于 [防守型合规骨架]，但实现它必须**偏离哪怕一条【建议】级别的软指导（如放弃优先L形，或调整默认间距）**时。
- **执行方式：** 截断工作流。AI 使用 `AskUserQuestion` 向用户展示两个骨架的意图、优缺点对比（A：原方案稳妥 vs B：置换方案带来奢华感）。
- **Web 端架构需求：** 这需要底层支持让 Agent 在此时进入 **Suspend（挂起/待机）** 状态，由 Server 向 Web 推送弹窗，用户点击选项后，将选择（Wakeup Callback）传回 Agent，Agent 再进入具体的“阶段 A”落子。

**3. 独特见解与深度补充**

除了上述基于核心哲学的重构方向外，我认为要让这种“自我反思”和“突破性设计”真正在系统中生效，还需要补充两层极具实战意义的考量（不依靠其他专家观点，独立生成的推论）：

- **推敲发生的时机：决策越早上浮，试错成本越低**
  为什么要把核心的反思和对比前置到“步骤 6 布局骨架”阶段？因为此时没有任何家具坐标被精确计入，只有纯语义层面的意图对抗（Semantic Intent Confrontation）。如果在生成完整方案甚至通过了 `validate_layout` 之后再去反思，高昂的沉没成本（过长的上下文、密集的 Token 开销和时间成本）会隐性地“阻止”原本能够发生的设计升华。骨架阶段是思维岔路最多的时刻，在这里分叉并且拦截确认，才是最高效的。

- **反思系统边界：AskUserQuestion 也是某种“系统的终极留白”**
  我们在优化系统时不必去遍历编写“在条件 X 和 Y 满足时什么方案绝对更好”的规则。相反，当 AI 侦测到存在偏离常规但具备长远收益的选项时，直接刹车，把决策权和审美权通过 `AskUserQuestion` 返还给用户——这个过程完美契合了“三级约束模型”中定义的最上层的自由区域。这种交互体验不但能让 Agent 从“固执的干活人”升格为“可协同沟通的专家顾问”，也是当前架构获得不可替代体验溢价的最优路径。

### 专家：Codex（工作流与系统落地专家）

- **核心观点**：本次应按“方法论层 + 流程层”一次性重构，而不是继续做规则补丁。目标不是让 Agent 更会“解释当前方案”，而是让 Agent 在默认流程里具备“主动提出更优方案、在关键分歧处阻塞并与用户共决策、最终可追溯地落盘”的能力。

- **问题定性（为什么必须做大改）**：

  这次主卧案例不是参数偏差，也不是单条规则冲突，而是典型的“首个合规解锁死”问题：流程给了 Agent 合规闭环（Read -> 生成 -> validate），却没有给“继续质疑首解”的制度化时机。结果是：

  1. AI 在用户触发前倾向于局部最优（符合规则但缺设计跃迁）
  2. AI 对“重大布局分歧”只做口头解释，不触发决策闸门
  3. 最终报告强调“通过验证”，但缺少“为何这是最优”的可审计证据

- **设计原则（Codex 版本）**：

  1. **先流程后规则**：先定义“何时必须反思/何时必须问用户”，再谈具体房型规则。

  - 新增硬约束：命中重大决策触发器时必须调用 `AskUserQuestion`，并暂停后续写入。
  - 定义重大决策触发器（最小集合）：

  - 在步骤 6 后插入**全局反思阶段**（阻塞步骤），要求 Agent 输出：
    - 当前骨架的关键收益
    - 至少一次反例推演（替代骨架）
    - 是否触发重大决策闸门的判定

    - 若命中重大决策触发器：必须先 `AskUserQuestion`
    - 用户未选择前：禁止 Write
  - 升级 8A/8B 检查清单，把“是否存在明显更优全局方案”从参考项升为可阻塞项。

  - 在全局规划原则中补入“二次设计原则”：首个可行解不是终局，必须做一次全局复评。
  - 增加“留白价值 vs 功能价值”的比较框架，避免“看起来高级但本质浪费”。

  - 强化“优秀方案 = 合规 + 空间潜力释放 + 功能联动”的判断口径。

- **功能代码改进需求（本轮不实现，仅提出）**：

  1. **权限层**：解除 `AskUserQuestion` 禁用，主控与 layout-agent 均可用。
  2. **Agent-Server 协议层**：新增“提问事件 -> 用户选择回传 -> 流程恢复”的闭环状态机。
  3. **Web 交互层**：新增决策卡片（方案 A/B + 取舍说明 + 阻塞态），并记录选择日志。
  4. **审计层**：对每次重大决策记录 `trigger -> options -> user_choice -> final_apply`，可回放。

- **验收标准（建议）**：

  1. **主动性验收**：在不追加提示的主卧生成中，Agent 能主动提出“南墙衣柜 + 西侧功能重构”类替代。

  4. **安全回归验收**：`validate_layout` 及几何硬约束流程不退化。

- **结论**：

  这次改动的关键不是“再教 Agent 一条衣柜规则”，而是把“主动反思 + 用户共决策 + 审计闭环”升级为 generate 工作流的默认基础设施。只有这样，系统才会稳定地产生“可用”与“有设计感”同时成立的结果。
