# 思考强度动态配置调研报告

> **调研日期**：2026-01-20
> **调研目的**：了解 Claude Agent SDK 中思考强度（max_thinking_tokens）的配置方式，评估 Web 端动态切换的可行性

---

## 一、背景

### 1.1 问题描述

BIMCanvas 项目需要在 Web 端支持用户动态切换 AI 的"思考强度"（off/low/medium/high），以平衡响应速度和推理深度。

### 1.2 当前状态

- **master 分支（3732ebc）**：不支持 Web 端动态切换，只能通过配置文件设置初始值
- **rollback/test 分支**：实现了动态切换，但使用了非公开 API

---

## 二、已知关联问题：连续对话失败

> **关联报告**：`reports/连续对话失败问题调查报告_v2.md`

### 2.1 问题描述

启用 thinking 功能（`max_thinking_tokens > 0`）后，**连续对话会失败**：

```
API Error: 400 messages.1.content.0: Invalid `signature` in `thinking` block
```

### 2.2 根因

**Claude Agent SDK 在多轮对话中，把带有 signature 的 thinking blocks 原封不动地放入历史消息中，导致 API 校验失败。**

- `signature` 是一次性验证令牌，只能用于当前请求
- SDK 不应该把 thinking blocks 放入后续请求的 messages 中
- 这是 **SDK 的行为问题**，不是 BIMCanvas 代码的问题

### 2.3 影响

| 场景 | thinking 启用 | thinking 禁用 |
|------|--------------|--------------|
| 单轮对话 | ✅ 正常 | ✅ 正常 |
| **连续对话** | ❌ 失败 | ✅ 正常 |

### 2.4 临时方案

禁用 thinking 功能：
```python
max_thinking_tokens = None  # 禁用 thinking
```

### 2.5 与动态配置的关系

**这意味着当前 thinking 功能本身存在 Bug**：
1. 即使不考虑"动态切换"，只要启用 thinking 就会有连续对话问题
2. 在 SDK 修复此 Bug 之前，thinking 功能实际上是**不可用**状态
3. 动态切换功能的优先级应该低于"修复连续对话问题"

## 三、思考强度配置方式

### 2.1 配置文件位置

```
~/.bimcanvas/config.json
```

### 2.2 配置格式

```json
{
  "thinking": {
    "enabled": true,
    "defaultLevel": "medium",
    "budget": {
      "off": null,
      "low": 5000,
      "medium": 10000,
      "high": 20000
    }
  }
}
```

### 2.3 等级与 Token 数量对应

| 等级 | Token 数量 | 说明 |
|------|-----------|------|
| off | null | 禁用思考 |
| low | 5000 | 快速响应 |
| medium | 10000 | 平衡（默认） |
| high | 20000 | 深度推理 |

### 3.1 TypeScript SDK vs Python SDK

| 初始化 `maxThinkingTokens` | ✅ 支持 | ✅ 支持 |
| **运行时 `setMaxThinkingTokens()`** | ✅ 支持 | ❌ 不支持 |
| 运行时 `setModel()` | ✅ 支持 | ✅ 支持 |

## 四、rollback/test 分支实现分析

### 4.1 实现方式

**文件**：`BIMCanvas.Agent/src/agent/main_agent.py`

```python
async def set_thinking_level(self, level: str) -> bool:
    """动态调整思考强度（不断开连接）"""
    settings = get_settings()
    tokens = settings.thinking.get_tokens(level)

    # 通过底层 Query 发送控制消息（非公开 API）
    await self._client._query._send_control_request({
        "subtype": "set_max_thinking_tokens",
        "max_thinking_tokens": tokens
    })
    self._current_thinking_level = level
    return True
```

### 4.2 调用链

```
Web 前端
    ↓ POST /chat/stream { thinkingLevel: "high" }
HTTP Server (http_server.py)
    ↓ agent.chat_stream(message, thinking_level=thinking_level)
MainAgent.chat_stream()
    ↓ 检测 level 变化
    ↓ await self.set_thinking_level(thinking_level)
SDK 内部协议
    ↓ _client._query._send_control_request(...)
Claude Code CLI
    ↓ 处理控制消息（假设支持）
```

### 4.3 问题分析

| 问题 | 说明 |
|------|------|
| **使用私有 API** | `_client._query._send_control_request()` 以 `_` 开头，非公开接口 |
| **控制类型未定义** | Python SDK 的 `SDKControlRequest` 类型中不包含 `set_max_thinking_tokens` |
| **依赖 CLI 支持** | 假设底层 Claude Code CLI 处理此消息，但 SDK 层面未暴露 |
| **升级风险** | SDK 版本更新可能导致此方法失效，且无升级警告 |

## 五、master 分支当前实现

### 5.1 代码位置

**文件**：`BIMCanvas.Agent/src/agent/main_agent.py` (第 571-573 行)

```python
async def chat_stream(self, user_message: str, thinking_level: str = None):
    if not self._connected:
        await self.connect(thinking_level)
    # 注意：思考强度仅在 connect() 时配置，不支持动态调整
    # 如需不同思考强度，需要断开后重新 connect(thinking_level=xxx)
```

### 5.2 配置加载

**文件**：`BIMCanvas.Agent/src/config/settings.py`

```python
@dataclass
class ThinkingConfig:
    enabled: bool = True
    default_level: str = "medium"
    budget: dict[str, int | None] = field(default_factory=lambda: {
        "off": None,
        "low": 5000,
        "medium": 10000,
        "high": 20000
    })

    def get_tokens(self, level: str = None) -> int | None:
        if not self.enabled:
            return None
        level = level or self.default_level
        if level == "off":
            return None
        return self.budget.get(level, self.budget.get("medium"))
```

## 六、可选方案对比

| 方案 | 实现方式 | 优点 | 缺点 |
|------|---------|------|------|
| **A. 配置文件** | 修改 `~/.bimcanvas/config.json` | 稳定，官方支持 | 需要重启 Agent 生效 |
| **B. 非公开 API** | `_send_control_request()` | 无需重连，体验好 | 依赖私有 API，可能随时失效 |

| **D. 等待官方支持** | 等 Python SDK 添加公开方法 | 最稳定 | 不确定时间 |

## 八、结论与建议

### 8.1 现状总结

1. **TypeScript SDK 支持运行时调整思考强度**，Python SDK 不支持
2. **rollback/test 分支的实现**使用了非公开 API，存在升级风险
3. **master 分支**只支持初始化时配置，Web 端无法动态切换

### 8.2 建议

**短期方案**：
- 如果 Web 端动态切换是必需功能，可以采用 rollback/test 分支的实现方式
- 但需要做好 SDK 升级后可能失效的准备，并在代码中添加降级逻辑

**长期方案**：
- 关注 Anthropic 官方 Python SDK 更新，等待添加 `set_max_thinking_tokens()` 公开方法
- 或向 Anthropic 提交功能请求
