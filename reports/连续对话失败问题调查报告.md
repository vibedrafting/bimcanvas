# BIMCanvas 连续对话失败问题调查报告

> 日期：2026-01-19
> 状态：调查中
> 报告人：Claude Agent

## 一、问题现象

### 1.1 错误信息

```
API Error: 400 messages.1.content.0: Invalid `signature` in `thinking` block
```

### 1.2 复现步骤

1. 启动 BIMCanvas Agent 服务
2. 通过前端发送第一条消息（如"你好"）→ **成功**
3. 发送第二条消息（如"你是谁"）→ **失败**，触发上述错误

### 1.3 问题特征

- 首次对话正常
- 第二次及后续对话失败
- 错误与 `thinking` 块的 `signature` 验证相关

### 1.4 用户关键反馈

> "最近这个不能连续对话的报错，是在**引入新的线程后**才出现的，我认为和之前 `max_thinking_tokens` 参数的设置**无关**。"

关联 Commit：`2d79fd5 功能：Agent端多窗口并行开发支持`

## 二、调查过程与尝试

### 2.1 尝试一：调整 max_thinking_tokens 参数

**假设**：thinking 功能配置问题导致 signature 验证失败

**尝试内容**：
- 检查 `max_thinking_tokens` 参数设置
- 尝试禁用 thinking 功能

**结果**：用户反馈此方案无效，问题在引入多窗口支持后才出现

### 2.2 尝试二：分析代码架构变更

**调查范围**：`2d79fd5` commit 引入的变更

**发现**：
```python
# http_server.py
agents: dict[str, MainAgent] = {}  # 按 windowId 缓存 Agent

async def get_agent(window_id, ...) -> MainAgent:
    if window_id not in agents:
        agent = MainAgent(...)
        await agent.connect()  # 在 HTTP 请求 1 的异步上下文中连接
        agents[window_id] = agent
    return agents[window_id]  # 在 HTTP 请求 2 的异步上下文中复用
```

**问题点**：跨 HTTP 请求复用同一个 Agent 实例

详见下文"官方资料信息"部分。

## 三、官方资料信息

### 3.1 SDK 异步上下文限制（关键发现）

**出处**：`docs/agent_sdk/claude_agent_sdk/client.py` 第 46-52 行

```python
"""
Caveat: As of v0.0.20, you cannot use a ClaudeSDKClient instance across
different async runtime contexts (e.g., different trio nurseries or asyncio
task groups). The client internally maintains a persistent anyio task group
for reading messages that remains active from connect() until disconnect().
This means you must complete all operations with the client within the same
async context where it was connected.
"""
```

**翻译**：
- ClaudeSDKClient **不能**跨不同的异步运行时上下文使用
- 客户端内部维护一个持久的 anyio 任务组用于读取消息
- **必须**在连接时的同一个异步上下文中完成所有操作

### 3.2 官方推荐的多轮对话模式

**出处**：`docs/agent_sdk/docs/examples/streaming_mode.py`

```python
async def example_multi_turn_conversation():
    # 所有操作在同一个 async with 块中
    async with ClaudeSDKClient() as client:
        # 第一轮对话
        await client.query("What's the capital of France?")
        async for msg in client.receive_response():
            pass

        # 第二轮对话 - 同一个异步上下文 ✅
        await client.query("What's the population?")
        async for msg in client.receive_response():
            pass
```

### 3.3 Session Management 机制

**出处**：`docs/agent_sdk/docs/Guides/Session Management.md`

**关键信息**：
1. SDK 会在初始 system message 中返回 session_id
2. 可以使用 `resume` 参数恢复之前的会话
3. 跨请求时应使用新客户端 + session_id resume

**获取 session_id 的方法**：
```python
async for message in query(prompt="...", options=...):
    if hasattr(message, 'subtype') and message.subtype == 'init':
        session_id = message.data.get('session_id')
```

**恢复会话的方法**：
```python
async for message in query(
    prompt="Continue",
    options=ClaudeAgentOptions(resume=session_id)
):
    pass
```

### 3.4 ClaudeAgentOptions 结构

**出处**：`docs/agent_sdk/claude_agent_sdk/types.py` 第 616-680 行

```python
@dataclass
class ClaudeAgentOptions:
    # ... 其他字段 ...
    resume: str | None = None  # 第 625 行
    # ... 其他字段 ...
```

确认 `resume` 字段存在且类型为 `str | None`。

## 四、问题根因分析

### 4.1 问题链路图

```
HTTP 请求 1 (asyncio Task A)
  → get_agent() 创建 Agent
  → agent.connect() 在 Task A 的上下文中启动
  → ClaudeSDKClient 的 anyio 任务组绑定到 Task A
  → 成功 ✅

HTTP 请求 2 (asyncio Task B)
  → get_agent() 返回缓存的 Agent
  → agent.chat_stream() 在 Task B 的上下文中调用
  → 尝试使用 Task A 上下文中的客户端
  → 违反 SDK 异步上下文限制
  → 失败 ❌ (Invalid signature 错误)
```

### 4.2 根因总结

**直接原因**：跨异步上下文复用 `ClaudeSDKClient` 违反了 SDK 限制

**触发条件**：
1. `http_server.py` 按 windowId 缓存 Agent 实例
2. 不同 HTTP 请求运行在不同的 asyncio 任务中
3. SDK 明确禁止跨异步上下文使用客户端

**为什么表现为 thinking signature 错误**：
- thinking block 的 signature 验证依赖客户端内部状态
- 跨上下文访问导致状态不一致，signature 验证失败

### 4.3 之前分析的误区

之前认为是 `max_thinking_tokens` 导致的问题，实际上：
- Thinking 功能本身没有问题
- 问题在于**跨请求复用客户端**
- 用户反馈"引入新线程后出现"是正确的线索

## 五、可能的修复方向

> **注意**：以下仅为技术分析，用户尚未同意实施任何方案

### 方向 A：每次请求重连 + Session Resume

- 每次 HTTP 请求都重新创建 ClaudeSDKClient
- 使用 SDK 的 `resume` 选项恢复之前的会话
- 保存每次会话的 session_id

**优点**：
- 保留对话历史
- 保留 Thinking 功能
- 符合 SDK 官方使用模式

**缺点**：
- 每次请求需要重连（可能有延迟）
- 需要管理 session_id

### 方向 B：禁用 Thinking 功能

- 设置 `max_thinking_tokens = None`
- 绕过 signature 验证问题

**优点**：
- 实现简单

**缺点**：
- 失去 thinking 功能
- 可能只是掩盖问题而非解决

### 方向 C：重新设计 Agent 缓存策略

- 不再跨请求缓存 Agent 实例
- 或改为在同一异步上下文内处理所有请求

**优点**：
- 从根本上解决问题

**缺点**：
- 架构改动较大
- 可能影响多窗口并行功能
