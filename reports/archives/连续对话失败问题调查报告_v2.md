## 一、问题现象

### 1.1 错误信息

```
API Error: 400 messages.1.content.0: Invalid `signature` in `thinking` block
```

### 1.2 复现步骤

1. 启动 BIMCanvas Agent 服务
2. 通过前端发送第一条消息（如"你好"）→ **成功**
3. 发送第二条消息（如"你是谁"）→ **失败**，触发上述错误

### 1.3 问题特征

| 特征 | 描述 |
|------|------|
| 首次对话 | 正常 |
| 第二次及后续对话 | 失败 |
| 错误类型 | `thinking` 块的 `signature` 验证失败 |
| 触发条件 | 启用 thinking 功能（`max_thinking_tokens > 0`） |

### 1.4 用户关键反馈

> "最近这个不能连续对话的报错，是在**引入新的线程后**才出现的。"

关联 Commit：`2d79fd5 功能：Agent端多窗口并行开发支持`

## 二、调查过程与尝试

### 2.1 第一阶段：初步假设与排查

#### 假设 1：max_thinking_tokens 参数配置问题

**调查内容**：
- 检查 `max_thinking_tokens` 参数是否正确设置
- 对比官方文档的推荐配置

**结论**：参数配置本身没有问题，用户反馈此问题在引入多窗口支持后才出现

#### 假设 2：多窗口支持引入的异步上下文问题

**调查内容**：
- 分析 `2d79fd5` commit 的代码变更
- 查阅 SDK 文档关于异步上下文限制的说明

**发现**：
```python
# http_server.py
agents: dict[str, MainAgent] = {}  # 按 windowId 缓存 Agent

async def get_agent(window_id, ...) -> MainAgent:
    if window_id not in agents:
        agent = MainAgent(...)
        await agent.connect()  # 在 HTTP 请求 1 的异步上下文中连接
        agents[window_id] = agent
    return agents[window_id]  # 在 HTTP 请求 2 的异步上下文中复用
```

**SDK 文档警告**（`docs/agent_sdk/claude_agent_sdk/client.py:46-52`）：
> "As of v0.0.20, you cannot use a ClaudeSDKClient instance across different async runtime contexts."

**结论**：虽然存在跨异步上下文复用的问题，但这不是导致 `Invalid signature` 错误的直接原因。

### 2.2 第二阶段：回档验证

**操作**：将代码回滚到多窗口支持引入之前的版本

**结果**：**问题依然存在**

**结论**：多窗口支持的代码变更不是根因，问题存在于更底层

### 2.3 第三阶段：API 请求日志分析（关键突破）

**方法**：在代码中添加日志，记录发送到 Anthropic API 的完整请求内容

**发现**：通过对比两次请求的日志，找到了问题的确凿证据。

**说明**：

- thinking 配置正常
- 请求成功，返回包含 thinking block 的响应

### 3.2 第一次响应（成功）

```json
{
  "role": "assistant",
  "content": [
    {
      "type": "thinking",

      "type": "text",

    }
  ]

```

**说明**：
- 响应包含 `thinking` block，带有 `signature` 字段
- `signature` 是一次性的验证令牌，用于验证 thinking 内容的完整性

### 3.3 第二次请求（失败）

```json
{
  "model": "claude-sonnet-4-20250514",
  "max_tokens": 8096,
  "messages": [
    {
      "role": "user",
      "content": "你好"
    },
    {
      "role": "assistant",
      "content": [
        {
          "type": "thinking",
          "thinking": "用户说\"你好\"，这是一个常见的中文问候语...",
          "signature": "EoAGCkgICxACGAIqQLtyQBoVD7CCXW4/X0zt3aXXuFnkMi0VbYCZJcF5wiydARlqa5wWA..."
        },
        {
          "type": "text",
          "text": "您好，我是 BIMCanvas 助手..."
        }
      ]
    },
    {
      "role": "user",
      "content": "你是谁"
    }
  ],
  "thinking": {
    "budget_tokens": 10000,
    "type": "enabled"
  }
}
```

**问题所在**：
- SDK 把上一轮的完整响应（包括 thinking block 和 signature）放入了历史消息
- `messages[1].content[0]` 是一个带有 `signature` 的 `thinking` block
- API 尝试验证这个 `signature`，但由于它是为上一个请求生成的，验证失败

### 3.4 错误响应

```json
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "messages.1.content.0: Invalid `signature` in `thinking` block"
  }
}
```

## 四、根因分析

### 4.1 根因确认

**Claude Agent SDK（或其底层 CLI）在构建多轮对话请求时，把之前响应中的 thinking block（包含 signature）原封不动地放入了历史消息中。**

### 4.2 技术背景

Anthropic API 的 thinking block signature 具有以下特性：

| 特性 | 说明 |
|------|------|
| **一次性** | 每次响应生成唯一的 signature |
| **请求绑定** | 不能在后续请求中复用 |
| **验证用途** | API 会校验 signature 的有效性 |

当 SDK 把带有旧 signature 的 thinking block 放入新请求的 messages 时：
1. API 接收到包含 signature 的 thinking block
2. API 尝试验证该 signature
3. 验证失败（因为 signature 是为上一个请求生成的）
4. 返回 400 错误：`Invalid signature in thinking block`

### 4.3 问题归属

**这是 Claude Agent SDK（或其底层 CLI）的行为问题，不是 BIMCanvas 代码的问题。**

SDK 在维护对话历史时，不应该把带有 signature 的 thinking blocks 放入后续请求的 messages 中。

### 4.4 正确的处理方式（SDK 应该做的）

SDK 在构建历史消息时应该：
1. **方案 A**：只保留 `text` blocks 作为历史，过滤掉 `thinking` blocks
2. **方案 B**：移除 thinking blocks 中的 `signature` 字段后再放入历史
3. **方案 C**：使用其他机制管理多轮对话（如 session resume）

### 4.5 之前分析的误区

| 之前的假设 | 实际情况 |
|-----------|---------|
| 多窗口支持引入的问题 | ❌ 回档后问题依然存在 |
| 异步上下文限制 | ❌ 与 signature 错误无直接关联 |
| set_model() 重复调用 | ❌ 与此无关 |
| max_thinking_tokens 配置问题 | ❌ 配置本身没问题 |
| **SDK 把 thinking blocks 放入历史消息** | ✅ **确认为根因** |

## 八、总结

### 根因（已确认）

**Claude Agent SDK 在多轮对话中把带有 signature 的 thinking blocks 复用到后续请求中，导致 API 校验失败。**

这是 SDK 的行为问题，不是 BIMCanvas 代码的问题。

### 临时解决方案

禁用 thinking 功能（`max_thinking_tokens=None`）可以立即解决连续对话问题，但会失去思考能力。

### 长期解决方案

1. 向 Anthropic 报告此 SDK bug
2. 等待官方修复，或
3. 研究 SDK 是否提供消息历史的自定义处理机制
