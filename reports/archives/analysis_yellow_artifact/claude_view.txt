  ---
  黄色边界框（Yellow Bounds Artifact）问题深度分析报告

  1. 问题确认

  从截图 ai_vision_after_load_1765955305136.png 中可以清晰看到：
  - 位置：场景左下角（坐标原点附近）有一组独立的黄色边界框
  - 形态：多个嵌套的 3D 矩形框，与场景中其他元素（墙体、柱子、模块）的正常边界框明显分离
  - 预期：所有 BoxHelper 应该紧密包围其对应的几何体，不应出现在原点附近的孤立框

  ---
  2. 根本原因分析

  经过深度代码分析，问题根源在于 SceneBuilder.ts 的 setLayers() 方法调用时序与 Three.js Group 嵌套结构的冲突。

  2.1 核心问题：BoxHelper 创建时机错误

  代码位置: SceneBuilder.ts:182-190

  private setLayers(object: THREE.Object3D) {
      object.layers.enable(LayerManager.LAYER_MODEL);
      const boxHelper = new THREE.BoxHelper(object, 0xffff00);
      boxHelper.layers.set(LayerManager.LAYER_BOUNDS);
      this.scene.add(boxHelper);  // BoxHelper 被添加到 scene 根节点
  }

  问题：setLayers() 在对象被添加到父 Group 之前就被调用，导致 THREE.BoxHelper 基于错误的世界坐标矩阵计算边界。

  2.2 门组件的典型错误流程

  代码位置: SceneBuilder.ts:260-335 (createDoor 方法)

  private createDoor(center: THREE.Vector2, width: number, height: number, angle: number) {
      const root = new THREE.Group();
      root.rotation.x = -Math.PI / 2;
      this.scene.add(root);

      const frameGroup = new THREE.Group();
      frameGroup.position.set(center.x, center.y, 0);  // Group 设置位置
      frameGroup.rotation.z = angle;

      const topFrame = new THREE.Mesh(topGeo, frameMat);
      topFrame.position.set(0, 0, height);  // 局部坐标
      this.setLayers(topFrame);  // ⚠️ 问题点：此时 topFrame 还没有 parent
      frameGroup.add(topFrame);  // 之后才添加到 frameGroup
      // ...
  }

  执行时序问题：

  | 步骤 | 操作                                      | topFrame 的 parent | matrixWorld 状态         |
  |------|-------------------------------------------|--------------------|--------------------------|
  | 1    | topFrame.position.set(0, 0, height)       | null               | 仅包含局部位置           |
  | 2    | this.setLayers(topFrame) → 创建 BoxHelper | null               | ❌ 基于局部坐标计算边界  |
  | 3    | frameGroup.add(topFrame)                  | frameGroup         | 应包含 frameGroup 的变换 |
  | 4    | root.add(frameGroup)                      | root → scene       | 完整的世界变换           |

  2.3 最严重的问题：门的 Swing Arc（弧线）

  代码位置: SceneBuilder.ts:312-330

  const curve = new THREE.EllipseCurve(
      -width / 2, 0,     // 中心点：(-width/2, 0)
      width, width,       // 半径
      0, swingAngle,
      false, 0
  );
  const points = curve.getPoints(32);
  const geometry = new THREE.BufferGeometry().setFromPoints(points);
  const arc = new THREE.Line(geometry, this.materials.get('swingArc'));
  arc.position.set(0, 0, 20);
  this.setLayers(arc);    // ⚠️ BoxHelper 创建在原点附近
  panelGroup.add(arc);    // arc 之后才添加到 panelGroup

  计算分析（以 layout_proposal.json 中的门 d001 为例）：

  - 门宽度: width ≈ 750mm
  - EllipseCurve 中心: (-375, 0)
  - 弧线点范围: X: [-375-750, -375+750] = [-1125, 375], Y: [0, 750]

  当 setLayers(arc) 被调用时：
  1. arc 没有 parent（parent === null）
  2. arc.matrixWorld 是 identity matrix
  3. BoxHelper 计算出的边界: 约 (-1125, 375) × (0, 750) × (20, 20)
  4. 这个 BoxHelper 被添加到 scene 根节点，位置正好在原点附近！

  4. 为什么 clearScene() 没有解决问题

  代码位置: SceneBuilder.ts:85-118

  public clearScene() {
      const toRemove: THREE.Object3D[] = [];
      this.scene.traverse((child) => {
          // ...
          if (child instanceof THREE.LineSegments || child.type === 'BoxHelper') {
              toRemove.push(child);
          }
      });
      toRemove.forEach(child => {
          this.scene.remove(child);  // 只对 scene 直接子对象有效
      });
  }

  clearScene 本身逻辑正确，但问题不在于清理，而在于：

  1. clearScene 确实删除了所有 BoxHelper（BoxHelper 是 scene 的直接子对象）
  2. 但紧接着 buildFromDocument 又创建了新的错误定位的 BoxHelper
  3. 每次加载文档都会重新创建同样的问题

  6. 截图中异常框的来源分析

  从截图中左下角的黄色框群分析：
  - 最可能来源：门的 swing arc（弧线） 的 BoxHelper
  - 原因：arc 的几何体点集范围是 (-1125, 375) × (0, 750)，BoxHelper 包围这个范围
  - 表现：多个嵌套的黄色框，因为门的多个组件（arc、panel、frames）的 BoxHelper 都在原点附近

  7. 潜在解决方向（仅供参考）

  方案 A：延迟创建 BoxHelper

  在所有 Group 结构完成后，遍历场景为每个需要边界框的对象创建 BoxHelper：

  // 在 buildFromDocument 末尾调用
  private createBoundHelpers() {
      this.scene.traverse((child) => {
          if (child instanceof THREE.Mesh || child instanceof THREE.Line) {
              child.updateMatrixWorld(true);  // 强制更新世界矩阵
              const boxHelper = new THREE.BoxHelper(child, 0xffff00);
              boxHelper.layers.set(LayerManager.LAYER_BOUNDS);
              this.scene.add(boxHelper);
          }
      });
  }

  方案 B：使用 BoxHelper 的 update 机制

  创建 BoxHelper 后存储引用，在渲染循环中更新：

  private boxHelpers: THREE.BoxHelper[] = [];

  // 在 animate 中
  this.boxHelpers.forEach(helper => helper.update());

  方案 C：将 BoxHelper 作为子对象添加

  将 BoxHelper 添加到目标对象的父级，而非 scene 根节点：

  private setLayers(object: THREE.Object3D) {
      object.layers.enable(LayerManager.LAYER_MODEL);
      const boxHelper = new THREE.BoxHelper(object, 0xffff00);
      boxHelper.layers.set(LayerManager.LAYER_BOUNDS);
      object.add(boxHelper);  // 添加为对象的子对象
  }
