# claude-agent-sdk 升级 502 问题调查报告

> **报告日期**：2026-02-26（更新）
> **报告状态**：二分法测试完成，已定位分界版本
> **当前分支**：`rollback/old-sdk`

---

## 1. 问题概述

将 `claude-agent-sdk` 从 `0.1.31` 升级到 `0.1.43` 后，通过代理网关（`127.0.0.1:8045`）调用第三方模型时，请求持续返回 **502 Upstream Error**，导致 Agent 无法正常工作。经二分法测试确认：**0.1.41 是最后可用版本，0.1.42 起 SDK 内部不再向代理网关发送 HTTP 请求**。

## 4. 已确认事实

### 4.1 版本对比结论

| 条件 | SDK 0.1.31 | SDK 0.1.43 |
|------|------------|------------|
| 同一代理网关 (`127.0.0.1:8045`) | ✅ 正常 | ❌ 502 |
| 同一模型 (`gemini-3.1-pro-low`) | ✅ 正常 | ❌ 502 |
| 同一 API Key | ✅ 正常 | ❌ 502 |

**结论**：代理网关和模型本身可用，问题与 SDK 版本直接相关。

### 4.2 SDK 0.1.31 → 0.1.43 已知差异

| 变化项 | 0.1.31 | 0.1.43 |
|--------|--------|--------|
| `ClaudeAgentOptions` 字段 | 无 `effort`、无 `thinking` | 新增 `effort`、`thinking` 字段 |
| 内置 CLI 版本 | 旧版（版本号未知） | v2.1.56 |
| 思考配置类型 | 仅 `max_thinking_tokens` (int) | `ThinkingConfigAdaptive`、`ThinkingConfigDisabled` typed dict |
| CLI 命令行标志 | 无 `--max-thinking-tokens`、无 `--effort` | 可能添加 `--max-thinking-tokens`、`--effort` |

### 4.4 二分法版本测试结果

通过逐版本安装测试，结合代理中间层请求日志验证，确定分界版本：

| SDK 版本 | 测试结果 | 代理中间层是否收到 HTTP 请求 |
|----------|----------|------------------------------|
| 0.1.31 | ✅ 正常 | ✅ 收到 |
| 0.1.36 | ✅ 正常 | ✅ 收到 |
| 0.1.38 | ✅ 正常 | ✅ 收到 |
| 0.1.40 | ✅ 正常 | ✅ 收到 |
| **0.1.41** | **✅ 正常** | **✅ 收到（最后可用版本）** |
| **0.1.42** | **❌ 失败** | **❌ 未收到** |
| 0.1.43 | ❌ 失败 | ❌ 未收到 |

### 4.5 关键发现：0.1.42 起 HTTP 请求未发出

- **验证方法**：通过代理中间层（`127.0.0.1:8045`）的请求日志确认
- **现象**：SDK 0.1.42+ 版本下，代理中间层**完全没有收到任何 HTTP 请求**
- **结论**：问题不是请求格式/参数不兼容，而是 **SDK 内部在发送 HTTP 请求之前就已失败**
- **分界点**：`0.1.41` → `0.1.42` 之间的 SDK 内部变更导致了此问题

### 4.6 SDK 0.1.43 `_build_command()` 关键代码

来自 SDK 源码中 `SubprocessCLITransport._build_command()` 方法（0.1.31 中不存在此逻辑）：

```python
# 思考配置 → --max-thinking-tokens
resolved_max_thinking_tokens = self._options.max_thinking_tokens
if self._options.thinking is not None:
    t = self._options.thinking
    if t["type"] == "adaptive":
        if resolved_max_thinking_tokens is None:
            resolved_max_thinking_tokens = 32_000
    elif t["type"] == "enabled":
        resolved_max_thinking_tokens = t["budget_tokens"]
    elif t["type"] == "disabled":
        resolved_max_thinking_tokens = 0
if resolved_max_thinking_tokens is not None:
    cmd.extend(["--max-thinking-tokens", str(resolved_max_thinking_tokens)])

# 努力程度 → --effort
if self._options.effort is not None:
    cmd.extend(["--effort", self._options.effort])
```

## 5. 已尝试的排查步骤

### 5.1 移除 `--max-thinking-tokens 0` 标志

**操作**：将 thinking 配置从 `ThinkingConfigDisabled(type="disabled")` 改为 `None`，使 CLI 不传递 `--max-thinking-tokens 0`。

**预期效果**：CLI 命令从

```
claude.exe ... --model gemini-3.1-pro-low --max-thinking-tokens 0 --effort medium ...
```

变为

```
claude.exe ... --model gemini-3.1-pro-low --effort medium ...
```

**实际结果**：❌ 仍然 502 错误。

### 5.2 回退至 SDK 0.1.31

**操作**：`pip install claude-agent-sdk==0.1.31`，代码回退至 0.1.31 兼容版本。

**实际结果**：✅ 恢复正常。

### 5.3 二分法版本测试

**操作**：逐版本安装测试，通过代理中间层请求日志验证 HTTP 请求是否发出。

**测试路径**：0.1.31 → 0.1.36 → 0.1.38 → 0.1.40 → 0.1.42（失败） → 0.1.41（成功）

**实际结果**：精确定位 0.1.42 为首个异常版本，详见 §4.4。

## 6. 待排查方向

根据二分法测试结果，排查范围已从"请求格式差异"缩小到 **SDK 0.1.41 → 0.1.42 的内部变更**：

### 6.1 SDK 内部变更（核心方向）

由于 0.1.42+ HTTP 请求根本未发出，问题出在 SDK 内部（CLI 启动流程或请求发送逻辑），而非代理网关兼容性。可能的原因：

- **内置 CLI 二进制文件更新**：0.1.42 可能更换了内置的 `claude.exe`，新版 CLI 在启动、认证或请求发送环节存在 breaking change
- **SDK Python 层变更**：`SubprocessCLITransport` 的进程管理、stdin/stdout 通信、环境变量传递等逻辑可能有变化
- **CLI 启动前置检查**：新版 CLI 可能新增了启动前的认证检查、版本校验等，在到达 HTTP 请求阶段前就失败

### ~~6.2 请求格式差异~~（已排除）

~~请求 body 中是否新增了代理网关无法识别的字段~~ → 请求根本未发出，非格式问题

### ~~6.3 代理网关兼容性~~（已排除）

~~代理网关对新版请求格式的解析能力~~ → 请求未到达代理网关，非网关问题
