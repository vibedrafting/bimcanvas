# 首页功能现状说明

> 更新时间：2026-03-26  
> 所属分支：`feature/docker-deployment`  
> 参考文档：`plans/archives/Homepage/Homepage_Server_Implementation_Plan.md`

## 1. 首页的定位

当前 BIMCanvas 的“首页”不是一个纯展示页，而是系统的主入口页，承担以下职责：

- 作为应用启动后的默认落点
- 展示本地项目列表
- 展示最近打开项目入口
- 提供 `.bcp` 导入能力
- 提供打开已有项目能力
- 提供删除项目能力
- 作为“首页内实例设置台”的承载页
- 负责从首页切入工作区

因此它更准确的定位是：

- 项目入口页
- 实例入口页
- 工作区之前的状态切换页

## 2. 当前整体结构

首页相关实现横跨前端和服务端两层。

### 2.1 前端主文件

| 文件 | 作用 |
|------|------|
| `BIMCanvas.Web/src/App.vue` | 应用启动判定：首页还是工作区 |
| `BIMCanvas.Web/src/views/HomePage.vue` | 首页主视图 |
| `BIMCanvas.Web/src/stores/appStore.ts` | 首页与工作区的全局视图状态、项目列表状态 |
| `BIMCanvas.Web/src/services/ProjectService.ts` | 首页使用的项目管理 API 封装 |
| `BIMCanvas.Web/src/types/homepage.ts` | 首页 DTO 类型定义 |
| `BIMCanvas.Web/src/composables/useProjectFile.ts` | `.bcp` 导入、冲突处理、导出逻辑 |
| `BIMCanvas.Web/src/components/UI/ConflictDialog.vue` | 导入冲突弹窗 |
| `BIMCanvas.Web/src/components/UI/HomeSettingsPanel.vue` | 首页中的实例设置页 |

### 2.2 服务端主文件

| 文件 | 作用 |
|------|------|
| `BIMCanvas.Server/Controllers/ProjectController.cs` | 首页相关项目管理 API |
| `BIMCanvas.Server/Services/ProjectService.cs` | 项目扫描、打开已有项目、删除项目 |
| `BIMCanvas.Server/Services/RecentProjectsService.cs` | 最近打开项目记录 |
| `BIMCanvas.Server/Services/ConfigService.cs` | 配置目录与 `recent_projects.json` 路径 |
| `BIMCanvas.Server/Dtos/ProjectLoadResult.cs` | 首页相关 DTO，包括 `ProjectSummary` |
| `BIMCanvas.Server/Program.cs` | 首页相关服务 DI 注册 |

## 3. 首页与工作区的切换机制

### 3.1 启动时的视图判定

应用启动时首先由：

- `BIMCanvas.Web/src/App.vue`

调用：

- `ProjectService.getStatus()` → `GET /api/project/status`

根据 Server 当前状态决定：

- 如果服务端已经有加载中的项目，直接进入工作区
- 如果没有加载中的项目，显示首页

这意味着首页并不是绝对首屏，而是“当前没有已加载项目时的首屏”。

### 3.2 前端视图状态

全局视图状态由：

- `BIMCanvas.Web/src/stores/appStore.ts`

维护，当前只有两种视图：

- `homepage`
- `workspace`

切换规则：

- 首页打开项目成功后，切到 `workspace`
- 关闭项目后，回到 `homepage`
- 导入 `.bcp` 成功后，如果数据成功载入，也会进入 `workspace`

### 3.3 进入工作区的真正触发点

`App.vue` 中通过监听：

- `appStore.currentView`

在 `homepage → workspace` 时统一执行 `enterWorkspace()`，它会负责：

- 清空旧数据
- 重新从 Server 拉取当前项目
- 执行工作区 cinematic / build sequence

所以首页本身不负责加载完整工作区数据，它只负责把入口状态切到正确位置。

## 4. 首页当前具备的功能

### 4.1 项目列表

首页主列表由：

- `HomePage.vue`
- `appStore.fetchProjectList()`

驱动。

前端会并行调用：

- `GET /api/project/list`
- `GET /api/project/recent`

然后分别填充：

- `projectList`
- `recentProjects`

列表展示内容来自 `ProjectSummary`，包括：

- 项目名
- 文件夹路径
- 创建时间
- 更新时间
- 方案数量
- 当前激活方案
- 版本
- 是否有效
- 错误信息

### 4.2 最近打开

首页有两个 Tab：

- 全部项目
- 最近打开

服务端最近记录由：

- `RecentProjectsService`

写入：

- `<BIMCANVAS_HOME>/recent_projects.json`

当前行为：

- 打开项目成功后写入最近记录
- 已不存在的项目会在读取最近记录时自动清理

### 4.3 导入 `.bcp`

首页右上角“导入 `.bcp`”按钮复用了现有导入链路：

- `BIMCanvas.Web/src/composables/useProjectFile.ts`

当前导入流程：

1. 优先使用 File System Access API 选择文件
2. 浏览器不支持时，退回隐藏的 `<input type="file">`
3. 上传到 `POST /api/project/upload`
4. 如果服务端返回冲突，弹出 `ConflictDialog`
5. 用户选择覆盖/使用已有项目后，再调用冲突解决接口
6. 成功后加载项目数据并切入工作区

### 4.4 打开已有项目

点击首页项目卡片时，会调用：

- `appStore.openProject(folderPath)`

对应服务端接口：

- `POST /api/project/open-folder`

服务端当前做的事情包括：

- 路径安全检查
- 验证项目目录存在
- 验证 `project.json` 存在
- 验证 `baseline/` 存在
- 补齐固定模板文件
- 补齐派生产物
- 必要时生成 warning
- 记录最近打开项目
- 初始化对话日志
- 清理旧 Worktree

### 4.5 删除项目

首页项目卡片右侧有删除按钮。

当前删除链路：

- 前端弹确认对话框
- 调用 `DELETE /api/project/{name}`
- 服务端删除项目目录
- 同步移除最近记录

当前安全约束：

- 不能删除当前已打开的项目
- 服务端做路径穿越检查
- 删除前会移除 Git 只读文件属性

### 4.6 首页内实例设置

首页当前还承载一个“实例设置”入口。

它的特点是：

- 入口只在首页显示
- 进入设置后首页内容切到设置面板
- 返回后恢复项目列表视图

这部分属于首页功能的一部分，但设置系统本身已经单独整理在另一份文档中：

- `reports/首页实例设置系统现状说明.md`

## 5. 服务端接口现状

首页当前主要依赖以下 API：

| 接口 | 用途 |
|------|------|
| `GET /api/project/status` | 判断当前是否已有加载中的项目 |
| `GET /api/project/list` | 扫描项目目录，返回项目摘要 |
| `GET /api/project/recent` | 返回最近打开项目 |
| `POST /api/project/open-folder` | 打开已有项目文件夹 |
| `POST /api/project/upload` | 上传 `.bcp` 并尝试导入 |
| `POST /api/project/upload-resolve` | 处理导入冲突 |
| `POST /api/project/close` | 关闭当前项目，回首页 |
| `DELETE /api/project/{name}` | 删除项目 |

当前这些接口基本已经构成首页完整工作流。

## 6. 数据与文件落点

### 6.1 项目目录

首页项目列表扫描的根目录来自：

- `ProjectService.DefaultProjectsRoot`

它最终依赖：

- `ConfigService`

当前运行时根路径规则：

- 优先使用 `BIMCANVAS_HOME`
- Windows 默认在 `Documents/BIMCanvas`
- 非 Windows 默认在用户目录下的 `.bimcanvas`

项目目录通常位于：

- `<BIMCANVAS_HOME>/Projects`

### 6.2 最近项目记录

最近项目记录文件位于：

- `<BIMCANVAS_HOME>/recent_projects.json`

由：

- `RecentProjectsService`

管理。

记录内容包括：

- 项目名
- 文件夹路径
- 最后打开时间
- 打开次数

## 7. 当前功能状态总结

### 7.1 已实现

- 启动时根据服务端状态决定显示首页还是工作区
- 首页项目列表扫描
- 最近打开记录
- `.bcp` 导入
- 导入冲突处理
- 打开已有项目
- 删除项目
- 返回首页能力
- 首页内实例设置入口

### 7.2 当前体验上已经比较稳定的部分

- 首页与工作区的二态切换已经明确
- 打开已有项目链路完整
- 导入冲突链路已接通
- 项目无效时可在列表中显示错误态，而不是直接崩掉
- 删除当前打开项目会被服务端拦截

### 7.3 当前仍然存在的边界与不足

#### 最近打开的排序语义还不够完整

前端“最近打开”Tab 当前是：

- 用 `recentProjects` 做过滤条件
- 但实际渲染顺序仍然沿用 `projectList` 的顺序

也就是说它当前更像：

- “最近打开项目子集”

而不是严格意义上的：

- “按最近打开时间排序后的列表”

#### 首页仍然偏管理入口，不是完整工作台

首页当前主要解决的是入口与管理问题，而不是内容创作问题。

它还没有：

- 搜索
- 排序
- 分组
- 收藏
- 分页
- 批量操作

#### 错误反馈形式还不统一

当前首页的错误反馈混合使用了：

- 页面内错误 banner
- `alert`
- 控制台日志

尤其导入链路里仍有一些 `alert` 风格提示，后续可以统一成更一致的 UI 反馈方式。

#### 自动化验证仍然有限

首页功能目前主要依赖：

- 构建通过
- 手工测试
- 服务端接口验证

还没有覆盖整条首页链路的前端 E2E 测试。

## 8. 与首页设置系统的边界

当前需要明确区分：

- 首页
- 首页里的设置系统

首页本身负责的是：

- 项目入口
- 项目管理
- 工作区切换
- 设置入口承载

设置系统负责的是：

- 四组实例配置的统一读取/编辑/保存/重启

所以“首页功能”和“首页设置系统”是包含关系，不是同一个概念。

## 9. 后续建议

如果继续完善首页，优先建议做这几项：

1. 让“最近打开”Tab 按 `LastOpenedAt` 真正排序，而不是只做过滤。
2. 把导入/删除/打开失败提示统一成一致的页面级反馈机制。
3. 给首页补充基本的搜索和排序能力。
4. 为首页主流程增加自动化回归测试，至少覆盖：
   - 首屏显示首页
   - 打开项目进入工作区
   - 返回首页
   - 导入冲突处理
   - 删除项目
5. 如果未来首页继续承载更多入口，需要重新梳理“项目入口页”和“实例管理页”的信息层级。

## 10. 一句话结论

当前首页已经不是一个占位页面，而是 BIMCanvas 的正式入口层：

- 它负责项目发现、项目导入、项目打开、项目删除、最近记录和进入工作区
- 并额外承载了首页内实例设置能力

从功能上看，首页主链路已经成型；从产品化角度看，它还有排序、搜索、反馈一致性和自动化验证这几块可继续补强。
