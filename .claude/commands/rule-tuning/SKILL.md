# Agent 规则调优工作流

## 执行流程（5 步）

```
1. 接收反馈 → 读取 Agent 日志（[THINK] 段落）+ 用户评价 + 截图
2. 分析链路 → 找到 Agent 误判点，追踪引用的规则条目
3. 审查规则 → 读取 3 个注入点文件，对照分类问题类型
4. 设计改动 → 最小有效改动，检查跨文件一致性
5. 实施评估 → 用户重新测试，对比关键指标
```

## 规则的 3 个注入点

| 注入点 | 源码路径 | Agent 读取时机 |
|--------|---------|---------------|
| **设计指南** | `BIMCanvas.Server/Templates/knowledge/placement_guide.md` | 前置准备（步骤2） |
| **执行工作流** | `BIMCanvas.Agent/templates/skills/generate-workflow/SKILL.md` | 每个执行步骤 |
| **家具规则** | `BIMCanvas.Server/Templates/modules/module_library.json` | 放置每件家具时 |

**修改规则时必须检查 3 个注入点的一致性，避免互相矛盾。**

## 规则问题 4 分类（按排查优先级）

| # | 类型 | 特征 | 修复策略 |
|---|------|------|---------|
| 1 | **规则冲突** | 多条规则互相矛盾（最隐蔽） | 明确优先级或删除矛盾项 |
| 2 | **语气过弱** | "可/建议"致 Agent 不执行（最常见） | "可"→"应"/"取最小值" |
| 3 | **规则歧义** | 规则存在但 Agent 解读错误 | 补充映射/注释 |
| 4 | **规则缺失** | Agent 没有找到相关指导 | 新增规则 |

## 规则修改 5 原则

1. **最小有效改动** — 不为假设场景预设规则，不新增复杂公式/阈值表
2. **跨文件一致性** — 3 个注入点同步修改，保持一致语义
3. **许可性→指令性** — "可缩减至"→"应取最小值"（Agent 更可能执行）
4. **警惕新矛盾** — 新增/修改规则后检查是否与已有规则冲突
5. **保留弹性** — 不硬编码，用"推荐 X，紧凑取 Y"的分层表述

## Agent 日志分析要点

- **`[THINK]` 段落**：Agent 推理链，找"为什么选这个值"的决策点
- **对比不同房间**：同类房间应有一致逻辑，差异点即问题点
- **追踪数值来源**：Agent 报告的间距值追溯到引用的哪条规则
- **讨论模式自述**：让 Agent 解释推理，往往精准定位根因

## 效果评估 4 维度

| 维度 | 检查方法 |
|------|---------|
| 关键指标对比 | 修改前后的具体数值（间距、位置等） |
| 决策链路引用 | Agent 是否在 [THINK] 中引用了更新后的规则 |
| 无副作用 | 其他房间/家具的布置是否正常 |
| 成本/耗时 | token 消耗和执行时间变化 |
