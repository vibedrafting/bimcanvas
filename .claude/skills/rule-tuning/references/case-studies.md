# 规则调优实战案例

## 案例 1：通道分类歧义（规则歧义型）

**现象**：rz_1 窗侧 300mm，rz_2 窗侧 250mm，同类房间不一致
**Agent 决策链路**：
- rz_1：先固定窗侧 300mm → 使用侧 = 剩余 700mm（正确）
- rz_2：先尝试窗侧 300mm → 使用侧 850mm → 认为不够 900mm 标准 → 压缩窗侧到 250mm

**根因**：Agent 把"床使用侧到衣柜"误分类为主通道（900mm），实际应为床侧通道（500mm）
**问题类型**：规则歧义 — placement_guide §4.1 "常见通行间隙"未标注适用哪个通道标准

**修复**（3 处改动，2 个文件）：
- `placement_guide.md` §4.1：通行间隙场景补充适用标准映射
  - "床使用侧到衣柜 → 按床侧通道（≥500mm），非主通道"
  - "床脚到墙面 → 按次通道（≥600mm）"
- `SKILL.md` 6A：补充常见误判提示
- `SKILL.md` 8A.2/8B.2：新增 S9 跨房间一致性检查

**效果**：两房窗侧均 300mm，一致 ✓

## 案例 2：许可性表述过弱（语气弱 + 规则冲突型）

**现象**：两房窗侧均 300mm（一致但偏大），用户认为紧凑房型应取 200mm
**Agent 决策链路**：
- 读取 §4.1 通道表 → 看到"推荐 300mm+" → 以此为目标
- §5.3 说"可缩减至窗帘预留距离" → Agent 视为可选优化，未执行
- SKILL.md 说"不应压缩窗侧间距" → 反向强化保留 300mm

**根因**：
1. "可缩减至"是许可性表述，Agent 不当作默认策略
2. 上一轮新增的"不应压缩窗侧间距"与紧凑房型策略矛盾

**问题类型**：语气过弱 + 规则冲突（复合型）

**修复**（4 处改动，3 个文件）：
- `placement_guide.md` §4.1：通道表窗侧行加注"紧凑房型取 200mm"
- `placement_guide.md` §5.3："可缩减至" → "取最小值 200mm" + 设计意图说明
- `SKILL.md` 6A：删除"不应压缩窗侧"，改为"紧凑房型窗侧取最小值 200mm"
- `module_library.json` mod_bed_001："可缩减至" → "取最小值 200mm"

**效果**：rz_1 窗侧 200mm/使用侧 800mm，rz_2 窗侧 200mm/使用侧 950mm ✓

## 案例 3：主卧布置三大错误（规则冲突 + 歧义 + 缺失复合型）

**现象**：衣柜放东墙（600mm窄通道）、床居中（浪费入口空间）、北墙 4070mm 未利用

- 规则歧义：S3"最长连续墙面"被理解为"无门无窗完整墙"；"远离床"太模糊
- 规则缺失：无"墙面有效段评估"概念

**问题类型**：规则冲突 + 规则歧义 + 规则缺失（复合型）

**修复**（12 处改动，3 个文件）：
- `placement_guide.md` §5.2：主卧改为"侧对窗户+偏窗侧 200mm"
- `placement_guide.md` §6.1：朝向表"次卧首选"→"主卧、次卧均适用"
- `SKILL.md` 新增 §5.6：衣柜墙面评估流程
- `SKILL.md` S1/S3 检查清单更新
- `module_library.json` 两个柜体："远离床"→"有效段最长的非床头墙、非窗墙"

**关键教训**："有门的墙 ≠ 不可用的墙"，需计算门后剩余段长度
**效果**：衣柜正确放北墙、床侧对窗户 ✓

## 案例 4：主卧睡眠模块紧贴窗帘 + 只有一个床头柜（规则歧义 + 冲突型）

**现象**：主卧床紧贴窗帘（窗侧仅 200mm），只有一个床头柜（北侧），空间明明宽裕（4850mm）
**Agent 决策链路**：
- 读 §5.2 → "窗侧间距取最小值 200mm" → 直接设床南边缘 y=1100
- 检查南侧床头柜 → 200mm < 450mm → 放不下 → 省略
- 引用 mod_cabinet_001 "若单侧空间不足500mm，允许省略" → 接受省略
- ❌ 未回溯调整床位置

**根因**：
1. §5.2"窗侧间距取最小值 200mm"**缺少"紧凑房型"限定词**，而 §4.1、§5.3、mod_bed_001 都有
2. Agent 优先引用 §5.2（主卧专门章节），恰好是唯一缺限定的来源
3. "使用侧留最大空间" vs "主卧优先成对布置"冲突时，Agent 选了前者

**问题类型**：规则歧义（主因）+ 规则冲突（次因）+ 规则缺失（无紧凑定义）

**修复**（5 处改动，3 个文件）：
- `placement_guide.md` §5.2 核心关系：决策顺序从"先设200mm→检查床头柜"改为"先预留床头柜空间→剩余偏向使用侧"
- `placement_guide.md` §5.2 间距分配：补充"紧凑"前置条件 + 内嵌紧凑定义（使用侧<500mm）
- `SKILL.md` §6A：同步新决策顺序，去除通用化暗示
- `module_library.json` mod_bed_001 rule[3]：同步决策顺序
- `module_library.json` mod_bed_001 rule[4]：主卧"至少一个"→"应成对"

**关键教训**：规则的适用范围限定词（如"紧凑房型"）在跨文件同步时容易丢失，§5.2 是唯一遗漏的来源却恰好是 Agent 最优先引用的
**效果**：待验证（预期：窗侧 650mm + 两个床头柜 + 使用侧 1350mm）

## 案例 5：主卧衣柜空隙 + 梳妆台位置偏差（模块库盲区 + 规则缺失型）

**现象**：
1. 衣柜仅放 2×1500mm=3000mm，北墙有效段 4070mm 留了 1070mm 空隙（理想方案填满整面墙）
2. 梳妆台放在东内墙（床脚旁），L 形延伸区短墙完全闲置（理想方案利用拐角空间）

**Agent 决策链路**：
- 衣柜：正确选择北墙（4070mm 有效段）→ 放 2×1500mm → 尝试 mod_cabinet_custom_001 填充 1070mm 空隙 → 发现 depth limits [800,1200] 不含 600mm → 放弃 → 用"顶角规则"合理化空隙
- 梳妆台：直接在主体区域寻找墙面 → 选东内墙 x=12400（"床脚旁使用方便"）→ 将延伸区视为"衣柜+过道"未评估残余空间

**根因**：
1. 模块库盲区：`mod_cabinet_custom_001.morphology.limits.depth = [800, 1200]`，默认 `size.depth = 600` 不在自身 limits 范围内——规格矛盾
2. 规则缺失：无异形空间利用策略，梳妆台 relation_rules 为空，SKILL.md 阶段 B 无空间评估步骤

**问题类型**：模块库覆盖盲区（问题 1）+ 规则缺失（问题 2）

**修复**（9 处改动，3 个文件）：
- `module_library.json` mod_cabinet_custom_001：depth limits [800,1200]→[600,1200]；relation_rules 补充"作为衣柜补充件时 depth 应与主柜体一致"
- `module_library.json` mod_vanity_custom_001：relation_rules 新增"优先利用异形空间"+"避免床脚正前方"；topology_rules 补充"前方 600mm+ 站立空间"
- `placement_guide.md` §5.2："衣柜尽量整墙"→"衣柜应填满有效段全长（标准柜体阵列+定制柜体补充）"
- `placement_guide.md` §1：新增"异形利用规则"设计原则
- `placement_guide.md` §9.2 S3：同步"填满有效段全长"
- `SKILL.md` 8A.2/8B.2 S3：增加"填满有效段全长"检查（两处）
- `SKILL.md` §6B：新增"评估可用空间"步骤（识别异形区域残余墙面）

**关键教训**：
1. 模块库的 morphology.limits 应覆盖默认 size 值，否则 Agent 会因 limits 约束放弃合理方案
2. "尽量"等许可性表述会被 Agent 用其他规则（如"顶角规则"）合理化偏差，应改为指令性"应"
3. 辅助家具的 relation_rules 不能为空——Agent 在无指引时倾向于在主体区域内就近放置，忽略异形空间

**效果**：✅ 已验证通过
- 衣柜：2×1500+1×1070=4070mm 填满北墙有效段全长（Agent [THINK] 引用 "standard array plus custom fill approach"）
- 梳妆台：放置于 L 形延伸区右墙 x=14100, y=4200-5150, 950mm 宽（Agent 显式执行"可用残余空间评估"步骤）
- 成本：$1.39 / 21 turns / 504s（与修改前持平）
- 无副作用：8 模块 0 错误，全部 H/S 检查 PASS

## 案例 6：L 形主卧衣柜选错墙面（规则歧义 + 规则缺失型）

**现象**：L 形主卧（rz_3）衣柜放在东步墙（X=12400, 3300mm），而非北墙（Y=5750, 门后有效段 4070mm）。导致床侧通道仅 600mm，理想方案北墙衣柜可释放 1200mm 通道。

**Agent 决策链路**：
- 心理分区 L 形房间为"下矩形=床区"+"上矩形=过渡区"
- 衣柜搜索范围自动收窄到床所在子区域
- 评估表仅列出东步墙（3300mm）和东上墙（1550mm），跳过北墙
- 东步墙 3300mm 在已评估范围内最长 → 选中
- Agent 事后讨论承认：如果被强制列出所有墙面，北墙 4070mm 不可能被跳过

**根因**：
1. 规则歧义：SKILL.md §5.6 "列出候选墙面" 未强制穷举，Agent 可自由裁量搜索范围
2. 规则缺失：无 L 形房间的衣柜功能分区指引，Agent 默认"衣柜应在床附近"
3. 异形利用规则仅提及"辅助家具"，暗示 Agent 跳过异形区域做衣柜评估

**问题类型**：规则歧义 + 规则缺失

**修复**（5 处改动，3 个文件）：
- `placement_guide.md` §5.2：追加"衣柜墙面选择"条——必须穷举房间边界上的每一段墙面，L 形不必与床同区
- `placement_guide.md` §1 异形利用规则：从"辅助家具"扩展为"先衣柜评估，残余给辅助家具"，适用家具新增衣柜
- `module_library.json` mod_cabinet_1500 relation_rules：插入"必须穷举房间边界上每一段墙面（含 L 形拐角、延伸区墙段）"
- `module_library.json` mod_cabinet_custom_001 relation_rules：同上
- `SKILL.md` §5.6：追加"常见误判 2"——L 形房间只评估床所在子区域的误判提醒

**关键教训**：
1. "列出候选墙面"等开放性步骤需要结构化约束（穷举 + 表格），否则 Agent 会用心理捷径缩小搜索范围
2. 异形空间规则不能只定位为"辅助家具空间"——这会隐式排除衣柜对该区域的评估
3. Agent 的"心理分区"倾向在 L 形房间中特别强——需要显式打破"衣柜必须在床附近"的默认假设

**效果**：⏳ 待验证

## 案例 7：L 形转角衣柜——从规则叠加到概念引入（概念缺失型）

**现象**：
1. 主卧衣柜放在床对面东墙（线性铺满 3475mm），床到衣柜间距仅 500mm
2. 窗帘因衣柜占据东南角被迫缩短至 2600mm（未满铺）
3. 参考布局中衣柜应为 L 形转角（北墙 + 东墙上部）

**Agent 决策链路**：
- §7.4 穷举墙段 → 排除窗墙和床头墙 → 计算有效段
- 东墙 3475mm >> 北墙 1720mm → 选东墙（"有效段最长"）
- 从未讨论过 L 形转角布局的可能性 → 概念盲区

**初版调优方案（规则叠加反面教材）**：
- "§7.4 新增规则：避免床对面墙"
- "窗帘角部偏移 200mm"
- ❌ 治标不治本——Agent 仍不知道 L 形转角是什么

**正确方案（概念引入）**：
- §7.4 重构为"布局模式选择"——引入 L 形转角衣柜设计概念
- 含设计理念 WHY：功能分区、动线优化、储纳增量、空间释放
- §1 新增前瞻协调原则（系统性解决跨阶段协调缺失）

**问题类型**：概念缺失（type 0）

**修复**（6 处改动，3 个文件）：
- `placement_guide.md` §7.4：整节重构为"布局模式选择 + 墙面分配"，含 L 形转角设计概念（WHY）+ 线性回退方案
- `placement_guide.md` §1：新增"前瞻协调规则"设计原则
- `SKILL.md` 6A 预检：第 4 项改为"布局模式评估"，新增第 5 项"前瞻协调"
- `SKILL.md` 8A.2 S3：泛化为支持双模式
- `module_library.json` mod_cabinet_1500：relation_rules 引用 L 形转角概念

**关键教训**：
1. Agent 说"我缺少 XX 规则"时，追问：是缺规则还是缺设计概念？

**效果**：⚠️ 部分生效——Agent 确实评估了 L 形（概念引入成功），但受"入口附近"限制仅检查 NE 角，回退线性后仍选东墙（见案例 8）

## 案例 8：L 形转角衣柜 NW 角 + 线性回退优化（案例 7 验证 + 后续修复）

**现象**：
1. 主卧衣柜放在床对面东墙（线性 3275mm），床在西墙，间距仅 500mm（与案例 7 相同）
2. Agent 这次**确实评估了 L 形**（NE 角），但正确判断 NE 角不可行后回退线性
3. 用户指出应在 **NW 角**做 L 形（西墙主臂 + 北墙西段 730mm 副臂）

**Agent 决策链路**：
- §7.3：排除整个东墙（"门墙"）→ 仅剩西墙做床头
- §7.4 L 形：检查 NE 角 → 东墙门上方 175mm < 1200mm → 正确回退线性
- §7.4 线性 step 4：选东墙 3475mm（最长）→ 未触发 "< 800mm" 优化警告
- §4.1：通道 500mm ≥ 500mm → 通过

**根因**（规则层，3 个子问题）：
1. §7.4 条件 1 限定"入口附近" → Agent 只检查 NE 角，跳过了可行的 NW 角
2. §7.4 条件 2 "各 ≥ 1200mm" → NW 角北墙西段 730mm 不合格（副臂门槛过高）
3. §7.4 线性 step 4 "< 800mm" 检查嵌套在【建议】中 → Agent 短路跳过
4. §7.3 "门墙"整面排除 → 东墙 3475mm 实墙段不可用于床头

**修复**（11 处改动，3 个文件）：
- `placement_guide.md`（6 处）：§7.3 门段概念 + §7.1 同步 + §7.4 条件放宽/设计理念泛化/布置方式重构/线性step4拆分
- `module_library.json`（4 处）：custom_001 width 下限 800→600 + relation_rules 同步 × 2 + bed topology 门段
- `SKILL.md`（1 处）：S4 检查项"非门墙"→"远离门段"

**关键教训**：
1. 从单一案例提取的规则容易携带"偶然特征"——案例 7 的参考图 NE 角恰好在入口旁，"入口附近"被写入规则，但 L 形核心价值与入口位置无关
2. 验证上一轮修复时要关注"修复边界"——案例 7 引入了概念（成功），但适用条件仍受单一案例局限
3. 【建议】标签 + 嵌套写法会被 Agent 短路跳过——安全约束必须独立为【必须】步骤

**效果**：⏳ 待验证

## 案例 9：主卧衣柜布置不足——有效段计算概念混淆 + 线性排除过宽 + 阶段间充足性缺失（概念混淆 + 规则层 + 规则缺失 复合型）

**现象**：3200×4400mm 主卧，衣柜仅 1070mm（北墙门间），西墙北段 1600mm 被梳妆台占据。用户期望 NW 角 L 形衣柜（参考设计）。

**Agent 决策链路**：
- §7.3：西墙纯实墙 → 优先级 1 命中 → 床头选西墙
- §7.4 L 形：NW 角——**用"门段"（x=480~2230）计算副臂** → 250→480 = 230mm < 600mm → 不可行
- §7.4 L 形：NE 角——东墙门上方仅 175mm → 不可行 → 全部不可行 → 回退线性
- §7.4 线性 step 2："排除窗墙和床头墙" → 西墙整面排除
- §7.4 线性 step 4：北墙门间 1070mm 为唯一候选 → 选中
- Phase B：tags 含 vanity → 西墙北段 1600mm 放梳妆台

**根因**（3 层）：
1. **概念混淆（根本原因）**：Agent 用 §7.3"门段"（门洞 + 两侧 500mm 床头缓冲 = x=480~2230）代替 exclusion zone（ez_5 = x=980~1730）计算衣柜有效段。正确副臂 = 250→980 = **730mm ≥ 600mm**，NW 角 L 形完全可行
2. 规则层（错误 3）：线性 step 2"排除床头墙"排除整面墙，但床组仅占 y=2450-5050，北段 1600mm 空闲
3. 规则缺失（错误 4）：阶段 A→B 无"必须家具充足性检查"，梳妆台（可选）替代了衣柜（必须）空间

**几何验证（修正后）**：
```
NW 角 (250, 6650)
├── 主臂（西墙南下）：y=5050→6650 = 1600mm ≥ 1200mm ✓
├── 副臂（北墙东延）：x=250→980 = 730mm ≥ 600mm ✓  ← exclusion zone 而非"门段"
├── 副臂末端通道：980→3450 = 2470mm ≥ 900mm ✓
└── 总衣柜：1600 + 730 = 2330mm（vs 当前 1070mm，改善 2.2 倍）
```

## 案例 10：L 形衣柜 bounds 拆分失败（规则歧义型）

**现象**：主卧 NW 角 L 形条件满足（主臂 1500mm，副臂 730mm），但 Agent 回退到分段线性布局（西墙 1500mm + 北墙东段 1070mm），未形成 L 形

**Agent 决策链路**：
1. ✅ 正确识别 NW 角 L 形条件满足
2. ❌ 将主臂视为单一连续 1500mm 模块 (x:250-850, y:5150-6650)
3. ❌ 副臂 (x:250-980, y:6050-6650) 与主臂在 600×600 转角重叠
4. ❌ 认为副臂只能从 x=850 开始 → 仅剩 130mm → 判定 L 形不可行
5. ❌ 回退线性

**偏离点**：步骤 2 — Agent 默认主臂必须是一个完整矩形模块，未考虑在转角接缝处拆分

**根因**：§7.4 step 4"转角处理"仅描述物理结果（"90° 相接，无需特殊转角模块"），未说明如何将 L 形转化为不重叠的 bounds 矩形。step 2 的"布满"一词强化了"单一连续模块"的隐含假设。

**正确做法**：
```
主臂模块（西墙截断段）：(250,5150)→(850,6050) = 900×600
副臂模块（北墙含转角）：(250,6050)→(980,6650) = 730×600
接缝线：y=6050（共享边，不重叠）→ L 形成立
```

**问题层级**：规则层 — Type 3 (规则歧义)

**修复**（3 个文件，3 处改动）：
- `placement_guide.md`（2 处）：§7.4 step 4 扩展 bounds 拆分规则 + 数值示例；step 2 "布满"添加截断交叉引用
- `SKILL.md`（1 处）：常见错误表新增"L 形主臂整段覆盖"条目

**关键教训**：
1. **概念→实现的鸿沟**：Agent 可以理解 L 形的设计理念，但在将概念转化为不重叠的矩形 bounds 时需要明确的操作指引
2. **"布满"的歧义**：在 bounds 上下文中，"布满"容易被理解为"一个模块占满整段"，需要区分概念覆盖（设计层面整段利用）和物理 bounds（可拆分为多个模块）
3. **数值示例的力量**：案例 9 通过示例解决了有效段计算的歧义，本案例沿用同一策略，用具体坐标示例解决 bounds 拆分歧义

**效果**：⏳ 待验证
