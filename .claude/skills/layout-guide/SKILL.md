# Layout Agent 操作指南

> layout-agent 专用：决策树式操作指导，根据任务描述判断标准执行流程

## 执行决策树

```
收到任务
    │
    ▼
┌─────────────────────────────────┐
│ Step 1: 阅读项目 README.md      │
│ → 了解目录结构、文件用途        │
└─────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────┐
│ Step 2: 判断任务类型            │
│ → 根据【操作类型】或关键词判断  │
└─────────────────────────────────┘
    │
    ├─ query（只读）
    │   └─ 执行 Query 流程
    │
    ├─ edit（单一修改）
    │   └─ 执行 Edit 流程
    │
    └─ generate（完整布置）
        └─ 执行 Generate 流程
```

## Query 流程（只读）

**触发条件**：【操作类型】: query 或关键词"统计/查看/列出/有多少"

**允许工具**：Read, Glob, Grep
**禁止工具**：Write, Edit

**步骤**：
1. Read 目标数据文件（如 modules.json）
2. 空数据检查 → 空则报告"数量为 0"
3. 分析/统计（仅基于实际读取的数据）
4. 验证：报告内容必须与文件实际内容一致
5. 返回结果

**禁止行为**：
- 根据房间信息推断/编造不存在的模块
- 空数据时自动创建示例数据

## Edit 流程（单一修改）

**触发条件**：【操作类型】: execute + 关键词"移动/删除/旋转/调整"

**步骤**：
1. Read modules.json
2. 定位目标模块
3. 执行修改操作
4. 验证约束（间距≥800mm、不超边界、不重叠）
5. Write 保存结果

## Generate 流程（完整布置）

**触发条件**：【操作类型】: execute + 关键词"布置/设计/创建/生成"

**步骤**：
1. **必须**先阅读 knowledge/placement_guide.md
2. Read computed/room_zones.json
3. Read modules/module_library.json
4. Read baseline/openings.json
5. 分析空间，按优先级布置：
   - 锚点家具（电视柜/床/餐桌）
   - 主要家具（沙发/衣柜）
   - 辅助家具（茶几/边几）
6. 验证约束
7. Write schemes/modules.json

## 核心约束（所有流程适用）

### 布置规则
- 大型家具靠墙（床、衣柜、沙发）
- 电视柜居中于电视墙，沙发正对电视（2.5-4m）
- 床头不靠窗，家具不阻挡门
- 通道宽度 ≥ 800mm
- 不与禁区重叠
- 不阻挡门开启

### 数据真实性
- 输出必须**严格基于**实际读取的文件内容
- 统计结果必须与 modules.json 数组长度一致
- 空数组 → 报告"数量为 0"，禁止推断
- 报告的每个模块 ID 必须在 modules.json 中实际存在

## 布置优先级

1. **锚点家具**：客厅→电视柜，卧室→床，餐厅→餐桌
2. **主要家具**：围绕锚点布置
3. **辅助家具**：填充剩余空间

## 标签驱动选择

根据 zone.tags 筛选 module.tags 有交集的模块。

## 输出格式（modules.json）

```json
[
  {
    "id": "m_1",
    "moduleId": "mod_bed_001",
    "zoneId": "rz_3",
    "bounds": [[11100, 2000], [13100, 2000], [13100, 4000], [11100, 4000]],
    "facing": "north",
    "items": []
  }
]
```

## 工作目录说明

- **query 任务**：使用当前工作目录
- **execute 任务**：使用 MainAgent 传递的 worktreePath（隔离环境）

确保所有文件操作都在正确的工作目录下执行。
