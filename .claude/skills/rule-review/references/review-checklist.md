# 提示词审查诊断指南

> 三层诊断模型，每层以底层机制为基础。
> 检查项不是必须逐条过的清单——理解了机制，就能自主判断该关注什么。
> 每条格式：**检查什么** → **为什么重要** → **怎么判断** → **典型违规**

---

## 第一层：信息架构

> **基础：机制 1 — 注意力是零和的。** 提示词中每个 token 都在竞争 AI 的注意力。100 条规则中每条只分到 1% 注意力。冗余规则不是无害的——它们稀释真正重要的规则的权重。
>
> 核心问题：**Agent 能高效处理这些信息吗？**

### D1.1 结构与信噪比

- **检查**：文件结构是否清晰？是否有冗余或低价值内容？
- **为什么**：结构帮 AI 建立信息索引（不是为了好看）；冗余直接稀释关键规则的注意力权重
- **判断**：(1) 标题/目录能否让 Agent 快速定位所需信息？(2) 对比性信息是否用表格？(3) 对每段内容问"去掉这段，Agent 行为会变差吗？"——不会就是噪音
- **违规**：placement_guide 中"设计原则"和"尺寸标准"混在同一章节；跨文件重复同一规则；详细解释 Agent 已知的常识

### D1.2 职责归属

- **检查**：每个文件是否只包含属于自己职责范围的内容？
- **为什么**：职责越界 = 规则散落 → Agent 找不到完整信息 → 决策链中断。一处定义、其他处引用——否则 Agent 恰好优先读到那个少了限定词的版本
- **判断**：对照 `references/prompt-file-map.md` 职责边界表（SKILL.md 管流程，placement_guide 管标准，module_library 管模块）
- **违规**：SKILL.md 中出现具体设计数值（"窗侧 200mm"）；module_library 中引用外部文件（必须自包含）

### D1.3 跨文件一致性

- **检查**：同一规则在不同文件中的表述是否语义一致？
- **为什么**：规则在跨文件传播中会丢失限定词（案例 4 的教训）——Agent 优先读到的那一处决定行为
- **判断**：追踪 `references/prompt-file-map.md` 跨文件追踪表中的高频同步项，对比用词、数值、适用范围
- **违规**：placement_guide 说"紧凑房型取 200mm"，SKILL.md 说"窗侧取最小值 200mm"——缺少"紧凑"限定

## 第二层：认知校准

> **基础：机制 2（概念激活 > 规则添加）+ 机制 3（WHY = 泛化能力）。** 概念引入激活 AI 训练数据中的整个知识区域，规则修复只改一个参数——这是完全不同量级的影响。而 WHY 从根本上改变规则的适用范围：无 WHY 的规则只能机械执行，有 WHY 的规则能在边界场景中被灵活应用。
>
> 核心问题：**Agent 的判断力被校准到什么水平？**

### D2.1 WHY 覆盖率

- **检查**：关键规则是否解释了原因？
- **为什么**：**这是单条检查中影响最大的一项**（机制 3 是"三个机制中最关键的"）。有 WHY 的规则在规则未覆盖的场景中仍能引导合理推导；无 WHY 的规则只能被机械执行
- **判断**：对每条非自明规则问"为什么要这样做？"——如果答案不显然，就需要补充 WHY。原因应简洁（1-2 句"因为 X 所以 Y"），过度解释同样占用注意力
- **违规**："衣柜应填满有效段全长"——为什么不留一段空白？应补充：连续柜面视觉整洁 + 最大化收纳

### D2.2 示例充分性

- **检查**：抽象规则是否有具体示例辅助理解？
- **为什么**：AI 从一个具体示例中提取到的模式，远比十句抽象描述更精确（机制 2 的推论）
- **判断**：规则中是否包含具体数值场景或 JSON 片段？module_library 的 relation_rules 是否足够具体到 Agent 能直接执行？
- **违规**："衣柜应合理利用墙面空间"——无具体场景说明何为"合理"；"优先利用门后凹位"——未说明什么条件下触发

### D2.3 约束层级分化

- **检查**：规则是否区分了"必须/禁止"（硬约束）vs"应/建议"（软指导）vs"可/优先"（自由度）？
- **为什么**：所有规则都用"必须"语气 → Agent 无法区分优先级 → 在矛盾时随机妥协。三级约束模型让 Agent 知道哪些绝对不能违反、哪些可以灵活处理
- **判断**：统计各文件中语气词分布；检查清单 H/S 分级是否准确（H 项是否真是硬约束？S 项是否允许合理偏离？）
- **违规**：所有规则都用"必须"语气；把"衣柜填满有效段"归为 H 项（实际是设计建议，非安全/功能约束）

### D2.4 禁止项：具体性 + 堵不如疏

- **检查**：(1) 禁止项是否足够具体？(2) 是否有禁止项可以改为正面引导？
- **为什么**：模糊的禁止项无法被执行（"禁止不合理布置"）。而即使具体的禁止项，也可能不如正面引导有效——"禁止做 X"让 Agent 知道不该做什么，但不知道该做什么，在边界场景中容易困惑（rule-tuning 反模式 1："堵不如疏"）
- **判断**：禁止项能否被机械执行（无需主观判断）？对每条禁止项追问：能否改为"教会做 Y"？
- **违规**："禁止不合理布置"（无法执行）；"禁止选择床对面墙放衣柜"（应改为教会 L 形转角概念——让 Agent 理解为什么不选对面墙）

## 第三层：留白

> **基础：控制的悖论 — 真正的控制来自共识，不来自穷举规则。** 过度规则化 → AI 把注意力全用于合规检查 → 没有注意力用于"思考怎么做得好"。好的提示词不追求全覆盖——自由区域不是"还没来得及写规则的地方"，而是"经过深思熟虑后决定不写规则的地方"。
>
> 核心问题：**Agent 有发挥设计判断力的空间吗？**

### D3.1 自由区域与软指导弹性

- **检查**：是否有显式标注的 Agent 自主决策空间？软指导是否允许合理偏离？
- **为什么**：人类设计师的"好品味"恰恰体现在没有硬性规则的地方。如果每个决策点都被规则覆盖，Agent 变成规则执行器，无法从"不犯错"升级到"有品味"
- **判断**：是否有"位置由 Agent 根据剩余空间自主决定"类似的显式标注？S 级检查项是否允许 Agent 在说明理由后偏离？
- **违规**：每个决策点都被规则覆盖，Agent 没有任何自主权；所有检查项都标为 H（硬性）

### D3.2 原理覆盖边界场景

- **检查**：边界场景是否通过设计原理引导，而非穷举规则？
- **为什么**：不可能为每种户型写规则，但原理（如"空间流动感""视觉均衡"）能让 Agent 在新场景中自行推导。提供评估维度而非具体答案——AI 可以在不同房间中做出不同但合理的判断
- **判断**：是否有设计原理级别的内容（而非纯规则）？遇到新场景时 Agent 有没有推导依据？
- **违规**：试图用规则覆盖每一种可能场景，导致规则数量膨胀但边界场景仍然覆盖不到
