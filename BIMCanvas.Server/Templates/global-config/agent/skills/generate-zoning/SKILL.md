# 分区 Skill

> 为空间制定布局策略：决定这个空间应该有几种不同的体验，它们之间是什么关系。
> 分区是"规划"的组成部分——空间功能定义后，后续房间策略在此框架内精确布置。

**与 generate-workflow 的协调**：本 Skill 在 Stage 2.2（分区设计）被加载。此时 generate-workflow 已通过 `save_semantic_plan(v0.1)` 提交了：
- 语义方案 v0.1（空间骨架：动线/纵深/采光/初步意图）
- 基于物理约束确定的主要家具最优墙面位置

**输入**：v0.1 已提交的空间骨架 + 主要家具墙面结论
**输出**：分区兼容性结论 + 功能定义（写入 v0.2）
**不做**：不重新分析空间几何、不重新推导墙面语义、不重做主家具决策

本 Skill 基于这些已有分析做分区评估——不重新推导空间信息。执行顺序：先用已确定的家具位置过滤不兼容的分区方案，再做功能定义。

**禁止重新评估家具位置**：家具的墙面归属已由房间策略确定，分区评估只检查"分区方案是否兼容这些已确定的需求"。

WHY：分区赋予空间以意图。有意图的空间才能产出有设计感的布置——家具属于各自区域的功能叙事，区域间的留白是有意识的空间节奏。没有分区的布置只是"把家具塞进房间"。同时，分区解耦约束，让每个子空间聚焦单一功能，降低布置难度。

## 一、本 Skill 的职责

本 Skill 始终被加载，负责两件事：
1. **空间预演**（步骤 1）：评估空间是否需要物理分割，如需则确定分割方式
2. **功能定义**（步骤 2）：为空间（或各子空间）定义功能身份

"不分区"是合法结论——步骤 1 判定无需分割后，步骤 2 仍需执行，将整个空间定义为单一功能区。

WHY：功能定义是布置的前提。每块空间的功能身份（"这里是睡眠区""这里是梳妆区"）在策略阶段之前就应该明确——否则后续家具布置是在没有空间意图的基础上进行的。分区 Skill 的核心产出不是 subZones 数据，而是"空间各部分承担什么功能"的显式决策。

## 二、分区方法

### 步骤 1：空间预演（分割评估 + 预布置验证）

分区线不是凭空画出来的——它从家具预布置和动线想象中浮现。

**快速判断**：矩形 + 单功能标签组 + 无空间冲突信号 → 结论"无需物理分割"，直接进入步骤 2

**需要详细评估的信号**（命中任一则列举分割候选 → 预布置验证 → 选择最优分割）：

| 信号 | 典型场景 | 判断依据 |
|------|---------|---------|
| 异形空间 | L 形、T 形、带凹角 | rawBoundary 顶点 > 4，存在可独立围合的子空间 |
| 多功能组合 | 客餐厅、书房卧室 | 多个功能标签 + 面积足以分区 |
| 功能间墙面冲突 | 床和衣柜争抢同一面墙 | 主要家具放置后通道 < 900mm |
| 空间比例失调 | 窄长形（宽深比 > 1:2.5） | 单一空间内动线过长或功能分散 |

**1a. 列举分割候选**：异形空间的内凹角通常允许两种正交切割方向（水平切或垂直切），产生不同的子空间形状和墙面资源分配。列出各候选的子空间尺寸和主要墙面长度。

**1b. 预布置验证**：对每个候选方案，在脑中粗放主要家具，检验分区是否成立。

具体做法：
1. 找到 tags 中最大的家具（床、衣柜、沙发等），估算其占用尺寸
2. 将主要家具粗放到候选子空间中最可能的墙面
3. 检查：主通道 ≥ 900mm？家具间是否产生无法解决的冲突？
4. 如果某候选方案的子空间放不下必要家具或通道不足 → 该方案不可行

WHY：分区尺寸是从家具尺度反推出来的。说"这块 3m×3m 是睡眠区"，是因为已经验证了床 + 床头柜 + 通道在 3m×3m 内放得下。没有预布置验证的分区线只是任意的几何切割。

**1c. 确定可行方案**：基于预布置验证，筛除不可行方案（主要家具物理放不下或主通道不足），保留所有可行方案及其预布置结论，进入步骤 2。

- 异形区判断标准：≥2 面墙围合 + 与主体共享墙角
- 异形区是"有独立空间特征的迷你房间"，不是"主区域的附属墙段"
  WHY：物理围合创造独立空间体验

### 步骤 2：定义功能（语义层面）

**2a. 功能分配审视**：步骤 1 已确定分割方式和子空间形状。现在审视各子空间的墙面资源和空间品质（采光、动线位置、与相邻空间的关系），决定功能分配。

空间阅读三要素：
- **动线方向**：入口 → 深处，人的自然行进路径
- **纵深层次**：前场（靠入口，适合过渡/公共功能）vs 远端（适合私密/静态功能）
- **采光轴**：窗侧适合日间活动、需要自然光的功能

对每个候选方案，推演其对另一个子空间的连锁影响（示例 1 演示了这种推演）。分区标签一旦确定，后续房间策略只在标签范围内思考——分区决策锁定了后续所有可能性。

**子空间内的功能方案分歧**：当子空间的墙面资源允许两种以上功能方案（如"纯衣柜"vs"衣柜+梳妆台"），且方案间对日常使用有质的差异时——这是战略选择，需要在步骤 2b 中一并向用户展示。"区域内的标签分配"不是跳过询问的理由：标签决定了后续房间策略能放什么家具，影响与分区划分同等重大。

WHY：局部最优 ≠ 全局最优。延伸区"看起来适合做 X"不代表"X 放在延伸区是全局最优解"。

**2b. 展示分区方案**：向用户展示分区分析和推荐方案（AskUserQuestion）。

展示内容：
- 推荐方案：分割方式 + 各子空间功能定位 + 对用户日常使用的具体影响
- 替代方案（如步骤 1 有多个可行方案）：核心差异和取舍
- 推荐理由

WHY：分区是整个布局的骨架——分割方向和功能定位一旦确定，锁定后续所有可能性。设计师在确定空间骨架前展示方案给客户，是专业流程的自然环节。进入分区流程本身就意味着空间足够复杂，值得用户确认。

**2c. 确定功能**：选择推荐方案，功能映射到 Zone Tags，Tags 映射到房间策略文件。
WHY：功能驱动产出"有使用场景的空间"；几何驱动产出"零散家具的堆放区"。

### 步骤 3：输出 subZones（数据层面）
- 修改 `schemes/zones.json` 中父 zone 的 `subZones` 字段
- 每个子 zone：`type = "designable"`，`id = "dz_{n}"`
- 子 zone 的 `roomId` 继承父 zone，`tags ⊆ 父 zone tags + optionalTags`
- 写入后 Server 自动创建子目录
- 写入后调用 `get_zone_boundaries(zoneIds=[新子zone列表])` — 返回子 zone 边界中的 passage 段（通向相邻分区的开放连通），后续房间 Skill 据此避免在通道处放大型家具

> WHY：子分区的 rawBoundary 不区分墙和通道。passage 段解决了"这条边到底是实墙还是通向 dz_2 的通道"的关键问题。

## 三、分区策略声明示例

### 示例 1：L 形主卧（异形分区 — 预布置验证驱动选择）

场景：rawBoundary 7 个顶点，L 形空间，tags=[sleep, wardrobeStorage]，optionalTags=[vanity]
- L 形整体：宽约 5000mm，高约 4850mm，右上角有 1700×1550 延伸
- 北墙约 5000mm 横跨 L 形上沿，西墙约 4850mm，南墙约 3300mm

步骤 1a — 列举分割候选：
- **方案 A（竖直切割，沿内凹角垂直线）**：左右分
  - dz_1: 3300×4850 主体区（西侧），拥有西墙 4850mm、南墙 3300mm
  - dz_2: 1700×1550 小延伸区（东北角）
- **方案 B（水平切割，沿内凹角水平线）**：上下分
  - dz_1: 约 5000×1550 北部长条区，拥有北墙完整 5000mm
  - dz_2: 3300×3300 南部方正区

步骤 1b — 预布置验证：
- tags 含 sleep + wardrobeStorage → 主要家具是床（优先按 1800×2100 + 双床头柜预估，不成立时复核 1500×2100 + 双床头柜）和衣柜（深 600mm）
- **方案 A 验证**：主体区宽 3300mm，床深 2100 + 衣柜深 600 + 通道 = 3300mm → 通道仅 600mm（< 900mm 主通道标准）。床和衣柜在 3300mm 宽度内产生无法调和的空间冲突。延伸区 1700×1550 太小无法承载衣柜
- **方案 B 验证**：北部长条区获得完整北墙 5000mm，wardrobeStorage 沿北墙展开（深 600mm），前方净空 950mm ≥ 900mm ✓。南部 3300×3300 方正空间放床，两侧通道各 750mm ≥ 500mm ✓

→ 方案 A 的核心功能（sleep + wardrobeStorage）在主体区产生物理冲突；方案 B 通过功能分离彻底解决。两种分割有质的差异。

步骤 2b — 展示分区方案（AskUserQuestion）：
- 推荐方案 B（上下分）：北部做更衣走廊（5000mm 连续墙面），南部 3300×3300 方正睡眠区
- 替代方案 A（左右分）：传统 L 形拆解，主体区做卧室（wardrobeStorage 在内部解决，通道紧凑），延伸区做小型辅助功能区
- 核心取舍：wardrobeStorage 墙面充裕 + 睡眠区方正 vs 传统分割 + 更大睡眠区面积

步骤 2a — 功能分配审视（假设用户选择方案 B）：
- 北部长条 5000×1550 的可用墙面呈 L 形（北墙 + 东墙延伸段），两种功能方案：
  - 纯衣帽间（L 形两边都做衣柜）→ 最大收纳，但梳妆台失去最佳位置
  - 衣柜 + 梳妆台组合（L 形短边 1700mm 恰好放梳妆台）→ 靠近卫浴动线化妆，但减少衣柜容量
- 两种方案对日常使用有质的差异 → 战略选择 → 在步骤 2b 中向用户展示（AskUserQuestion）

步骤 2c/3 — 定义功能 + subZones：
- dz_1: 衣帽间/更衣区, tags=[wardrobeStorage], optionalTags=[vanity]
- dz_2: 睡眠区, tags=[sleep]

### 示例 2：客餐一体（功能分区）

场景：7.2m×4.8m 矩形，tags=[tvMedia, rest, dining]，南墙大窗，北墙入口

空间阅读：动线北→南 · 纵深：入口区→过渡→休息区 · 采光：南窗全面

步骤 2 — 定义功能：
- 南侧 4.2m → 客厅区（采光好，适合日常休息和观影）
- 北侧 3.0m → 餐厅区（靠入口和厨房，缩短上菜动线）

步骤 3 — subZones：
- dz_1: 客厅区, tags=[tvMedia, rest]
- dz_2: 餐厅区, tags=[dining]

### 示例 3：矩形主卧（快速判断 — 不分割）

场景：矩形 3600×4200mm，tags=[sleep, wardrobeStorage]，北墙入口，南墙窗

空间阅读：矩形 + 单功能标签组 + 无空间冲突信号 → 快速判断

步骤 1 — 快速判断：矩形空间，单一功能标签组，无异形、无多功能冲突
→ 结论：无需物理分割

步骤 2 — 功能定义：整体空间 = 睡眠+收纳区，功能单一，不需要子空间标签

→ 不产出 subZones，直接继续 generate-workflow

WHY：矩形 + 单功能 = 快速路径。详细评估留给确实需要分割的空间。

## 四、关键约束

**【硬约束】**
- ① 子空间边界不重叠 — 一个位置不能同时属于两个功能区
- ② 子空间合集覆盖原始 rawBoundary — 不遗漏可用空间
- ③ 功能定义必须具体（"更衣区"✓ "过渡区"✗）— 模糊功能无法映射 Tags
- ④ 子分区完成后必须调用 get_zone_boundaries — passage 数据是后续房间 Skill 正确工作的前提

**【软指导】**
- 分区线需有预布置根据 — 不能说明主要家具如何容纳的分区线，只是任意切割
- 异形区优先搜索可选家具位置 — 独特尺寸恰好适配特定家具
- 动线区域保持通透 — 通行功能优先于放置功能
- 子空间边界用矩形近似 — 与 OBB 设计原则一致，简化坐标推理

**【自由区域】**
- 分区线的精确位置
- 功能区面积比例分配
- 子空间命名风格
- 分区数量（2个还是3个，根据空间实际情况判断）
