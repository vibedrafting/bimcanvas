# Generate 规划

> 你在本 Skill 中是设计师。你的职责不是复刻参考图，而是把“当前户型 + 定稿参考分析 + 设计知识库”压缩成可施工的语义合同。

## 最重要的规则

1. **`v0.1` 永远只分析当前户型，不读参考分析。**
2. **只有定稿后的 `reference_analysis` 才能进入 planning。**
3. **`v0.2` 是战略层方案，第一次正式消费 reference_analysis。**
4. **`v0.3` 是完整施工简报，placement 只读 `v0.3`。**
5. **若核心参考意图与当前几何冲突，必须先 Ask，再继续规划。**

**WHY**：
- `v0.1` 不独立成立，后面的参考消费就没有真实空间基线。
- planning 如果消费未定稿参考分析，就会把 analysis 阶段尚未冻结的歧义偷偷带进设计决策。
- placement 不应重新理解 raw reference；它只该施工。

---

## 职责与输出

- 输入：
  - 用户需求
  - 项目 README
  - 当前设计区几何
  - 房间策略文件
  - 模块库
  - 可选家具规则
  - 可选的、**已定稿**的 `reference_analysis`
- 输出：
  - `v0.1`：空间骨架
  - `v0.2`：战略层方案
  - `v0.3`：完整施工简报

**【必须】**planning 是唯一的语义压缩点：
- 把当前户型读懂
- 把定稿 reference_analysis 消化掉
- 把真正采纳的参考理解写进 `semantic_plan`
- 把偏离与转译理由写进 `semantic_plan`

**【必须】**本 Skill 不负责坐标化施工，不写 `modules.json`。

---

## 入场判断

### 自主规划模式

适用于：
- 当前任务没有参考图
- 或当前任务没有已定稿的 `reference_analysis`

### 参考消费模式

适用于：
- 当前任务已完成 `generate-reference-analysis`
- 当前设计区已经存在可供消费的最新定稿 `reference_analysis`

**参考消费模式入场动作**：
1. 调用 `load_reference_analysis(zoneId)` 读取最新版本
2. 若返回 `status=missing`，立即停止并说明“缺少已定稿的 reference_analysis，不能进入参考消费模式”
3. 复述当前消费的参考分析版本号

**【必须】**不要根据图片名称、用户措辞、主观印象给流程另起名字。

**【必须】**图片本身不是合同；定稿 `reference_analysis` 才是 planning 的正式参考输入。

---

## 1. 感知

1. 调用 `mcp__canvas__request_background_screenshot`
2. 并行读取：
   - `references/design_principles.md`
   - `references/design_evaluation.md`
   - `modules/module_library.json`
   - `schemes/zones.json`
   - `computed/exclusions.json`
3. 调用 `mcp__canvas__get_zone_boundaries`
4. 根据当前 zone tags 读取对应房间策略文件：
   - 卧室：`references/bedroom.md`
   - 卫生间：`references/bathroom.md`
   - 客餐厅：`references/livingroom.md`

---

## 2. 规划

### 2.1 空间骨架 -> `v0.1`

**目标**：独立理解当前项目户型。

**【必须】**无论是否存在 `reference_analysis`，`v0.1` 都只分析当前户型。

从 `design_evaluation.md` 的品质维度完成空间阅读：
- 动线方向
- 纵深层次
- 采光轴
- 当前空间潜力与风险

`v0.1` 只写空间骨架，不写具体家具坐标。

#### `v0.1` 推荐结构

```markdown
# v0.1 空间骨架

## 当前户型空间阅读
- ...

## 动线与纵深
- ...

## 采光与安静区判断
- ...

## 初步设计抓手
- ...
```

#### 保存规则

```text
save_semantic_plan({
  zoneId,
  version: "v0.1",
  planType: "derived",
  content
})
```

`v0.1` 不写 `referenceAnalysisVersion`。

**WHY**：
- `v0.1` 是后续所有设计决策的真实地基。
- 如果参考分析直接覆盖 `v0.1`，空间基线会被参考图幻觉污染。

---

### 2.2 战略层方案 -> `v0.2`

**目标**：锁定主家具、分区组织、关键空间关系，以及参考的战略级采纳与偏离。

#### 自主规划模式

1. 基于房间策略确定主要家具策略
2. **【必须】**加载 `generate-zoning`
3. 先用主要家具需求过滤分区方案，再确定功能定义
4. 输出战略层方案

#### 参考消费模式

先读取最新定稿 `reference_analysis`，重点识别：
- 参考布局核心理解
- 与当前项目的关键差异
- 用户确认后的设计倾向
- 优先保留的参考意图
- 可调整或不要求忠实参考的部分
- 当前采用的转译原则

然后执行和自主规划模式相同的主干逻辑：
- 房间策略
- `generate-zoning`
- 主要家具策略
- 分区组织
- 战略选择 / AskUserQuestion

**参考消费模式的核心要求**：
- 优先保留已经在参考分析中定稿的核心设计组织
- 把当前户型中的转译结果写清楚
- 不能把“看起来更合理”当作偏离理由
- 偏离理由必须来自几何、建筑锚点、功能冲突或用户最新确认

#### 核心冲突处理

若出现以下情况，必须先 Ask，再继续：
- 参考分析中明确要保留的核心设计意图无法兑现
- 当前项目只能在两种完全不同的战略方案之间选择
- 参考分析里“可调整”的表述仍不足以覆盖当前冲突

#### `v0.2` 推荐结构

```markdown
# v0.2 战略层方案

## 空间骨架承接
- ...

## 主要家具策略与分区
- ...

## 关键空间关系
- ...

## 参考采纳与偏离摘要
- 采纳：...
- 偏离：...
- 转译原则：...

## 自动标记
- ...
```

#### `v0.2` 示例：带参考分析

```markdown
# v0.2 战略层方案

## 空间骨架承接
- 当前户型进深有限，但仍可形成入口前场与深处睡眠区。

## 主要家具策略与分区
- 入口侧先形成换衣/收纳过渡区，再进入主睡眠区。
- 床作为主家具位于更深处的安静区。

## 关键空间关系
- 保留“入口 -> 换衣/收纳 -> 睡眠”的递进关系。
- 换衣区优先与主通行形成缓冲，而不是与窗位争抢。

## 参考采纳与偏离摘要
- 采纳：保留独立换衣体验与睡眠区后置。
- 偏离：原图整面高柜方案因北墙窗位改为半围合收纳。
- 转译原则：优先保留空间组织，不强求原图柜体展开方向。

## 自动标记
- 无
```

#### 保存规则

```text
save_semantic_plan({
  zoneId,
  version: "v0.2",
  planType: "derived",
  content,
  referenceAnalysisVersion: "vN"   # 参考消费模式必填
})
```

`v0.2` 提交后，立即读取 `references/optional-furniture-rules.md`。

**WHY**：
- `v0.2` 的职责是先把“方向”锁死，再让 `v0.3` 补足施工所需细节。
- 如果在 `v0.2` 不写战略级偏离，`v0.3` 就会在已经落定主家具后再补写理由，因果顺序会倒置。

---

### 2.3 完整施工简报 -> `v0.3`

**目标**：把 `v0.2` 收束成 placement 唯一可读的完整合同。

#### 自主规划模式

在不推翻 `v0.2` 主要家具与分区前提下，补全：
- 可选家具
- 附属家具
- 关键留白
- 关键关系
- 最终落地表达

#### 参考消费模式

在不推翻 `v0.2` 战略层方案前提下，补全：
- 最终家具体系
- 最终保留的空间关系
- 细节级适配理由
- 最终参考采纳与偏离摘要

**【必须】**`v0.3` 必须让 placement 直接施工，不得要求 placement 回头解释 `reference_analysis`。

#### `v0.3` canonical 结构

```markdown
# v0.3 完整施工简报

## 主要家具
- [家具名]：墙面归属 / 朝向语义 / 尺寸等级或关键尺寸

## 可选/附属家具
- [家具名]：保留 / 补充 / 省略 + 锚点位置或原因

## 保留空段与关键留白
- [墙面或边段]：保留目的

## 关键关系与分区意图
- [邻接 / 对位 / 前后场 / 通行与静区关系]

## 参考采纳与偏离摘要
- [最终采纳项]
- [最终偏离项]
- [最终转译理由]

## 自动标记
- `[自动代决] ...` / `[自动适配] ...` / `- 无`
```

#### `v0.3` 示例：带参考分析

```markdown
# v0.3 完整施工简报

## 主要家具
- 床：房间深处主睡眠区，床头靠实墙，1800 大床
- 收纳柜组：入口侧换衣/收纳过渡区，形成半围合收纳界面

## 可选/附属家具
- 床头柜 x2：保留，位于床两侧
- 梳妆台：保留，位置调整到南窗西侧，不要求与原参考图同侧

## 保留空段与关键留白
- 入口侧主通行：保留换衣区前的过渡空段
- 窗前：保留采光留白，不布置高体量柜体

## 关键关系与分区意图
- 动线为入口 -> 换衣/收纳 -> 睡眠
- 梳妆台服从采光与通行，不影响独立换衣体验

## 参考采纳与偏离摘要
- 采纳：独立换衣体验、睡眠区后置、梳妆功能保留
- 偏离：原图整面高柜改为半围合收纳；梳妆台改到另一侧窗位
- 转译理由：北墙窗位和当前进深限制了原图展开方式，优先保留空间组织与功能保留

## 自动标记
- [自动适配] 收纳柜组缩短以避让窗洞，但保持入口侧换衣过渡不变
```

#### 保存规则

```text
save_semantic_plan({
  zoneId,
  version: "v0.3",
  planType: "derived",
  content,
  referenceAnalysisVersion: "vN"   # 参考消费模式必填
})
```

---

## 3. 约束

- `v0.2` 之后，主要家具策略与战略级分区不可在本 Skill 内被静默推翻
- `v0.3` 只能补全，不得重新发明一套新的战略方向
- `placement` 只允许读取 `v0.3`
- 不在本 Skill 内写 `modules.json`
- 不在本 Skill 内调用 `load_semantic_plan`

**【自由区域】**
- 可选家具的取舍（在 `optional-furniture-rules` 框架内）
- 家具间精确间距
- 设计意图措辞
- 细节级转译方式

**WHY**：
- 只把必须正确的阶段边界写成硬规则。
- 具体怎么把参考意图转译到当前户型，仍然留给设计判断，而不是把 prompt 写成分支爆炸的规则表。

---

## 4. 交接

本 Skill 完成后，由编排层路由到 `generate-placement` 进行施工。
