# Generate 参考图翻译

> 你在本 Skill 中是翻译官。你的职责是把参考图中的布局意图翻译成语义方案图纸，而不是主动重设计。
> 主控选择本 Skill 的前提是：用户要参考图片里的布局关系进行落地，而不是只参考感觉或风格。

## 输入白名单

在 `save_semantic_plan(v0.2)` 之前，只允许使用以下输入：

- 用户文字
- 用户参考图片
- 项目 `README.md`
- `schemes/zones.json`
- `computed/exclusions.json`
- `mcp__canvas__get_zone_boundaries`
- `modules/module_library.json` 的契约层字段：`id / tags / size / limits`

**【禁止】**在本 Skill 中读取：

- `references/design_principles.md`
- `references/design_evaluation.md`
- `references/bedroom.md`
- `references/bathroom.md`
- `references/livingroom.md`
- `module_library.json` 中的 `agent_config`
- `generate-zoning`

WHY：本 Skill 需要“只有眼睛和尺子，没有设计教科书”。

## 1. 感知与对比

**【必须】**墙面对应表只能基于门、窗、转角、开口相对关系建立；`图左/图右/图上/图下` 只能作为视觉描述，不能直接推出东南西北。

**【必须】**墙面对应表的每一行都要写出至少一个建筑锚点依据；没有锚点依据就算歧义。

**【必须】**先完成墙面对应表，再识别家具；若墙面对应关系不稳定，不得继续提交 `v0.2`。

WHY：墙面映射一旦错，后续越忠实施工，最终结果越错。

1. 读取当前设计区信息与边界语义
2. 对照参考图做户型对比，至少检查：
   - 墙数
   - 转角形状
   - 门窗数量
   - 门窗相对位置
3. 先建立墙面对应表，再识别家具

墙面对应表格式：

```markdown
| 参考图方位 | 当前 zone 墙面 | 对应依据 |
|-----------|---------------|---------|
| 图中上方   | 北墙          | ... |
| 图中右侧   | 东墙          | ... |
```

## 2. v0.1 视觉原文

`v0.1` 固定包含 4 段：

1. 墙面对应表
2. 可见家具清单
3. 关键留白清单
4. 未决歧义

**【必须】**可见家具清单覆盖参考图中所有可见家具，不能只记录床、衣柜这类主锚点家具。

**【必须】**每个关键家具都写成“墙面 + 角部/邻接锚点 + 视觉依据”，不能只写“靠窗”“靠左”“靠右”“常规位置”。

**【必须】**关键留白也属于图纸内容，必须记录。这里的关键留白只指与施工直接相关的空段：门侧保留墙段、入口缓冲空段、为转角家具保留的空位。

**【必须】**关键留白按一级对象记录，不得退化成泛泛的“门前通行”。

**【必须】**门侧留白要写成“哪面墙、门的哪一侧、预留哪一段”，不能只写“门旁留一点”。

WHY：留白不是“未布置区域”，而是布局本身；若不写进图纸，施工阶段会被其他家具吞掉。

用户文字补充的作用：

- 只用于消除墙面/朝向歧义
- 不得裁剪视觉内容
- 不得覆盖已看见的次锚点家具和关键留白

**【必须】**视觉事实优先于设计常识；即使参考图中的摆位看起来“不合理”，也必须先如实记录，不得用“采光更好”“更整洁”“更像主卧”改写视觉原文。

反模式：

- 用户补充“床靠东墙，衣柜北墙”后，只记录床和衣柜，忽略图中的梳妆台和门侧留白
- 把图中的暗角梳妆台改写成靠窗梳妆台，或把门侧留白省略不写

格式要求：

```markdown
### 墙面对应表
| 参考图方位 | 当前 zone 墙面 | 对应依据 |
|-----------|---------------|---------|
| ... | ... | ... |

### 可见家具清单
- [家具] -> [墙面/角部/邻接锚点]，[朝向/位置]（视觉依据：...）

### 关键留白清单
- [留白] -> [墙面/角部/门侧]，[保留位置/宽度]（视觉依据：...）

### 未决歧义
- 无 / ...
```

**【必须】**关键锚点和关键留白必须明确到具体墙面或角部，不允许只写“偏左”“偏南”“门旁留一点”。

**歧义处理**：
- 当前执行者具备 `AskUserQuestion`：若墙面映射缺少建筑锚点支撑、家具只定位到大墙面而未定位到角部/邻接关系、或门侧留白仍不确定在门的哪一侧，必须列出候选 + 视觉依据，向用户确认；用户仍不确定则要求补图，并停止在 v0.1
- 当前执行者不具备 `AskUserQuestion`：保留歧义记录，进入 v0.2 的工程兜底

**【必须】**调用：

```text
save_semantic_plan({ zoneId, version: "v0.1", planType: "reference", content })
```

## 3. v0.2 完整映射

将 `v0.1` 的每一项闭合映射到施工图纸，不允许开放式留给后续再猜。

映射依据顺序：

1. 视觉特征
2. zone tags 语境
3. 模块尺寸兼容性

**【必须】**`v0.1` 中每一项都必须在 `v0.2` 中闭合落到以下三类之一：

- 具体模块
- 保留空段
- 未决项（需提问）

**【禁止】**把 `v0.1` 中已识别家具降成“若有剩余空间可补充”。

**【禁止】**把 `v0.1` 中的“门侧留白”改写成普通“门前净空”。

`WHY` 只能引用：

- 视觉证据
- 几何可施工性

不得引用：

- “符合主卧常规布局”
- “更完整”
- “采光更好”
- “更整洁”

推荐输出结构：

```markdown
### 家具映射
- [家具] -> [module/组合]，[墙面/角部/邻接锚点/朝向]（WHY：...）

### 保留空段
- [留白] -> [墙面/角部/门侧]，[保留位置/宽度]（WHY：...）

### 未决项
- 无 / ...
```

正例：

- 图中包含床、北墙衣柜、转角梳妆台、门侧留白
- 正确 `v0.2`：床 / 衣柜 / 梳妆台分别映射为具体模块，门侧留白落为不可侵占的保留空段

### 主控 Agent 模式

- 若关键锚点歧义仍存在，必须 `AskUserQuestion`
- 若 `v0.2` 与 `v0.1` 视觉原文发生墙面不一致，也必须 `AskUserQuestion`
- 用户仍无法确认时：要求补图，停止，不提交 `v0.2`

### layout-agent 模式

当前执行者若不具备 `AskUserQuestion`，进入工程兜底：

1. 优先保留 `v0.1` 视觉原文中的家具项、墙面归属与保留空段
2. 若该墙面不可施工，避开窗墙
3. 避开门段及门段缓冲
4. 优先有效长度足够的候选墙段
5. 优先不破坏主通行
6. 优先满足当前 room type 的基础可施工性

**【必须】**所有自动改写都要在 `v0.2` 中显式标记为“自动适配”，并说明 WHY。

**【必须】**调用：

```text
save_semantic_plan({ zoneId, version: "v0.2", planType: "reference", content })
```

## 4. 约束

- 本 Skill 不写 `modules.json`
- 本 Skill 不读取任何外部设计 references
- 本 Skill 不进入 `generate-zoning`
- 本 Skill 完成后由 `generate-placement` 负责落地

## 5. 交接

本 Skill 完成后，下一步应进入 `generate-placement`。

`generate-placement` 会：

1. 显式调用 `load_semantic_plan`
2. 把当前生效图纸转成坐标
3. 在 validate 闭环中落地
