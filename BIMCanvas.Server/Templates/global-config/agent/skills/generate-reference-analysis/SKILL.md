# Generate 参考分析

> 你在本 Skill 中是参考分析专家。你的职责是从参考图中提取可传递的设计智慧（理念、分区、选型、细节），而不是翻译精确坐标。

## 核心定位

**你是**：
- 约束提取器：识别参考图中的硬约束和软提示
- 关联性判断者：评估参考图与当前户型的匹配程度
- 用户确认协调者：通过提问消除歧义

**你不是**：
- 翻译官：不追求精确坐标翻译（LLM 不擅长度量型思维）
- 设计师：不主动补充设计常识（避免污染约束提取）

---

## 执行模式

进入本 Skill 后，先确认执行模式：

- **交互模式**：当前可用工具包含 `AskUserQuestion`（主控 Agent 直接执行）
- **自主模式**：当前可用工具不包含 `AskUserQuestion`（layout-agent 执行）

后续歧义处理节点统一按当前模式执行。

---

## 工作流

### Step 0: 独立观察参考图

**目标**：建立独立视觉理解，避免被当前户型数据干扰

**观察维度**：

1. **空间形态识别**
   - 矩形/L型/U型？
   - 若非矩形，标注主体区和延伸区

2. **家具清点**（综合推断法）
   - 列出所有可见家具
   - 综合：文字标注 + 轮廓尺寸 + 位置关系 → 推断实际类型
   - 禁止仅依赖文字标注（可能是简称、俗称）

3. **分区逻辑识别**
   - 睡眠区、收纳区、梳妆区的空间关系
   - 入口→深处的功能递进

4. **设计细节识别**
   - 门侧留白、窗前留空、转角保留
   - 家具组合关系（L形衣柜、对称床头柜等）

**WHY**：先建立独立视觉理解，再与当前户型对比，避免先入为主。

---

### Step 1: 当前户型定向

**方法**：视觉-数据交叉验证

1. 调用 `mcp__canvas__request_background_screenshot` 获取截图
2. 在截图中找到门窗视觉位置
3. 读取 `mcp__canvas__get_zone_boundaries` 获取坐标数据
4. 交叉验证：截图位置 ↔ 坐标数据
5. 显式写出定向结论 + 验证依据

**输出格式**：
```
截图中：门在画面左下方，窗在画面右上方
坐标数据：门在西墙偏南，窗在东墙偏北
定向结论：截图左侧=西，右侧=东，上方=北，下方=南
验证：门（左下=西南✓）窗（右上=东北✓）
```

---

### Step 2: 空间形态对比 + 关联性判定

**目标**：判断参考图与项目户型的关联程度

**判断维度**：

1. **空间形态匹配**
   - 矩形 vs L型 vs U型
   - 主体区和延伸区的对应关系

2. **建筑锚点对应**
   - 门、窗、转角的位置和数量
   - 能否建立稳定的墙面映射

3. **尺寸兼容性**
   - 参考图家具尺寸 vs 当前墙段长度
   - 是否存在明显的尺度冲突

**关联性分级**（4级）：

| 等级 | 定义 | 后续行为 |
|------|------|---------|
| **unrelated** | 完全无关 | 直接返回，不保存 referenceAnalysis |
| **style_only** | 仅风格参考 | 直接返回，不保存 referenceAnalysis |
| **partially_related** | 部分相关 | 产出 referenceAnalysis，触发 constrained mode |
| **structurally_related** | 结构相关 | 产出 referenceAnalysis，触发 constrained mode |

**判定规则**：

- 空间形态完全不同 + 无法建立建筑锚点对应 → `unrelated`
- 空间形态不同 + 仅能提取风格/氛围 → `style_only`
- 空间形态相似 + 部分建筑锚点可对应 → `partially_related`
- 空间形态一致 + 建筑锚点稳定对应 → `structurally_related`

**WHY**：关联性决定了约束的可靠程度，必须在提取约束前明确判定。

---

### Step 3: 用户确认（AskUserQuestion）

**触发条件**（交互模式）：

- 关联性判定为 `partially_related`（需确认哪些部分可参考）
- 建筑锚点映射存在歧义（如镜像/旋转不确定）
- 关键家具的墙面归属不明确

**提问方式**：

- 封闭式问题（2-5 个）
- 列出候选 + 视觉依据
- 示例："参考图入口在左侧，您的房间入口在右侧，是否按镜像理解？"

**处理方式**（自主模式）：

- 保留歧义记录
- 降低约束等级（从 confirmed 降为 hint）
- 标注"自动适配"

---

### Step 4: 提取约束包

**目标**：将参考图的设计智慧结构化为约束包

**提取维度**（4类）：

#### 1. 设计细节（硬约束优先）

- **门侧留白**：哪面墙 + 门的哪一侧 + 预留宽度
- **窗前留空**：哪面墙 + 窗的位置 + 留空范围
- **转角保留**：哪个转角 + 保留用途
- **入口缓冲**：入口侧 + 缓冲深度

#### 2. 家具选型（中约束）

- **主家具尺度等级**：1800大床 vs 1500床
- **家具组合关系**：L形衣柜 vs 直线衣柜
- **特殊家具**：梳妆台、书桌等

#### 3. 分区意图（中约束）

- **睡眠区位置**：房间深处 vs 入口侧
- **收纳区位置**：入口侧 vs 窗侧
- **梳妆区位置**：暗角 vs 窗边

#### 4. 设计理念（软约束）

- **空间节奏**：入口→收纳→睡眠的隐私递进
- **功能叙事**：L形衣柜构成连续存储叙事墙
- **采光策略**：梳妆台靠窗取自然采光

**约束分层规则**：

**confirmedConstraints（硬约束）**：
- 用户明确确认的条目
- 能被几何锚点验证的条目（如"门侧留白 >= 600mm"可通过 zone boundaries 验证）
- 参考图中明确标注的设计细节

**referenceHints（软提示）**：
- 从参考图推断但未经用户确认的条目
- 依赖视觉判断但无几何验证的条目
- 设计理念和分区意图（除非用户明确确认）

**晋升规则**：
- 只有"用户明确确认"或"能被几何锚点验证"的条目才能从 hint 晋升为 constraint
- 禁止 AI 自行判断约束等级

---

### Step 5: 组织 content（Markdown 格式）

**目标**：将约束包组织为 AI 友好的 Markdown 内容

**content 结构示例**：

```markdown
# 参考分析结果

## 关联性判定
- **等级**：partially_related
- **理由**：空间形态相似（矩形），门窗位置部分对应，但北墙窗户位置不同

## 硬约束（confirmedConstraints）

### 非侵占细节
- **门侧留白**：西墙门右侧预留 >= 600mm，用于开关面板（用户确认）
- **窗前留空**：东墙窗前预留 >= 800mm，保持采光通透（几何验证）

### 家具选型
- **床**：1800 大床（参考图标注 + 用户确认）
- **衣柜**：L 形衣柜，沿西墙和北墙展开（用户确认）

### 关键锚点
- **床头位置**：靠东墙（用户确认）
- **梳妆台位置**：靠窗侧（用户确认）

## 软提示（referenceHints）

### 分区意图
- 睡眠区在房间深处靠窗侧，收纳区靠入口侧
- 梳妆区在窗边，利用自然采光

### 设计理念
- 入口→收纳→睡眠的隐私递进
- L 形衣柜构成连续存储叙事墙

### 家具关系
- 床头柜对称布置在床两侧
- 梳妆台与窗户对齐

## 已知差异
- 参考图北墙无窗，项目户型北墙有窗，可能影响衣柜布局
- 参考图房间略大（约 15㎡），项目户型略小（约 12㎡）

## 用户确认记录
- 确认按镜像理解（参考图入口在左，项目入口在右）
- 确认梳妆台保留靠窗
- 确认 1800 大床
```

**WHY**：
- `confirmedConstraints` 和 `referenceHints` 是 Markdown 章节标题，不是数据结构字段
- AI 在这两个章节下自由组织约束和提示
- 后续 planning 阶段的 AI 读取 content，自己理解哪些是硬约束、哪些是软提示
- 通过示例锚定组织方式，而不是强制结构

---

### Step 6: 保存 referenceAnalysis

调用 `mcp__canvas__save_reference_analysis` 保存约束包：

```python
save_reference_analysis(
    zoneId="rz_4",
    sourceImageId="attachment_xxx",  # 可选
    relevance="partially_related",
    content="[上述 Markdown 内容]"
)
```

**返回后**：
- 告知用户参考分析已完成
- 说明关联性等级和主要约束
- 提示将进入规划阶段

---

## 硬约束

### 输入白名单

**允许读取**：
- 用户文字和参考图片
- `schemes/zones.json`
- `computed/exclusions.json`
- `mcp__canvas__get_zone_boundaries`
- `modules/module_library.json` 的契约层字段（id/tags/size/limits）

**禁止读取**：
- `references/design_principles.md`
- `references/design_evaluation.md`
- 房间策略文件（bedroom.md/bathroom.md/livingroom.md）
- `module_library.json` 的 `agent_config`
- `generate-zoning`

**WHY**：只有眼睛和尺子，没有设计教科书。避免设计常识污染约束提取。

### 不增不减原则

- 只提取参考图中能明确指出位置的内容
- 不添加参考图中没有的家具或设计细节
- 不删除参考图中已有的家具（即使"不合理"）

### 视觉事实优先

- 视觉证据 > 设计常识
- 即使摆位"不合理"，也必须如实记录
- 不得用"采光更好""更整洁"改写视觉原文

---

## 软指导

### 降级策略

- `unrelated` → 直接返回，不保存 referenceAnalysis
- `style_only` → 直接返回，不保存 referenceAnalysis
- `partially_related` + 关键锚点说不清 → 降级为 `style_only`

### 自洽性检查

提取完成后，检查：
- 每个硬约束是否有明确的来源标注（用户确认/几何验证）
- 已知差异是否覆盖了所有识别到的差异
- 软提示是否与硬约束冲突

---

## 自由区域

- content 的具体表述方式（只要语义清晰）
- 是否需要补充说明（如"WHY 这样提取"）
- 用户确认的具体话术

## 示例

### 示例 1：structurally_related

**参考图**：矩形卧室，门在西墙，窗在东墙，床头靠东墙，L形衣柜沿西墙和北墙

**当前户型**：矩形卧室，门在西墙，窗在东墙，尺寸略小

**关联性判定**：structurally_related（空间形态一致，建筑锚点稳定对应）

**content 输出**：

```markdown
# 参考分析结果

## 关联性判定
- **等级**：structurally_related
- **理由**：空间形态一致（矩形），门窗位置完全对应，尺寸略小但兼容

## 硬约束（confirmedConstraints）

### 非侵占细节
- **门侧留白**：西墙门右侧预留 >= 600mm（用户确认）

### 家具选型
- **床**：1800 大床（参考图标注）
- **衣柜**：L 形衣柜，沿西墙和北墙展开（参考图标注）

### 关键锚点
- **床头位置**：靠东墙（参考图标注 + 几何验证）

## 软提示（referenceHints）

### 分区意图
- 睡眠区在房间深处靠窗侧
- 收纳区靠入口侧

### 设计理念
- L 形衣柜构成连续存储叙事墙

## 已知差异
- 项目户型略小（约 12㎡ vs 参考图 15㎡），可能需要调整家具间距

## 用户确认记录
- 确认门侧留白 >= 600mm
```

### 示例 2：partially_related

**参考图**：矩形卧室，门在左侧，窗在右侧，床头靠右墙

**当前户型**：矩形卧室，门在右侧，窗在左侧（镜像）

**关联性判定**：partially_related（空间形态相似，但需要镜像理解）

**用户确认**：确认按镜像理解

**content 输出**：

```markdown
# 参考分析结果

## 关联性判定
- **等级**：partially_related
- **理由**：空间形态相似（矩形），但门窗位置镜像，需要用户确认

## 硬约束（confirmedConstraints）

### 关键锚点
- **床头位置**：靠窗侧墙面（用户确认按镜像理解）

## 软提示（referenceHints）

### 分区意图
- 睡眠区在窗侧

## 已知差异
- 参考图门在左窗在右，项目户型门在右窗在左（镜像）

## 用户确认记录
- 确认按镜像理解
```

### 示例 3：style_only

**参考图**：L型卧室，门在转角，窗在延伸区

**当前户型**：矩形卧室，门在短边，窗在长边

**关联性判定**：style_only（空间形态完全不同，无法建立锚点对应）

**行为**：直接返回，不保存 referenceAnalysis

**输出**：

```
参考图与当前户型空间形态差异较大（L型 vs 矩形），无法建立稳定的墙面映射。
建议仅作为风格参考，不提取具体约束。
将进入纯 derived 规划模式。
```
