# 空间标记上下文：数据格式与交互计划

版本日期：2026-04-27

## 0. 文档评估结论

原文档的核心方向是正确的：它已经明确了“网格只是 Web 临时交互介质、Agent 只接收合并后的空间标记、Server 只做无持久化几何合并”这些关键结论。

2026-04-27 修订：空间标记 `geometry` 坐标统一改为项目全局坐标，单位 mm，不再使用顶层设计区局部坐标。这样 `spatialMarks` 可直接与 `zones.json`、`modules.json` 中的项目坐标比较。

但原文档还不够作为完整实施计划使用。缺口主要在：

- 没有把“讨论结论”整理成可追踪的决策表。
- 没有明确每层代码应该改哪些文件、各自职责边界是什么。
- Web 端只写了交互流程，没有写清楚状态归属、窗口隔离、发送成功/失败清理语义、与现有选中/框选工具的冲突处理。
- Server 端只写了合并流程，没有写清楚路由、状态码、active worktree 读取路径、错误响应和不持久化边界。
- Agent 端只写了输出规则，没有明确当前 Agent 代码路径和 Claude/OpenAI 双路径复用点。
- 测试与验收缺少分阶段落地顺序、手工验证步骤和风险项。

因此，本文件现在作为后续开发的“完整计划与规格源”。若与早期聊天摘要冲突，以本文为准。

## 1. 目标与非目标

### 1.1 用户目标

用户可以在画布上临时圈出一个或多个区域，把这些区域作为下一条 AI 指令的上下文。例如：

- “这里是睡眠区，床组优先放这里。”
- “这块保持通行留白。”
- “衣帽间建议放在这个范围，不要占用门洞前方。”

空间标记表达的是用户意图，不是正式设计分区，也不是持久化项目数据。

### 1.2 功能目标

- 支持从 AI 上下文栏进入“空间标记”模式。
- 支持在一个顶层设计区内用网格点选/框选临时区域。
- 支持同一个批次多次添加、移除网格。
- 完成批次时由 Server 合并网格并裁剪到目标设计区边界。
- Web 只保留完成后的 `SpatialMark`，丢弃原始网格。
- 一条消息可以挂载多个完成后的空间标记批次。
- 空间标记随下一条消息进入 `context.spatialMarks`。
- Agent 在 `<canvas_context>` 中看到人类可读且结构化的空间标记。

### 1.3 非目标

- 不把网格选择写入项目文件。
- 不把空间标记保存到 `project.json`、`zones.json`、`modules.json` 或数据库。
- 不把原始 `selectedCells` 发送给 Agent。
- 第一版不编辑 `subZones`，也不在已有 `subZones` 内继续二级标记。
- 第一版不支持完成后重新编辑几何范围；要改范围就删除批次并重新选择。
- 第一版不把空间标记变成正式 `Zone` 或 `SubZone`。
- 第一版不提供面积统计、网格编号调试信息或可视化 diff。

## 2. 完整讨论结论

| 主题 | 结论 |
| --- | --- |
| 网格定位 | 网格只作为 Web 端临时交互介质。 |
| Agent 输入 | Agent 只接收完成后的 `SpatialMark[]`。 |
| 批次概念 | 一个批次代表一次用户明确标记意图，包含 `id + zoneId + label + description + geometry`。 |
| 多次选择 | 同一批次可由多次点选/框选累积，也可用 Shift 移除。 |
| 多批次 | 一个聊天窗口可挂载多个待发送批次。 |
| 生命周期 | 待发送批次只服务下一条聊天消息，发送完成后清空。 |
| 失败处理 | 发送失败或用户中断时保留待发送批次，方便重试。 |
| 标记目标 | 第一版只允许选择顶层 `activeScheme.zones` 设计区。 |
| 坐标原点 | 每个批次坐标使用项目全局坐标，原点为项目原点。 |
| 有效边界 | 使用 `computedBoundary ?? rawBoundary`。 |
| 坐标单位 | 毫米。 |
| 坐标精度 | Server 输出前 round 到毫米整数。 |
| 几何输出 | 规则矩形输出 `aabb`；不规则/带洞输出 `polygon`。 |
| 几何数组 | 一个批次可包含多个不相连区域，放在 `geometry` 数组。 |
| 洞 | 选择形成洞时保留为 `Polygon2D.holes`。 |
| Server 职责 | Server 只做校验、合并、裁剪、格式转换，不写项目文件。 |
| Core 职责 | NTS 几何合并算法放在 `BIMCanvas.Core`。 |
| Web 职责 | 负责交互、临时状态、待发送列表、上下文注入。 |
| Agent 职责 | 只渲染并解释 `spatialMarks`，不理解网格行列。 |

## 3. 术语

### 3.1 SpatialMark

完成后的空间标记批次。它是唯一会进入 Agent 上下文的数据。

### 3.2 SpatialMarkDraft

Web 当前正在编辑的临时批次。它包含 `selectedCells`，但不会持久化，也不会发给 Agent。

### 3.3 selectedCells

Web 临时记录的网格行列集合，形如 `{ col, row }[]`。只存在于 draft。

### 3.4 global 坐标

项目模型坐标，单位毫米，Y 轴向上。空间标记 `geometry`、`zones.json`、`modules.json` 使用同一套项目全局坐标。

### 3.5 local 坐标

相对目标顶层设计区左下角的历史坐标约定。空间标记上下文不再使用 local 坐标。

## 4. Agent 上下文数据格式

最终进入 `context.spatialMarks` 的结构：

```ts
type SpatialMark = {
  id: string
  zoneId: string
  label: string
  description: string
  geometry: SpatialGeometry[]
}

type SpatialGeometry =
  | { aabb: [number, number, number, number] }
  | { polygon: Polygon2DJson }

type Point2D = [number, number]

type Polygon2DJson =
  | Point2D[]
  | {
      shell: Point2D[]
      holes: Point2D[][]
    }
```

字段含义：

- `id`：短 id，表示一个完成批次，例如 `sm_01`。只要求在当前待发送上下文内唯一。
- `zoneId`：绑定的顶层设计区 ID。
- `label`：用户给这个区域的单字符串标签，例如 `睡眠区`、`通行留白`。
- `description`：用户补充说明。字段必须存在，可为空字符串。
- `geometry`：合并后的一个或多个不相连几何片段。

几何规则：

- 每个 `SpatialGeometry` 只能包含 `aabb` 或 `polygon` 之一。
- `aabb` 复用 Core 现有 JSON 格式：`[minX, minY, maxX, maxY]`。
- 不规则无洞多边形使用 Core `Polygon2D` 简写：`[[x,y], ...]`。
- 带洞多边形使用 Core `Polygon2D` 完整格式：`{ "shell": [...], "holes": [...] }`。
- 如果区域外轮廓是矩形但存在洞，必须输出 `polygon.shell + holes`，不能输出 `aabb`。
- `geometry` 为空数组视为非法完成批次。

示例：

```json
{
  "id": "sm_01",
  "zoneId": "rz_3",
  "label": "睡眠区",
  "description": "床组优先布置在这里，衣柜不要占用。",
  "geometry": [
    { "aabb": [9800, 1600, 12600, 4000] }
  ]
}
```

带洞示例：

```json
{
  "id": "sm_02",
  "zoneId": "rz_1",
  "label": "通行留白",
  "description": "保持外圈通畅，中间区域不属于该留白范围。",
  "geometry": [
    {
      "polygon": {
        "shell": [[0,0], [4000,0], [4000,3000], [0,3000]],
        "holes": [
          [[1600,1000], [2400,1000], [2400,1800], [1600,1800]]
        ]
      }
    }
  ]
}
```

## 5. Web 端计划

### 5.1 状态归属

空间标记状态必须绑定聊天窗口，而不是全局绑定整个应用。

建议扩展：

```ts
interface ChatWindow {
  pendingSpatialMarks: SpatialMark[]
  spatialMarkDraft?: SpatialMarkDraft | null
}

type SpatialMarkDraft = {
  zoneId: string
  zoneName: string
  cellSize: number
  selectedCells: Array<{ col: number; row: number }>
  label: string
  description: string
  isCompleting: boolean
  error?: string | null
}
```

原因：

- 多窗口可以对应不同分支或 worktree。
- 用户在 Chat A 的空间标记不应出现在 Chat B。
- 切换窗口后再切回来，应恢复该窗口未发送的批次和未完成 draft。
- 页面刷新不要求保留，因为空间标记不持久化。

### 5.2 Web 类型文件

需要新增或扩展：

- `BIMCanvas.Web/src/types/aiCommandCenter.ts`
  - `SpatialMark`
  - `SpatialGeometry`
  - `SpatialMarkDraft`
  - `GridSelectionCell`
  - `ChatWindow.pendingSpatialMarks`
  - `ChatWindow.spatialMarkDraft`
- `BIMCanvas.Web/src/types/canvas.ts`
  - 若已有 `Point2D/Polygon2D` 可复用，不重复定义。

### 5.3 Web 服务层

新增：

- `BIMCanvas.Web/src/services/SpatialMarksService.ts`

职责：

- 调用 `POST http://localhost:5000/api/spatial-marks/merge-grid-selection`。
- 对请求和响应做 TypeScript 类型约束。
- 不保存任何状态。

接口示意：

```ts
export const SpatialMarksService = {
  mergeGridSelection(request: MergeGridSelectionRequest): Promise<MergeGridSelectionResponse>
}
```

### 5.4 Web composable

建议新增：

- `BIMCanvas.Web/src/composables/aiCommandCenter/useSpatialMarking.ts`

职责：

- 读取 active window 的 `pendingSpatialMarks` 和 `spatialMarkDraft`。
- 进入/退出空间标记模式。
- 选择目标顶层设计区。
- 设置 `cellSize/label/description`。
- 添加/移除/清空 `selectedCells`。
- 完成批次并调用 Server 合并接口。
- 删除已完成批次。
- 编辑已完成批次的 `label/description`。
- 给 `useSelectionContext.buildContextPayload()` 提供待发送批次。
- 在 `useChatStream` 通知发送成功后清空对应窗口的 `pendingSpatialMarks`。

### 5.5 入口与面板交互

入口放在 AI Command Center 的上下文栏中，建议在 `Add Context` 菜单下新增：

- `Space Mark`

进入后显示一个紧凑工具面板，包含：

- 目标设计区选择。
- 网格尺寸输入，默认 `200mm`。
- `label` 输入，必填。
- `description` 输入，可空。
- 当前选中网格数量。
- `完成`、`清空选择`、`取消` 操作。

待发送批次列表显示在上下文栏或输入框上方：

- 每个批次显示 `label`、`zoneName/zoneId`、几何片段数量。
- 支持删除。
- 支持编辑 `label/description`。
- 第一版不支持编辑几何范围。

### 5.6 选择规则

- 普通点选：加入网格。
- 普通框选：批量加入网格。
- `Shift + 点选/框选`：从当前批次移除网格。
- 多次点选/框选累积到同一批次。
- `清空当前选择`：只清空 `selectedCells`，不退出批次。
- `取消当前批次`：丢弃 draft，不生成 `SpatialMark`。
- `完成当前批次`：要求 `selectedCells.length > 0` 且 `label.trim()` 非空。

键盘建议：

- `Esc`：若处于标记模式，取消当前批次。
- `Enter`：在 label/description 输入框外可触发完成批次。
- 标记模式中不触发普通 Delete 删除模块。

### 5.7 与现有画布交互的边界

当前画布交互集中在：

- `BIMCanvas.Web/src/services/interaction/InteractionService.ts`
- `BIMCanvas.Web/src/services/three/ThreeSceneService.ts`
- `BIMCanvas.Web/src/components/Canvas/ThreeCanvas.vue`

空间标记模式启动时应临时接管画布点击/框选，不应复用普通对象选择结果。

实现原则：

- 标记模式开启时，普通模块/墙/门窗选择不应响应点击。
- 标记模式不应触发拖拽、移动、复制、旋转等工具。
- 现有 `InteractionService` 的普通框选已有选择框 UI，可以借鉴，但空间标记应走独立逻辑，避免污染 `selectedIds`。
- 可以通过 `window.dispatchEvent(new CustomEvent('bimcanvas:spatial-mark-mode-change', ...))` 在 AI 面板和 Three 场景之间同步状态。
- Three 侧应在 dispose/rebuild 时清理所有空间标记临时 mesh。

### 5.8 网格渲染策略

网格只在当前目标顶层设计区上显示。

推荐实现：

- 读取目标 zone 的 `computedBoundary ?? rawBoundary`。
- 计算项目 AABB，以项目原点作为 grid origin。
- 按 `cellSize` 生成覆盖项目范围的候选网格。
- Web 视觉层可以只绘制 AABB 范围内网格；最终越界裁剪由 Server 保证。
- 为减少误选，Web 点击时优先忽略中心点不在 zone boundary 内的 cell。
- 已选 cell 用半透明填充。
- hover cell 用更浅高亮。
- Shift 移除时 hover/框选颜色区分。
- 标记网格对象放在独立 Three group，例如 `userData.type = 'spatial-mark-grid'`，便于统一清理。

视觉要求：

- 不遮挡建筑边界和模块。
- 不把网格作为正式项目图层保存。
- 切换目标 zone、切换窗口、取消模式、项目重载时都要清理旧网格。

### 5.9 完成批次流程

1. Web 校验 `zoneId/cellSize/selectedCells/label`。
2. 调用 Server 合并接口。
3. Server 返回 `geometry`。
4. 若 `geometry.length === 0`，Web 提示“标记区域为空或完全在设计区外”。
5. Web 生成短 id，例如 `sm_01`。
6. Web 创建：
   ```ts
   { id, zoneId, label, description, geometry }
   ```
7. Web 推入当前窗口 `pendingSpatialMarks`。
8. Web 丢弃 draft 的 `selectedCells`。
9. Web 退出当前批次编辑态，但可以保持空间标记模式，方便继续新建批次。

### 5.10 发送消息清理语义

发送聊天消息时：

- Web 将当前窗口 `pendingSpatialMarks` 合并进 `context.spatialMarks`。
- 发送期间这些批次进入只读/发送中状态，避免用户改动导致请求体和 UI 不一致。
- SSE 正常完成后清空当前窗口 `pendingSpatialMarks`。
- HTTP 非 2xx、fetch 抛错、Agent 未连接、用户主动中断时保留 `pendingSpatialMarks`。
- 如果 Agent 正常返回错误文本但 SSE 正常结束，视为上下文已送达，可以清空。

## 6. Server API 计划

### 6.1 路由

新增 Controller：

- `BIMCanvas.Server/Controllers/SpatialMarksController.cs`

路由：

```http
POST /api/spatial-marks/merge-grid-selection
```

### 6.2 请求格式

```ts
type MergeGridSelectionRequest = {
  zoneId: string
  cellSize: number
  cells: Array<{ col: number; row: number }>
}
```

坐标约定：

```ts
x0 = col * cellSize
y0 = row * cellSize
x1 = (col + 1) * cellSize
y1 = (row + 1) * cellSize
```

`col/row` 是项目全局网格索引，从项目原点开始。Server 仍会根据 `zoneId` 对应顶层设计区边界裁剪结果。

### 6.3 响应格式

```ts
type MergeGridSelectionResponse = {
  zoneId: string
  geometry: SpatialGeometry[]
}
```

### 6.4 读取路径

Server 必须读取当前活动窗口对应的数据：

```csharp
var projectPath = _projectContext.GetActiveWorktreePath()
                  ?? _projectContext.CurrentProjectPath;
```

这样多窗口 worktree 隔离仍然成立。

### 6.5 校验规则

返回 `400`：

- 未加载项目。
- 请求体为空。
- `zoneId` 为空。
- `cellSize <= 0`。
- `cells` 为空。
- 任意 `col/row < 0`。
- `zoneId` 不在顶层 `activeScheme.zones`。
- 目标 zone 缺少有效边界。
- 项目没有 active scheme。

返回 `404`：

- 当前项目目录或 active worktree 目录不存在。

返回 `500`：

- JSON 读取失败、NTS 合并异常或其他未预期异常。

错误响应统一：

```json
{ "message": "错误说明" }
```

### 6.6 不持久化保证

此接口不得写入：

- `project.json`
- `schemes/zones.json`
- `schemes/**/modules.json`
- `computed/*.json`
- 任何 Git/worktree 元数据

此接口也不应触发保存、提交、文件 watcher reload。

## 7. Core 合并算法计划

### 7.1 新增类型

建议新增：

- `BIMCanvas.Core/Models/Geometry/SpatialGeometry.cs`

结构：

```csharp
public class SpatialGeometry
{
    public AABB? Aabb { get; set; }
    public Polygon2D? Polygon { get; set; }
}
```

JSON 字段使用 camelCase，并且忽略 null，确保输出为：

```json
{ "aabb": [0, 0, 200, 200] }
```

或：

```json
{ "polygon": [[0,0], [400,0], [400,200], [0,200]] }
```

### 7.2 新增算法

建议新增：

- `BIMCanvas.Core/Algorithms/Spatial/GridSelectionMerger.cs`

方法：

```csharp
public static List<SpatialGeometry> MergeGridCells(
    Polygon2D zoneBoundary,
    double originX,
    double originY,
    double cellSize,
    IEnumerable<(int Col, int Row)> cells)
```

### 7.3 算法流程

1. 校验 `zoneBoundary`、`cellSize`、`cells`。
2. 将每个 cell 按项目全局网格原点转成 global 坐标矩形 polygon。
3. 使用 `GeometryFactory.BuildGeometry(cellPolygons).Union()` 合并。
4. 使用 `NtsConverter.ToNtsPolygon(zoneBoundary)` 得到目标 zone polygon。
5. 对 union 结果和 zone polygon 做 `Intersection()`。
6. 遍历结果：
   - `Polygon`：加入输出候选。
   - `MultiPolygon`：逐个拆出 Polygon。
   - `GeometryCollection`：递归提取面积型 Polygon/MultiPolygon。
   - Point/LineString 忽略。
7. 坐标按输出原点转换；空间标记接口固定输出项目全局坐标：
   ```text
   outputX = round(globalX)
   outputY = round(globalY)
   ```
8. 移除闭合重复点。
9. 合并连续共线点。
10. 无洞且外轮廓为轴对齐矩形时输出 `AABB`。
11. 其他情况输出 `Polygon2D`，保留 holes。

### 7.4 几何行为要求

- 共享边相邻 cell 合并为一个区域。
- 仅对角接触 cell 不应合并为一个区域，应输出多个 `geometry`。
- L 形选择输出 polygon。
- 形成洞的选择输出 `polygon.shell + holes`。
- 边界外溢 cell 必须被裁剪到目标 zone 内。
- 裁剪后面积小于容差的结果忽略。
- 输出 polygon 不包含最后一个重复闭合点。
- 输出不包含连续共线冗余点。

  - 当只有 spatial marks、没有普通选中对象时，也应返回 context。

  - 发送请求时包含 `context.spatialMarks`。
  - 根据发送结果清空或保留 pending spatial marks。

### 8.3 Agent 渲染点

Claude 路径：

  - `MainAgent._build_context_block(context)` 增加 `spatialMarks` 渲染。

OpenAI 路径：

- `BIMCanvas.Agent/src/server/http_server.py`
  - 当前会透传 `context` 并补充 `chatAttachments`。
  - 只要 `context` 保持 dict，不需要专门解析 `spatialMarks`。

### 8.4 Agent 文本格式

`<canvas_context>` 中新增段落：

```text
用户标注区域（项目坐标 mm）：
- sm_01 zoneId=rz_3 label=睡眠区
  description=床组优先布置在这里，衣柜不要占用。
  geometry=[{"aabb":[9800,1600,12600,4000]}]
```

渲染规则：

- 必须明确坐标是项目坐标 mm。
- 每个批次输出 `id / zoneId / label / description / geometry`。
- 不输出 `cellSize`。
- 不输出 `selectedCells`。
- 不输出网格行列。
- 不输出调试面积统计。

Agent 行为提示：

- 空间标记是用户强意图，但不是不可违反的硬约束。
- Agent 应优先遵守空间标记。
- 若因尺寸、通行、禁区、边界、门窗或碰撞必须偏离，应在回复中说明原因。

## 11. 风险与处理

### 11.1 NTS 几何精度

风险：union/intersection 可能产生极小碎片或重复点。

处理：

- 面积低于容差的 polygon 忽略。
- 输出前 round 到毫米。
- 输出前移除闭合点和共线点。

### 11.2 对角接触区域

风险：NTS 可能在 GeometryCollection 中返回点/线。

处理：

- 只提取面积型 Polygon/MultiPolygon。
- 点/线忽略。

### 11.3 Web 交互冲突

风险：空间标记模式和现有选择/拖拽工具互相干扰。

处理：

- 标记模式显式接管 pointer 事件。
- 标记模式中不修改 `selectedIds`。
- 退出标记模式时恢复原有 InteractionService 行为。

### 11.4 多窗口状态串扰

风险：pending marks 放在全局 ref，会被其他聊天窗口带走。

处理：

- 状态挂在 `ChatWindow`。
- `activeWindow` 切换时只显示该窗口状态。

### 11.5 发送清理时机

风险：过早清空导致失败后用户丢失标记。

处理：

- SSE 正常结束后再清空。
- HTTP 错误、fetch 错误、中断时保留。

### 11.6 大量网格性能

风险：很小 cellSize 或大范围框选造成过多 cell。

处理：

- UI 限制 `cellSize` 最小值，建议不小于 `50mm`。
- 完成前提示 selected cell 数量。
- Server 可设置软限制，例如超过 5000 cells 返回 400 并提示调大网格。

## 12. 默认参数

- 默认网格尺寸：`200mm`。
- 建议最小网格尺寸：`50mm`。
- 标记目标：仅顶层 `activeScheme.zones`。
- 坐标单位：毫米。
- 坐标原点：项目原点。
- `label`：必填。
- `description`：必带字段，可为空。
- `geometry`：必填数组。
- 原始网格选择：不持久化、不进入 Agent 上下文、不写项目文件。

## 13. 后续扩展方向

这些不进入第一版，但当前设计为它们保留空间：

- 支持在 `subZones` 内做二级空间标记。
- 支持完成后重新进入几何编辑。
- 支持从空间标记一键生成正式设计子分区。
- 支持空间标记截图或局部 viewport 自动附加。
- 支持面积统计，但只在 UI 展示，不默认发给 Agent。
- 支持空间标记模板，例如睡眠区、收纳区、通行区。
- 支持 pending marks 会话级本地缓存。
