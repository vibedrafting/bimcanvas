> 1. 是否运行时必需
> 2. 是否需要进 Docker 镜像
> 3. 缺失后会坏到什么程度

## 2. Docker 镜像约定（本轮）

本轮采用“全功能单镜像”策略，镜像默认承诺以下能力：

- Web 静态资源已构建，可由 Server 在生产模式直接托管
- Agent 运行时依赖已安装，默认 Python 指向 Agent venv
- 镜像内显式提供 `claude` 与 `ccr` 命令
- Playwright Chromium 与中文字体已安装，可覆盖阶段 2 的截图验收

本轮不进镜像的内容：

- API Key、Provider Base URL 等敏感凭据
- `/data` 下的实例配置与项目数据
- Nginx 反代能力（作为独立容器）
- Revit 子系统

## 3. 构建期工具不等于运行期依赖

以下几项最容易混淆：

- `claude-agent-sdk`、`aiohttp`、`aiohttp-cors`
  - 它们不是“只在源码编译阶段有用”的包，而是 Agent 进程真实运行时依赖
  - 关键不只是“镜像里装过”，而是“启动 Agent 的那个 Python 环境必须能 import 到”
- `Microsoft.Playwright.CLI`
  - 它主要是浏览器安装工具
  - 真正的业务运行时依赖是 Playwright 浏览器资产和 `BackgroundScreenshotService` 所需运行库
- Web 的 `npm ci` / `vite build`
  - 属于构建期工具链
  - `dist/` 才是 Server 生产模式下使用的运行时产物
- `dotnet restore` / `dotnet build`
  - 属于构建期动作
  - 最终运行时依赖是 .NET 运行环境与编译产物

## 4. 按场景看依赖

### 4.1 本机只跑 Web + Server，不用 AI

建议至少具备：

- `.NET 8`
- `Git`
- 开发态下的 `Node.js`

这时可以不配：

- `Python`
- Agent 依赖
- AI Provider 凭据

但 AI 对话、生成和部分 SSE 能力不可用。

### 4.2 本机跑完整 AI 主流程

除基础依赖外，还需要：

- `Python 3.10+`
- Agent Python 依赖
- `Claude Code CLI`
- Windows 下的 `Git Bash`
- 一套有效的 AI Provider 凭据

### 4.3 Docker 阶段 2 验收

宿主机主要需要：

- `Docker Engine / Docker Desktop`

镜像内部需要保证：

- `.NET 8`
- `Git`
- `Node.js`
- `Python 3.10+`
- Agent Python 依赖
- `claude`
- `ccr`
- Playwright Chromium

宿主机仍需外部提供：

- `instance.env`
- 卷挂载目录
- 有效 API Key / Provider 配置

## 5. 容易误判的实现差异

### 5.1 `Playwright` 业务上局部，但当前生产实现把它当门槛

- 从业务职责看，它只服务截图链路
- 但当前 `BIMCanvas.Server/Program.cs` 在生产模式下会把缺失 Playwright 视为启动错误

### 5.2 `Python / Agent` 业务上主要影响 AI，但当前生产实现也把它当门槛

- 从产品角度看，不使用 AI 时 Web + Server 仍可工作
- 但当前生产模式会把缺失 Python 或 Agent 依赖视为启动错误

### 5.3 `Git` 没有显式启动检查，但仍是主流程底座

- 启动阶段没有独立 `IsGitAvailable()`
- 但项目加载、仓库初始化、分支、合并、Worktree、AI Job 隔离都直接依赖 Git

### 5.4 `Node.js` 在生产模式理论上可弱化，但本轮 Docker 仍保留

- 如果只考虑“Server 托管 `dist`”，生产态未必一定需要 Node
- 但本轮镜像还承担 `claude` CLI 与可选 CCR 能力，因此仍保留 Node

## 6. 结论

如果只看当前仓库的真实运行门槛，最核心的是：

- `.NET 8`
- `Git`
- 开发态的 `Node.js`
- 完整 AI 链路所需的 `Python + Agent 依赖 + Claude CLI + Provider 凭据`

如果只看局部功能扩展，则主要是：

- `Playwright Chromium`
- `CCR / claude-code-router`
- `Nginx`
- `Revit 2019 / Revit API`

判断某项依赖是否“可选”时，不能只看业务职责，还要同时看当前实现是否把它升级成了启动门槛，以及本轮 Docker 镜像是否承诺直接提供这项能力。
