# 分区 Skill

> 将复杂空间降维为多个简单空间，使每个子空间可用对应房间 Skill 独立处理。
> 分区是"理解"的延伸，不是独立阶段。

## 一、触发条件

| 场景 | 触发信号 | 分区类型 |
|------|---------|---------|
| 异形空间 | rawBoundary 顶点 > 4 | 几何分区 |
| 开放多功能 | 多功能标签组 + 面积 > 20㎡ | 功能分区 |
| 两者兼有 | 上述条件同时满足 | 先几何后功能 |

WHY：矩形+单功能 = 简单空间，现有房间 Skill 直接处理。复杂空间需先降维，否则房间 Skill 无法有效工作。

## 二、分区方法（统一三步框架）

### 步骤 1：确定空间分割（几何层面）
- 矩形房间 → 跳过此步
- 非矩形 → 列举分割候选 → 评估墙面资源 → 选择最优分割

**1a. 列举分割候选**：异形空间的内凹角通常允许两种正交切割方向（水平切或垂直切），产生不同的子空间形状和墙面资源分配。列出各候选的子空间尺寸和主要墙面长度。

**1b. 评估墙面资源**：结合房间 tags 的功能需求，评估各分割方案的墙面资源分配。核心问题：哪种分割能让主要功能标签获得更充裕的墙面？tags 中的大型家具功能（wardrobeStorage、tvMedia 等）对连续墙面长度敏感——分割方式决定这些功能能获得多长的连续墙面，以及家具放置后剩余空间是否足够通行。

WHY：分割方向决定每个子空间获得的墙面长度——同一面长墙在方案 A 中完整可用，在方案 B 中可能被切断。分区阶段不考虑功能对墙面的需求，等同于蒙眼切蛋糕。

**1c. 选择分割方式**：如果两种分割对主要功能的墙面资源有质的差异 → 步骤 2b 中一并询问用户。如果一种明显优于另一种 → 直接选择并说明理由。

- 异形区判断标准：≥2 面墙围合 + 与主体共享墙角
- 异形区是"有独立空间特征的迷你房间"，不是"主区域的附属墙段"

### 步骤 2：定义功能（语义层面）

**2a. 功能分配审视**：步骤 1 已确定分割方式和子空间形状。现在审视各子空间的墙面资源，决定功能分配：某个功能放在主体区是否比放在延伸区更优？对每个候选方案，推演其对另一个子空间的连锁影响（示例1演示了这种推演）。分区标签一旦确定，后续房间 Skill 只在标签范围内思考——分区决策锁定了后续所有可能性。

WHY：局部最优 ≠ 全局最优。延伸区"看起来适合做X"不代表"X 放在延伸区是全局最优解"。

**2b. 多候选评估 + 用户确认**：覆盖两类决策——① 步骤 1 的分割方式选择（如有多候选）；② 各子空间的功能定位。如果候选方案之间存在质的差异（不是量的微调），向用户展示推荐方案和替代方案（AskUserQuestion，参见 BIMCANVAS.md 对话能力）。

**2c. 确定功能**：选择推荐方案，功能映射到 Zone Tags，Tags 映射到房间 Skill。
WHY：功能驱动产出"有使用场景的空间"；几何驱动产出"零散家具的堆放区"。

### 步骤 3：输出 subZones（数据层面）
- 修改 `schemes/zones.json` 中父 zone 的 `subZones` 字段
- 每个子 zone：`type = "designable"`，`id = "dz_{n}"`
- 子 zone 的 `roomId` 继承父 zone，`tags ⊆ 父 zone tags + optionalTags`
- 写入后 Server 自动创建子目录
- 写入后调用 `get_zone_boundaries(zoneIds=[新子zone列表])` — 返回子 zone 边界中的 passage 段（通向相邻分区的开放连通），后续房间 Skill 据此避免在通道处放大型家具

> WHY：子分区的 rawBoundary 不区分墙和通道。passage 段解决了"这条边到底是实墙还是通向 dz_2 的通道"的关键问题。

## 三、两种场景差异

**几何分区**（异形拆解）：先评估分割方式（步骤 1），再定义功能。关键：子空间边界不重叠、覆盖原始房间。

**功能分区**（开放空间）：需设计判断，可能需用户确认。空间阅读三要素：动线方向（入口→深处）、纵深层次（前场 vs 远端）、采光轴（窗侧适合日间活动）。关键：动线通透、面积匹配需求。

## 四、分区策略声明示例

### 示例 1：L 形主卧（几何分区 — 分割方式评估）

场景：rawBoundary 7 个顶点，L 形空间，tags=[sleep, wardrobeStorage]，optionalTags=[vanity]
- L 形整体：宽约 5000mm，高约 4850mm，右上角有 1700×1550 延伸
- 北墙约 5000mm 横跨 L 形上沿，西墙约 4850mm，南墙约 3300mm

步骤 1a — 列举分割候选：
- **方案 A（竖直切割，沿内凹角垂直线）**：左右分
  - dz_1: 3300×4850 主体区（西侧），拥有西墙 4850mm、南墙 3300mm
  - dz_2: 1700×1550 小延伸区（东北角）
- **方案 B（水平切割，沿内凹角水平线）**：上下分
  - dz_1: 约 5000×1550 北部长条区，拥有北墙完整 5000mm
  - dz_2: 3300×3300 南部方正区

步骤 1b — 评估墙面资源（基于 tags 功能需求）：
- tags 含 wardrobeStorage → 需要尽可能长的连续实墙
- 方案 A：wardrobeStorage 只能在 dz_1 内部解决，最长候选墙 4850mm，但若同时放床（深约 2000mm），衣柜靠对面墙后剩余通道 = 3300 - 2000 - 600 ≈ 700mm，紧凑。延伸区 1700×1550 太小无法承载 wardrobeStorage
- 方案 B：北部长条区获得完整北墙 5000mm，wardrobeStorage 在此墙面资源充裕且不影响南部睡眠区通道

→ 方案 B 让 wardrobeStorage 获得的连续墙面远优于方案 A。两种分割对主要功能的墙面资源有质的差异。

步骤 1c/2b — 询问用户（AskUserQuestion）：
- 推荐方案 B（上下分）：北部做衣柜区（5000mm 连续墙面），南部 3300×3300 方正睡眠区
- 替代方案 A（左右分）：传统 L 形拆解，主体区做卧室（wardrobeStorage 在内部解决，通道紧凑），延伸区做小型辅助功能区
- 核心取舍：wardrobeStorage 墙面充裕 + 睡眠区方正 vs 传统分割 + 更大睡眠区面积

步骤 2a — 功能分配审视（假设用户选择方案 B）：
- 北部长条 5000×1550 的可用墙面呈 L 形（北墙 + 东墙延伸段），两种功能方案：
  - 纯衣帽间（L 形两边都做衣柜）
  - 衣柜 + 梳妆台组合（L 形短边 1700mm 恰好放梳妆台）
- 两种方案对日常使用有质的差异 → 再次询问用户

步骤 2c/3 — 定义功能 + subZones：
- dz_1: 衣帽间/更衣区, tags=[wardrobeStorage], optionalTags=[vanity]
- dz_2: 睡眠区, tags=[sleep]

### 示例 2：客餐一体（功能分区）

场景：7.2m×4.8m 矩形，tags=[tvMedia, rest, dining]，南墙大窗，北墙入口

空间阅读：动线北→南 · 纵深：入口区→过渡→休息区 · 采光：南窗全面

步骤 2 — 定义功能：
- 南侧 4.2m → 客厅区（采光好，适合日常休息和观影）
- 北侧 3.0m → 餐厅区（靠入口和厨房，缩短上菜动线）

步骤 3 — subZones：
- dz_1: 客厅区, tags=[tvMedia, rest]
- dz_2: 餐厅区, tags=[dining]

## 五、关键约束

**【硬约束】**
- ① 子空间边界不重叠 — 一个位置不能同时属于两个功能区
- ② 子空间合集覆盖原始 rawBoundary — 不遗漏可用空间
- ③ 功能定义必须具体（"更衣区"✓ "过渡区"✗）— 模糊功能无法映射 Tags
- ④ 子分区完成后必须调用 get_zone_boundaries — passage 数据是后续房间 Skill 正确工作的前提

**【软指导】**
- 异形区优先搜索辅助家具位置 — 独特尺寸恰好适配特定家具
- 动线区域保持通透 — 通行功能优先于放置功能
- 子空间边界用矩形近似 — 与 OBB 设计原则一致，简化坐标推理
- 分割方式由功能需求驱动 — 不同切割方向产生不同墙面资源，优先选择让主要 tags 功能获得更充裕墙面的分割

**【自由区域】**
- 分区线的精确位置
- 功能区面积比例分配
- 子空间命名风格
