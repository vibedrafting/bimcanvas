# 分区 Skill

> 将复杂空间降维为多个简单空间，使每个子空间可用对应房间 Skill 独立处理。
> 分区是"理解"的延伸，不是独立阶段。

## 一、触发条件

| 场景 | 触发信号 | 分区类型 |
|------|---------|---------|
| 异形空间 | rawBoundary 顶点 > 4 | 几何分区 |
| 开放多功能 | 多功能标签组 + 面积 > 20㎡ | 功能分区 |
| 两者兼有 | 上述条件同时满足 | 先几何后功能 |

WHY：矩形+单功能 = 简单空间，现有房间 Skill 直接处理。复杂空间需先降维，否则房间 Skill 无法有效工作。

## 二、分区方法（统一三步框架）

### 步骤 1：识别子空间（几何层面）
- 矩形房间 → 跳过此步
- 非矩形 → 识别主体矩形 + 异形延伸区
  - 异形区判断标准：≥2 面墙围合 + 与主体共享墙角
  - 异形区是"有独立空间特征的迷你房间"，不是"主区域的附属墙段"
  WHY：物理围合创造独立空间体验

### 步骤 2：定义功能（语义层面）

**2a. 全局墙面审视 + 影响评估**：分区标签一旦确定，后续房间 Skill 只在标签范围内思考——分区决策锁定了后续所有可能性。分配功能前，审视整个空间的墙面资源：某个功能放在主体区是否比放在延伸区更优？对每个候选方案，推演其对另一个子空间的连锁影响（示例1演示了这种推演）。

WHY：局部最优 ≠ 全局最优。延伸区"看起来适合做X"不代表"X 放在延伸区是全局最优解"。

**2b. 多候选评估**：对每个子空间，列举 2-3 种可能的功能定位，评估各方案对用户日常使用体验的影响。如果多种方案之间存在质的差异（不是量的微调），向用户展示推荐方案和替代方案（AskUserQuestion，参见 BIMCANVAS.md 对话能力）。

**2c. 确定功能**：选择推荐方案，功能映射到 Zone Tags，Tags 映射到房间 Skill。
WHY：功能驱动产出"有使用场景的空间"；几何驱动产出"零散家具的堆放区"。

### 步骤 3：输出 subZones（数据层面）
- 修改 `schemes/zones.json` 中父 zone 的 `subZones` 字段
- 每个子 zone：`type = "designable"`，`id = "dz_{n}"`
- 子 zone 的 `roomId` 继承父 zone，`tags ⊆ 父 zone tags + optionalTags`
- 写入后 Server 自动创建子目录
- 写入后调用 `get_zone_boundaries(zoneIds=[新子zone列表])` — 返回子 zone 边界中的 passage 段（通向相邻分区的开放连通），后续房间 Skill 据此避免在通道处放大型家具

> WHY：子分区的 rawBoundary 不区分墙和通道。passage 段解决了"这条边到底是实墙还是通向 dz_2 的通道"的关键问题。

## 三、两种场景差异

**几何分区**（异形拆解）：确定性高，几何驱动。关键：子空间边界不重叠、覆盖原始房间。

**功能分区**（开放空间）：需设计判断，可能需用户确认。空间阅读三要素：动线方向（入口→深处）、纵深层次（前场 vs 远端）、采光轴（窗侧适合日间活动）。关键：动线通透、面积匹配需求。

## 四、分区策略声明示例

### 示例 1：L 形主卧（几何分区）

场景：rawBoundary 12 个顶点，主体 3.4m×4.9m（东侧），延伸区 2.6m×2.4m（西南），tags=[sleep, wardrobeStorage]，optionalTags=[vanity]，延伸区南墙中段有主卫门

步骤 1 — 识别子空间：
- 主体矩形 3.4m×4.9m（最大内接矩形）
- 延伸区 2.6m×2.4m（三面墙围合，约 6.2㎡）

步骤 2a — 全局墙面审视 + 影响评估（基于 get_zone_boundaries）：
- 主体 dz_1：东4.9m 实墙 / 南3.4m 实墙（最长非窗非床实墙）/ 西2.9m 实墙 / 北=窗墙
- 延伸 dz_2：西2.4m 实墙 / 南2.6m 实墙（含主卫门，可用完整墙段短）/ 北=通道(→dz_1) / 东=通道(→dz_1)

衣柜放主体南墙 vs 延伸区——影响评估：
- 主体南墙方案：3.4m 连续实墙放整排衣柜，整体性最好、收纳最充足、对睡眠区空间感影响最小（贴墙不占纵深）。延伸区释放给其他功能——西墙2.4m适合梳妆台（安静、采光柔和），南墙因主卫门居中、可用完整墙段短，适合放小型收纳柜
- 延伸区方案：衣柜放西墙（2.4m）+ 梳妆台利用残余墙段，经典更衣区布局，换衣动线集中。但主体南墙3.4m 空置，较为浪费

→ 两种方案对延伸区的空间性格有质的差异（更衣室 vs 化妆间），且最优衣柜位置取决于用户对延伸区的功能期望

步骤 2b — 询问用户（AskUserQuestion）：
- 推荐方案：衣柜放主体南墙（3.4m 整面衣柜，收纳最大化），延伸区做独立化妆间（晨起动线独立，西墙安静采光好）
- 替代方案：延伸区做更衣区（衣柜+梳妆台集中），经典布局，换衣动线最短
- 核心取舍：收纳容量+独立功能区 vs 换衣动线集中+经典布局

步骤 2c/3 — 定义功能 + subZones（假设用户选择推荐方案）：
- dz_1: 睡眠区, tags=[sleep, wardrobeStorage]
- dz_2: 化妆间, tags=[vanity], optionalTags=[generalStorage]

### 示例 2：客餐一体（功能分区）

场景：7.2m×4.8m 矩形，tags=[tvMedia, rest, dining]，南墙大窗，北墙入口

空间阅读：动线北→南 · 纵深：入口区→过渡→休息区 · 采光：南窗全面

步骤 2 — 定义功能：
- 南侧 4.2m → 客厅区（采光好，适合日常休息和观影）
- 北侧 3.0m → 餐厅区（靠入口和厨房，缩短上菜动线）

步骤 3 — subZones：
- dz_1: 客厅区, tags=[tvMedia, rest]
- dz_2: 餐厅区, tags=[dining]

## 五、关键约束

**【硬约束】**
- ① 子空间边界不重叠 — 一个位置不能同时属于两个功能区
- ② 子空间合集覆盖原始 rawBoundary — 不遗漏可用空间
- ③ 功能定义必须具体（"更衣区"✓ "过渡区"✗）— 模糊功能无法映射 Tags
- ④ 子分区完成后必须调用 get_zone_boundaries — passage 数据是后续房间 Skill 正确工作的前提

**【软指导】**
- 异形区优先搜索辅助家具位置 — 独特尺寸恰好适配特定家具
- 动线区域保持通透 — 通行功能优先于放置功能
- 子空间边界用矩形近似 — 与 OBB 设计原则一致，简化坐标推理

**【自由区域】**
- 分区线的精确位置
- 功能区面积比例分配
- 子空间命名风格
