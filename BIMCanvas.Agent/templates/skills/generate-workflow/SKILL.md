# 布置工作流

```
感知(Perceive) → 理解(Understand) → 策略(Strategy) → 执行(Execute) → 审查(Review) → 汇报(Report)
    快速机械        全局思考          明确方向        专注放置         设计评审        简洁交付
```

---

## 感知 Perceive

> WHY：纯机械操作，不占认知资源。先建立感官输入，后续阶段才有决策素材。

1. **截图**（单独调用，等收到后再继续）— `mcp__canvas__request_background_screenshot`，用 zone 模式聚焦目标分区或 full 模式看全屋。截图工具直接返回图片；若看不到内容，用 Read 查看返回的文件路径
2. **并行读取**：knowledge/design_principles.md + modules/module_library.json + schemes/zones.json + computed/exclusions.json
3. **边界语义**：调用 `get_zone_boundaries` — 获取每条边的类型（wall/passage/door/window）和坐标，直接用于墙面分析，不再从 rawBoundary + openings 手动推断

**模块数据**：契约层（id/tags/size）用于选择，意图层（agent_config: morphology + topology_rules + relation_rules）用于布置决策。按 Zone 的 tags/optionalTags 筛选兼容模块——匹配 tags 为必备家具，仅匹配 optionalTags 为可选家具。

## 理解 Understand

> WHY：理解空间本质后才能做出好决策。这是你花最多思考力的阶段——不要直接进入"放家具"模式。

**产出空间画像**（结合截图和数据，回答三个维度）：
1. **动线方向**：人从入口进来往哪走？主通道走向？
2. **纵深层次**：前场（入口侧）和深处（远离入口）分别在哪？
3. **采光轴**：窗户方向，光线通路有无遮挡风险？

**确定空间类型 → 加载房间策略**：

Read 策略参考文件路径（见系统注入的"策略参考文件"路径）下对应文件：

| tags 特征 | 空间类型 | 策略文件 |
|-----------|---------|---------|
| sleep / bedroom | 卧室 | bedroom.md |
| shower / toilet / washing | 卫生间 | bathroom.md |
| rest / tvMedia / dining / circulation | 客餐厅 | livingroom.md |

**【必须】评估分区需求**：

以下信号命中任一时，**加载 generate-zoning Skill**，由 Skill 内部的预布置验证决定是否产出 subZones：
- 异形空间：rawBoundary 顶点 > 4，存在可独立围合的子空间
- 多功能组合：多个功能标签 + 面积足以分区
- 功能间空间冲突：主要家具在同一空间内产生通道不足等矛盾

→ Skill 产出 subZones：调用 `get_zone_boundaries` 获取子 zone 边界语义（含 passage 段）→ 进入策略阶段（房间 Skill 已在理解阶段加载，覆盖所有子 zone）
→ Skill 判定无需分区：直接进入策略阶段

> ⚠ 反模式：信号命中后，用面积直觉（"延伸区太小"）跳过 Skill 加载。面积判断属于 Skill 内部的预布置验证——你的职责是触发 Skill，不是替代 Skill。

## 策略 Strategy

> WHY：先想清楚整体方案再动手放家具。策略是全局决策的记录，让执行时有明确方向，不陷入局部优化。

### 方案探索

遵循已加载的房间策略，为**全部家具**（必须+可选）探索布局方案：
- 锚点决策：核心家具选哪面墙，WHY
- 主要家具布局：衣柜/沙发等的墙面和模式
- 可选家具位置：逐件评估候选墙面，标注推荐位置和理由
- 间距分配：各侧空间分配

> 可选家具不是"填充剩余空间"——它的位置可能影响主要家具的布局选择。全局探索才能发现跨优先级的联动优化。

### 决策收敛

方案探索完成后，**列出**探索中浮现的所有选择点，逐一标注"战略/战术"：
- **战略选择**（家具墙面归属、空间功能定位等，影响用户日常使用体验）→ 向用户展示推荐方案和替代方案（AskUserQuestion）
- **战术选择**（间距微调、同墙面位置偏移等，由规范决定）→ 自主决策

> 判断标准：
> - **战术**：硬约束（【必须】规则）直接排除至仅剩一个可行方案，或差异仅涉及精确坐标/间距调整
> - **战略**：存在两个及以上可行方案，且差异涉及用户日常体验（墙面归属、功能组合、空间定位）

**【必须】唯一解回溯检查**：当某选择点"只剩一个可行方案"时，检查该唯一性的来源——是硬约束（空间物理限制、【必须】规则）直接排除的，还是前序决策（如衣柜占据了某墙段）间接消除的？

- 硬约束排除 → 战术，自主决策
- 前序决策消除 → 回到前序决策，评估是否存在"调整前序决策为当前家具腾出替代位置"的方案。如果存在，当前选择点是战略选择

WHY：前序决策消除替代选项后标注"唯一解=战术"，是自证预言——先做了一个选择，再用它的结果证明后续没有选择。回溯检查打断这条错误推理链。

> ⚠ 两个检验信号：(1) 在 thinking 中花费显著推理论证一个方案优于另一个——取舍 = 战略选择的特征；(2) "唯一可行位"的唯一性依赖于前序决策而非空间物理限制——自证预言 = 分类错误的特征。

### 产出策略声明

全部家具（必须+可选）的墙面归属、朝向意图、关键决策理由。

策略声明是**语义描述**，不是精确坐标。精确坐标在执行阶段根据 agent_config 计算。

策略声明中**【建议】**包含设计目标声明——参照 design_evaluation.md 的品质维度，用动线/空间意图/功能叙事/空间节奏/采光的语言说明本布局要达成什么。

> WHY：设计目标不是额外负担——它是后续执行和审查的锚点。有了"进门直达台盆"这个目标，选墙时就不需要纠结公式；审查时只需验证"进门后首个使用点是台盆吗？"。目标驱动让每个决策都有判据。

## 执行 Execute

> WHY：信赖前面阶段的决策质量，执行阶段专注精确计算。一次性放置减少上下文消耗。

### 放置

按策略声明 + design_principles + 房间策略约束 + module_library agent_config，精确定位全部家具（锚点→主要→可选，一次性写入）。

**放置前原则性检查**（每件家具）：
1. 是否阻挡门开启？（design_principles 空间硬约束）
2. 通行间隙是否满足通道标准？（design_principles 通道与间距，区分通行间隙与使用间隙）
3. 前瞻协调：主要家具是否阻断可选家具的策略位置？（design_principles 前瞻协调规则）

> bounds/重叠/禁区等几何检查由 validate_layout 自动完成，无需心算。

### 写入

Write `schemes/{zoneId}/modules.json`，每个模块包含 moduleId、bounds（四点坐标）、facing、items。id 由 Server 在 validate_layout 时自动生成，禁止手动填写。
分区场景写入路径：`schemes/{parentZoneId}/{childZoneId}/modules.json`（如 `schemes/rz_3/dz_1/modules.json`）。

### 验证闭环

**【必须】**每次 Write 后调用 `mcp__canvas__validate_layout(zoneIds=[...])`。分区场景传入子 zone 列表（如 `zoneIds=["dz_1", "dz_2"]`）。
错误代码：越界(E001)、墙体重叠(E002)、柱子重叠(E003)、禁区重叠(E004)、模块间重叠(E005)。

### 修正循环（最多 2 轮）

验证失败时：
1. 列出所有违规项
2. 按修正优先级处理：**平移** → **旋转** → **缩小**（limits 内）→ **替换**同功能更小模块 → **移除**
3. Read 当前 modules.json → 修正 → Write → 再次 validate_layout

> WHY：修正优先级从最小变动到最大变动——平移保留原始设计意图，移除是最后手段。

**兜底**：2 轮修正后仍失败 → 移除违规家具，保留核心布局，报告中说明原因。

## 审查 Review

> WHY：审查分两层——工程合规保证物理可行，设计品质验证目标达成。Layer 1 不通过时不进入 Layer 2。

**截图**（单独调用）→ 分层评估：

### Layer 1：工程合规
1. validate_layout 通过（几何合法性）
2. **可达性验证**（【必须】用坐标算术证明，禁止凭印象声称"满足"）：
   从入口走到每件家具使用面和每扇窗户，逐段计算最窄处，比对 design_principles 通道标准和房间策略专项标准。
   报告格式：`[起点] → [终点]：最窄处 [物体A] ↔ [物体B] Xmm（标准≥Ymm）✓/✗`
3. **功能完整性**：zone.tags 中每个功能标签至少有一个对应模块 → 缺失则补充

Layer 1 任何项未通过 → 修正（最多 2 轮）→ 重新验证

### Layer 2：设计品质
对照策略阶段声明的设计目标，逐项验证是否达成（参照 design_evaluation.md）。
- 声明了动线目标？→ 验证入门到首个使用点的路径
- 声明了功能叙事目标？→ 验证墙面/区域的家具连贯性
- 声明了空间节奏目标？→ 验证隐私/密度递进
- 其他已声明的目标？→ 逐条核实

品质目标有明显未达成 → 修正（最多 1 轮）→ 重新验证
全部通过 → 汇报

### 贯穿两层
- **策略一致**：最终布局实现了策略声明的核心意图
- **规则遵从**：房间策略的硬约束全部满足
- **分区连贯**（分区场景）：相邻子分区之间的动线连贯

**降级判断**：截图无法清晰辨别时，注明"品质评估依赖数字验证 + 策略交叉检查"。

---

## 汇报 Report

仅在审查通过后汇报：
- 空间画像摘要（动线、纵深、采光）
- 策略要点（锚点决策、关键取舍）
- 放置结果（家具清单、位置、朝向）
- 品质评估（Layer 1 合规 + Layer 2 设计目标达成情况）
- 决策痕迹：分歧点+选择理由（如有）

**禁止**：审查未通过时报告"布置完成"。

---

## 机制速查

- **【必须】截图单独调用**：不与其他工具并行
- **修正优先级**：平移 → 旋转 → 缩小 → 替换 → 移除
- 先读后写、validate_layout 必调、目录权限 → 见 BIMCANVAS.md 安全机制
